# Settings

bake reads its settings from `settings.json` in the Bake home, a JSON object read at startup. Only interactive commands write it: Ctrl+S in `/model` and `/thinking` saves `defaultProvider`, `defaultModel`, and `defaultThinkingLevel`; `/settings` saves `steeringMode`, `followUpMode`, `branchSummary.skipPrompt`, `statusLine`, and the `compaction` members `enabled`, `thresholdPercent`, `keepRecentTokens`, and `cachedSummary`; `/login`, `/logout`, and `/refresh-models` write `cliproxyapi` (`bake docs models`). A write keeps every other member. A missing file means the defaults. A file that is not a JSON object produces a warning and the defaults; a member of the wrong type is ignored. Projects have no settings file of their own.

## Members

| Member | Meaning |
|---|---|
| `defaultProvider`, `defaultModel` | The model a new session starts with when `--model` is not given (`bake docs models`) |
| `defaultThinkingLevel` | The thinking level when none is given: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`; `medium` when unset |
| `enabledModels` | Model patterns or globs that scope the available models when `--models` is not passed (`bake docs models`) |
| `modelThinkingLevels` | Thinking levels for particular models, keyed `provider/id`, used when a new session is given no thinking level |
| `steeringMode`, `followUpMode` | How prompts sent while a turn runs are delivered: `one-at-a-time` (the default) or `all` at the next step |
| `cliproxyapi` | The CLIProxyAPI account's route, or `null` once signed out; written by `/login` (`bake docs models`) |
| `defaultTools` | The tool names a session starts with, in place of `read`, `bash`, `edit`, `write`, the job tools, the web tools `web_search` and `web_fetch`, and `codemode`; a list of only `+name` and `-name` entries adds to or removes from those defaults instead, so `["+grep"]` keeps `codemode` |
| `webSearch.model` | The CLIProxyAPI route model `web_search` runs on: the id of one of the route's Anthropic Messages models, with or without `cliproxyapi/` |
| `maxConcurrentReadTools` | Optional integer from 1 to 64; bounds concurrent native read tools and runs batches containing other tools sequentially. Absent preserves existing unlimited parallel batches |
| `taskDocuments` | When `true`, enables the versioned `task_document` tool for plans, todos, and user-requested goals; default `false` |
| `subagents` | When `true`, gives a top-level session the subagent tools: `subagent`, `send_message`, `interrupt_agent`, `list_agents`, and `list_subagent_models` when more than one model is available; default `false` |
| `schedules` | When `true`, gives a top-level session the reminder tools `schedule_create`, `schedule_list`, and `schedule_delete`; default `false` |
| `codemode` | `mode`: how the other tools are presented while the `codemode` tool is active, which it is by default, `on` (default) or `only`; `inlineBudget`: the estimated tokens its description's tool declarations may take, 3000 when unset (`bake docs codemode`) |
| `maxToolArgumentWhitespace` | The most whitespace a streamed tool call's arguments may end with, outside string values, before bake abandons the response as a retryable error; a positive integer, 2000 when unset |
| `sessionDir` | One directory to keep every project's sessions in, in place of `sessions/` in the Bake home; continuing and listing still pick the working directory's sessions |
| `blockImages` | When `true`, images are not sent to the model |
| `images.autoResize` | Whether the `read` tool shrinks large images before sending them; `true` when unset |
| `terminal` | `showTerminalProgress`: whether the terminal shows a progress bar (OSC 9;4) while a turn runs; `notifications`: whether it shows a desktop notification when a turn ends or a tool needs approval while the terminal is out of focus. When unset, each is on in Ghostty and off elsewhere (`bake docs cli`) |
| `compaction` | `enabled` (default `true`), `reserveTokens` (default 16384), `keepRecentTokens` (default 20000), Bake's `thresholdPercent` (unset) and `cachedSummary` (default `true`), and `modelOverrides` keyed `provider/id` for the two token settings and `thresholdPercent` |
| `statusLine` | `tokens` and `cache`, each `false` unless set: whether the status line under the composer shows the session's input and output token totals (`↑12k ↓3.4k`) and its prompt cache (`cache 99% (R180k W2k)`: the share of the latest prompt read from the cache, then the session's cache reads `R` and writes `W`, each once it is not zero), as Pi's footer counts them |
| `branchSummary` | `reserveTokens` (default 16384), the room kept for the summary `/tree` can write of the branch it leaves, and `skipPrompt` (default `false`): when `true`, `/tree` leaves a branch without asking whether to summarize it |
| `backgroundCompaction` | When `true`, prepares one summary while foreground work continues; requires compaction enabled and defaults to `false` |
| `contextMasking` | When `true`, experimentally replaces older eligible tool observations with logged placeholders; default `false`, with ordinary compaction retained |
| `retry` | `enabled` (default `true`), `maxRetries` (3), `baseDelayMs` (2000), and `maxAgentDelayMs` (60000) for retrying transient model errors |
| `permission` | `presets` and `defaultPreset` (`bake docs permissions`) |
| `hooks` | `claudeCode` and `codex`: the Claude Code and Codex `hooks.json` files whose command hooks run during sessions; unset runs none (`bake docs hooks`) |

An invalid compaction token value or `thresholdPercent` is reported, by name, as an error when compaction runs. A malformed `permission` section stops the run, since its presets bound what tools may do.

`maxConcurrentReadTools` bounds batches made entirely of trusted native `read`, `ls`, `find`, and `grep` tools. Preparation and permission hooks run in assistant order; completion events follow completion order and recorded results retain assistant order. A batch containing any other tool runs sequentially, including a custom or MCP tool advertising itself as read-only. Invalid explicit values stop session creation. With the setting absent, existing unlimited parallel batches and mutation barriers apply. Cancellation waits for started work and skips queued execution; session shutdown also drains blocking native reads and listings.

With `taskDocuments: true`, the default tool set also includes `task_document`. An explicit `defaultTools` list or CLI tool selection still controls whether it is active. The tool lists, reads, and revises documents using their exact current revision reference. Documents belong to the selected session branch and remain available after compaction or resume. `claimed_complete` records the agent’s claim; it does not assert that files passed a check. The Rust SDK can record separate evidence tied to a trusted native check and declared file versions. No setting automatically creates a goal or runs checks. With `--no-session`, documents exist only for that process.

With `subagents: true`, the default tool set also includes the subagent tools, and an explicit `defaultTools` list or CLI tool selection still controls which are active. `subagent` delegates a self-contained task to a child agent with its own context, in the background by default; `send_message` continues or steers a child, `interrupt_agent` stops its current turn, and `list_agents` lists the session's children. In the interactive terminal, the row under the composer counts them, Ctrl+G lists them and opens one's model, state, file, and last words, and `x` on the list stops a running child's current turn as `interrupt_agent` does. A child runs on the caller's model unless the call names another available one, keeps its own session file under the sessions directory's `subagents/`, has `send_message` to its parent, and starts no children of its own. A session holds at most eight children at once and sets the least recently used idle one aside to make room; a set-aside child resumes from its file. Its completion and messages reach the parent as notices; `-p` waits for running children before it exits. A resumed session can continue its children, and a run cut off by an exit is reported as interrupted, never run again. The tools add about 1.7 KB to every request.

With `schedules: true`, the default tool set also includes the reminder tools, and an explicit `defaultTools` list or CLI tool selection still controls which are active. `schedule_create` sets one reminder: after a delay in seconds, at a time given with a UTC offset or as a local date and time in a named IANA time zone, or every so many seconds, at least 300. A local time that a daylight-saving change skips is refused, and a repeated one means its first occurrence. When a reminder is due, the model receives its text as a notice: during a running turn at its next step, and otherwise in a new turn. Reminders run only while the session is open; one that falls due while it is closed is delivered when the session is resumed, and a repeating one that missed several runs fires once for the latest. Each reminder is delivered at most once. Reminders belong to the session that made them: a fork keeps them in its history but delivers none of them, and subagents have no reminder tools. `schedule_list` lists the active reminders, and `schedule_delete` removes one by id. The tools add about 1.9 KB to every request.

Without `webSearch.model`, `web_search` uses the session's model when it is an Anthropic Messages model on the CLIProxyAPI route, else the last of the route's Anthropic Messages models whose id contains `haiku`, else the route's first Anthropic Messages model. Without any, or when `webSearch.model` names a model the route does not list, a search fails with a message naming the setting. A search is never retried on another model: when the chosen model is not found or does not search, the error names it and `webSearch.model`.

Automatic compaction starts once the context exceeds the model's context window minus `compaction.reserveTokens`. With `compaction.thresholdPercent`, a whole number from 1 to 100, it starts once the context exceeds that share of the window instead, but never later than the reserve allows: `80` on a 200k-token model compacts past 160k tokens, and `95` there still compacts past 183k. A low value compacts often, since a compaction keeps `keepRecentTokens` and the summary. `/settings` offers 50% to 95% and the default.

With `compaction.cachedSummary` on, the default, a compaction writes its summary in one request that repeats the agent's last request, with its system prompt, tools, messages, and options, and asks for the summary as the next turn. The provider can then read nearly all of that request from its prompt cache, and the summary is written from every tool result in full; the default summary sends the older messages as text under its own prompt, cuts each tool result to 2,000 characters, and reads no cache. The instruction quotes the first message the compaction keeps, so the summary stops where the kept messages begin. The cached request is sent only when its payload repeats the last request's, apart from the output limit and cache markers, and only for the model of that request; otherwise, after a context overflow, when the last response neither read nor wrote the cache, when `--max-model-calls` leaves no room for the default summary after it, or when the cache is past the lifetime the model declares (`promptCache`) or the provider reports, the default summary runs and nothing else is sent. When the cached request fails, calls a tool, is cut off, or returns no summary, the default summary runs after it. A cached summary costs the cache-read price for the whole conversation, which on a small session can be more than the default summary; `"cachedSummary": false` keeps the default summary. A compaction's mark in the transcript says how much of the summary's prompt the cache served, or why the cached summary was not used, and `--mode json` reports each summary request as a `compaction_summary` event with its `path` (`cached` or `standard`), `tokensBefore`, and any `fallbackReason`. The setting applies from the next request after it is turned on, and background compaction keeps the default summary. This is adapted from [pi-cached-compaction](https://github.com/nicobailon/pi-cached-compaction) 0.2.0, without its cache countdown, compaction before the cache expires, or longer cache retention.

With `backgroundCompaction: true`, Bake starts a summary once the context is within `compaction.reserveTokens` of the automatic compaction threshold, when that threshold is greater than `compaction.reserveTokens`. It installs a completed summary between turns only if the summarized context still matches. New conversation messages remain; context edits, navigation, another compaction, or changed model settings discard the candidate. Ordinary compaction still runs when required. Background requests share the run’s deadline and model-call allowance, preserve one call for foreground work, and remain charged when discarded. They can add model cost without reducing waiting time. JSON mode reports their lifecycle and each attempt’s available usage; interactive mode reports committed summaries.

With `contextMasking: true`, Bake keeps the last eight complete assistant tool batches and the latest successful `read` for each recorded path and range. Older successful text output from `read`, `ls`, `find`, and `grep` may be replaced by a placeholder when its recorded details identify a trusted host read capability. Unmarked imported history and unknown tool overrides remain, as do errors, incomplete batches, explicit context edits, images, and other tools. New tool results cannot supply the reserved provenance marker themselves, including while masking is off. Recorded markers are trusted session metadata, not cryptographic authentication of imported or edited logs. Assistant calls and their result identities stay paired. Each replacement is written as a Pi context edit before the reduced context is used, so reopening reproduces it and the original result stays in the file. Turning the setting off stops new masking; it does not undo recorded edits. Ordinary foreground compaction still applies when the retained context exceeds its threshold. JSON mode reports committed masking counts and removed content bytes. This experiment can lose useful older observations or cause repeated reads; its quality and cost are not yet qualified. Compare it with `backgroundCompaction` disabled to isolate the policy.

## Example

```json
{
  "defaultProvider": "cliproxyapi",
  "defaultModel": "gpt-5.5",
  "defaultThinkingLevel": "high",
  "defaultTools": ["+grep", "+find", "+ls"],
  "permission": { "defaultPreset": "workspace-write" },
  "compaction": { "thresholdPercent": 80 },
  "statusLine": { "tokens": true, "cache": true }
}
```
