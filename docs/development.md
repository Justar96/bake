# Bake development

This workspace builds `bake`, Bake's terminal coding agent. Run Cargo from the repository root so the toolchain pinned in `rust-toolchain.toml` applies. The product ships as one executable with embedded user documentation and needs no Node or Bun at runtime. Bake 0.4.0 releases Linux x86_64 and arm64; macOS and Windows support follows in 0.4.x.

## Run

From the repository root, build and run with Cargo:

```sh
cargo run --locked -p bake-cli --
cargo run --locked -p bake-cli -- --inline -c
cargo run --locked -p bake-cli -- preview
cargo run --locked -p bake-cli -- -p "explain this repository"
cargo run --locked -p bake-cli -- --help
cargo run --locked -p bake-cli -- docs
cargo run --locked -p bake-cli -- --self-check
```

Bake reads `BAKE_HOME`, then `DSH_HOME`, defaulting to `~/.bake`. `bake docs models` describes CLIProxyAPI sign-in; `bake docs settings` describes settings. Interactive and print modes share the same agent session, tools, model adapters, and Pi-format session storage. `bake preview` uses a fixture runtime with the same view components. The executable's [documentation](../crates/bake-cli/docs/) owns current commands and terminal behavior.

## Crates

| Crate | Responsibility |
|---|---|
| [`bake-agent`](../crates/bake-agent/) | The agent loop and stateful agent ported from Pi's `agent` package |
| [`bake-ai`](../crates/bake-ai/) | Provider-neutral model streaming ported from Pi's `ai` package |
| [`bake-cli`](../crates/bake-cli/) | The `bake` executable, launch options, embedded docs (`bake docs headless` for scripts and other agents), print/RPC modes, and update commands |
| [`bake-codemode`](../crates/bake-codemode/) | The native engine of Pi's codemode for Bake: the pinned QuickJS-NG WebAssembly binary run by Wasmtime in process, with Bake's own WASI shim and C API driver, Pi's script environment (prelude), source format, declarations, deterministic mode, and tool-search ranking; no agent types |
| [`bake-coding-agent`](../crates/bake-coding-agent/) | Pi's coding-agent services for Bake: sessions, the file tools (read, write, edit, ls, find, grep) with their output, truncation in whole characters, and file-mutation ordering, the bash tool and its timeout reports, models, prompts, skills, print mode with its `--output-format` result object and the first-byte wait for piped input, the CLIProxyAPI route, the D24 permission layer over bake-sandbox (full access by default as in Pi, session grants, deny notes, and switching presets during a session), session-owned MCP servers over stdio and Streamable HTTP, the web_search and web_fetch tools, the opt-in `visualize` chart, table, and diagram tool (`tools::visualize`, reading a diagram's Mermaid source with `bake-mermaid`), branch summaries at the session's thinking level, and compaction, with the threshold setting and the cached summary adapted from pi-cached-compaction, on by default |
| [`bake-mcp`](../crates/bake-mcp/) | The Model Context Protocol client boundary ported from Pi's `mcp` package: initialization, tool listing and calls, cancellation, and awaited shutdown over an injected, bounded transport, owned stdio server processes, and Streamable HTTP |
| [`bake-mermaid`](../crates/bake-mermaid/) | A bounded, total Mermaid-to-text renderer ported from OpenAI Codex's `codex-mermaid` (Apache-2.0; its NOTICE carries the license and marks each adapted file): flowcharts and sequence, state, class, and ER diagrams as lines of semantic node, edge, and text spans, or `Unsupported`, `Limit`, or `TooWide`, never a partial diagram, and Bake's `outline` of a source's family, node and link counts, and unlimited drawn size; no I/O and no ANSI output |
| [`bake-plugin-sdk`](../crates/bake-plugin-sdk/) | Guest-side bindings for Bake plugins: the bake:plugin@0.1.0 WIT contract for Rust components built for wasm32-wasip2 |
| [`bake-process`](../crates/bake-process/) | The owner of a spawned child and its whole process tree, shared by Bake's coding tools and MCP stdio servers: admission before creation, pinned leader identity, a Unix process group or a Windows Job the child is born in, and kill or detach settled to observed quiescence |
| [`bake-release`](../crates/bake-release/) | The release tool, never shipped: tag preflight, the archive packer and its self-checks, the third-party license bundle, the glibc floor, the install rehearsal with the shipped installer, manifest signing, and the live check, each verified with `bake-update` |
| [`bake-sandbox`](../crates/bake-sandbox/) | Bake's process-confinement contract: sandbox modes, per-call policies, escalation vocabulary with its once, session, and full-access outcomes, and the provider seam its backends implement |
| [`bake-tui`](../crates/bake-tui/) | Terminal ownership, Kitty keyboard input, clipboard, the terminal title with Ghostty progress and notifications, Herdr lifecycle and sidebar-token reporting, event loop, and live/fixture runtime connections, the `/permission` command, including the projection that draws a `visualize` call from its arguments while they stream, a diagram's source kept to its last newline, the live opening banner, its access tags, and the startup update notice |
| [`bake-tui-view`](../crates/bake-tui-view/) | Pure editor and presentation state, key bindings, the approval panel with its four answers and deny note, transcript layout and its per-tool call cards, previewed or expanded with Ctrl+O and named by a hint on the newest card with a count until it is used, and rendering, including the tasks surface under the composer: subagents and background shells on one standing row and in one list, with an agent's ledger and a shell's output; the status line's palette (`palette`, with the chart series colours `palette::SERIES`), state dot, and context gauge; the `visualize` card (`visual`: `Row::Visual`, bar, line, table, and Mermaid diagram drawings per width and look, a diagram drawn by the answers' fence path whatever `markdown.mermaid` says); Mermaid fences in answers drawn as diagrams through `bake-mermaid` (`mermaid`, under `markdown.mermaid`: `off`, `final`, or `streaming`, the longest run of a streaming fence's complete lines that renders); the layout planner puts the status line last and the bar above the box only while it has something to say, and the activity is drawn under the transcript's newest line |
| [`bake-update`](../crates/bake-update/) | Signed release verification, bounded downloads, installation locks, atomic updates, and rollback |

Dependencies are pinned exactly in `Cargo.toml`, with comments stating their purpose, license, and whether they ship. Keep test-only crates in dev-dependencies. Crate NOTICE files retain Pi's MIT attribution and source revisions, and `bake-mermaid`'s the Apache-2.0 license and NOTICE of the Codex source it adapts.

## Checks

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --workspace --locked
cargo build --release --locked -p bake-cli
cargo test --locked -p bake-agent --lib
```
