# Scope 02: native limit classification under D21

## Summary

[D21](../scope-00/support.md#decision-register) lets a native reader refuse, as a named native limit, only a spelling no released Bake writer produces; every log a released writer can produce must be decided as TypeScript decides it. This page classifies every native limit the Rust crates name, so each one is either justified by writer evidence, listed as a gap to port, or marked as undecided with the evidence that would decide it. [`native-limits.json`](native-limits.json) holds the same classification for tools, and [`native_limit_classification.rs`](../../../../rust/crates/bake-session/tests/native_limit_classification.rs) checks it against the sources it classifies.

There are 323 limit cases in 33 conformance case tables, grouped into 108 classified limits that cover all 99 limit-enum variants of 25 enums in `bake-session` plus string-named stage limits and `bake-cli` refusals. 94 limits (287 cases) are unreachable, 6 (4 cases) are reachable gaps, and 8 (32 cases) are undecided; owner decisions D28 and D29 settled two of the rows the undecided-limits pass left. The classification changed no limit's behavior; the event-types port later removed `replay-event-type`, whose gap request derivation now decides as TypeScript does, and the writer-spelling numbers port closed the provider-usage, context-window, unsafe-integer, payload-count, and row-encoder gaps; two usage rows it narrowed and four pass-through rows that followed it are now undecided. The deep-payloads port removed `replay-depth` and `restore-depth`: the scan, restoration, and request derivation read payloads of any depth with an iterative parser and stack-safe copies, comparisons, and drops, and the migrations port removed `migration-row-json-parser`: the older-generation migrations read rows of any depth too, so their `row/json-parser` stage, like `scan-json-parser`, refuses only lone surrogates and out-of-range numbers and now belongs to that row. `scan-json-parser` and the pass-throughs `log-file-scan`, `log-file-migration`, and `cli-migration-limit` are now reachable gaps, and so is `migrated-restore-restore`. The undecided-limits pass removed `content-kind-diagnostic` and the printing half of `v1-to-v2-float-lexeme`, whose refusal messages now print every number as `JSON.stringify` does, and settled the rest from writer traces and a read-only scan of real logs: lone surrogates, extra request config members, `Object.prototype` event types, and Session directories named `*.jsonl` are reachable gaps. The layout port removed `log-file-opposite-encoding`, whose refusal now carries TypeScript's encoding-mismatch message, and narrowed `log-file-windows-name` to a Win32 path platform; the lookup port removed `cli-migration-required`, so `bake-cli` lookup migrates older generations in memory, leaving the pass-through `cli-migration-limit`. The legacy-layout port removed `log-file-legacy-layout`: a Session directory named `*.jsonl` is listed as TypeScript lists it, and the flat-layout refusal, including the probe that refuses the id `nightly` beside a Session directory `nightly.jsonl`, now carries TypeScript's message. The lone-surrogates port made `parse_json` hold lone surrogates, re-expecting the `json-parser` rows from TypeScript, so `scan-json-parser` and `header-json-parser`, which now refuse only out-of-range numbers, and the pass-through `log-file-scan` are unreachable, and `log-file-migration`, left with untraced stage names, is undecided, and so is `cli-migration-limit`, which follows it now that `migrated-restore-restore` is unreachable. The stored-identity port removed `log-file-identity`: a writer on a case-insensitive volume puts a log whose `cwd` differs from an earlier one's only by case into that earlier project directory, so the selected path and the one its header names differ in spelling, and a write `open` now admits them when `realpath` resolves both to one file and otherwise refuses with TypeScript's `assertStoredIdentity` message, while a symlinked or renamed root never makes them differ, since both are spelled from the configured root.

## How limits were counted

A limit case is one conformance expectation that names a native limit. In a case table (`conformance/**/*-cases.json`) it is a string `limit` member, 302 in all, or a `bake-cli` refusal whose `kind` is `native-limit`, 21 in the list, lookup, and stat tables. A `limit` member under a nested object of a `rust` marker is named with that scope, as `inbox:count` and `consumedWork:inserted` in the inbox tables, because the same name means a different limit there. A `bake-cli` refusal is named `<stage>/<reason>`, or `<stage>/` when its reason is `null`; such a refusal passes a `bake-session` limit or a byte budget through. Files under `conformance/invalid/` are malformed synthetic-runner inputs, not case tables. A figure of 398 native limits has been quoted, but it appears nowhere in this checkout and no count reproduces it: counting every occurrence of the text `limit` in the conformance JSON files gives 465, which includes history prose and other keys, and counting `"limit"` keys alone gives the 302 string members above.

A limit variant is a variant of a `pub enum` named `*Limit` or `*Coercion` in `rust/crates/bake-session/src`: 99 variants in 25 enums. `bake-cli` defines no limit enum of its own. Stage limits that a migration names with a string, such as `v2-to-v3/payload-float-lexeme`, are listed by name; one row may carry several spellings of the same limit, such as `seq-float-lexeme` in the v1 codec and the v0-to-v1 edge. A pass-through variant, such as `ScanLimit::Codec`, wraps another limit; it has its own row, its cases are those its tables name with its wrapper name, and its classification is that of the limits it is seen passing through.

## Writer domain

The released writers are every Bake release, all of which write format 3 (`SESSION_FORMAT_VERSION = 3` at every tag from `v0.1.1`), and the upstream DeepSeek Harness releases whose format 0 to 2 logs Bake reads ([D23](../scope-00/support.md#decision-register)). Their release tags are not in this repository, so the historical citations name the last trunk commit before each format change: format 0 at `3efd4b51e0` (parent of `d1521ea783`), format 1 at `0bb7bba015` (parent of `f99b06eaed`), and format 2 at `81dcacbb44` (parent of `f7a6221158`). A citation `<commit>:<path>:<line>` reads that tree with `git show`.

A value counts as writer-produced when a first-party producer, a provider, an MCP server, a model, or a plugin using the documented API can put it in a log. A plugin that violates its declared TypeScript type at run time, for example by passing a number as an event type, is outside this domain; rows that rely on that rule say so. [D29](../scope-00/support.md#decision-register) applies the same rule to a provider that sends a usage count outside its own declared integer schema. Lane N's number port is part of the baseline: restoration and request derivation admit every `JSON.stringify` spelling, so the number limits that remain refuse only spellings no writer produces.

## Writer anchors

These facts recur across rows and are cited by tag.

- **W1:** Every released writer serializes rows and headers with JSON.stringify: v3 packages/session/session-persistence-jsonl/src/format.ts:322 and index.ts:1208; v2 81dcacbb44:packages/session/session-persistence-jsonl/src/format.ts:321 and index.ts:1212; v1 0bb7bba015:packages/session/session-persistence-jsonl/src/format.ts:350 and index.ts:1026; v0 3efd4b51e0:packages/session/session-persistence-jsonl/src/format.ts:256 and index.ts:659. - **W2:** Session.append snapshots data as lossless JSON and throws on -0, non-finite numbers, and non-plain values: packages/core/session/src/index.ts:737-740 with packages/util/values/src/index.ts:180; 3efd4b51e0:packages/core/session/src/index.ts:678, 0bb7bba015:...:670, 81dcacbb44:...:688, each with packages/util/values/src/index.ts:129.
- **W3:** Session.append assigns seq from the log length and time from Date.now(): packages/core/session/src/index.ts:751-752; 3efd4b51e0:packages/core/session/src/index.ts:693-694; 0bb7bba015:...:684-685; 81dcacbb44:...:702-703.
- **W4:** The v3 encoder runs assertV3Event before writing (packages/session/session-format-v2-to-v3/src/codec.ts:71-75), which requires a count seq, a safe-integer time, count surfaceOp endpoints below seq, and unique earlier count sourceEventSeqs (packages/session/session-format-v2-to-v3/src/payload.ts:278-309).
- **W5:** Headers are written by toHeaderLine through JSON.stringify (packages/session/session-persistence-jsonl/src/index.ts:1208) from a header whose createdAt is Date.now() (packages/core/session/src/index.ts:151) and whose version is SESSION_FORMAT_VERSION = 3 (packages/core/session/src/types.ts:89).
- **W6:** Turn and step are integer counters: packages/core/agent-loop/src/agent.ts:307-313 (turn/start) and 325-340 (step/start); settlements and tool calls copy them (agent.ts:452-493, packages/core/agent-loop/src/tool-calls.ts:329).
- **W7:** Provider usage reaches the log unvalidated: pi-ai 1.0.0 (bun.lock, also in v0.3.8) copies wire counts in parseChunkUsage (node_modules/@earendil-works/pi-ai/dist/api/openai-completions.js:1160-1180), mapUsage copies them (packages/llm/llm-pi-ai/src/stream.ts:25-33), and the stream accumulator records the usage chunk as is (packages/llm/llm/src/assistant-stream.ts:170-172); the v2 writer did the same (81dcacbb44:packages/llm/llm-deepseek/src/translate.ts:55-71), checking only its own total with Number.isSafeInteger. A provider count such as 12.5, 2^53, or the string "5" (which `cacheRead > 0` and `completion_tokens || 0` keep) is written.
- **W8:** An MCP server's inputSchema is kept as parsed (packages/mcp/mcp-client/src/protocol.ts:300-302, mode keep), becomes the tool's parameters (packages/mcp/mcp-client/src/tools.ts:143,243), and is logged in request/header tools (packages/core/agent-loop/src/agent.ts:640-653); the v2 and v0 writers did the same (81dcacbb44:packages/mcp/mcp-client/src/tools.ts:168 and 81dcacbb44:packages/core/agent-loop/src/agent.ts:552; 3efd4b51e0:packages/mcp/mcp-client/src/tools.ts:168 and agent.ts:508). No depth or magnitude bound applies, so a schema nesting past 64 containers or holding an integer such as 9223372036854775807 (written 9223372036854776000) is logged.
- **W9:** The llm/retry delayMs is fractional: retryDelayMs multiplies by a random jitter (packages/llm/llm/src/retry-policy.ts:233-234) and is logged at packages/llm/llm-retry/src/index.ts:182; the v2 writer jittered the same way (81dcacbb44:packages/llm/llm-retry/src/index.ts:62).
- **W10:** A caller-chosen budget, not a spelling: the limit fires only when the caller's budget is below the log's size. Budgets reach 2^53 - 1 (rust/crates/bake-cli/src/inspect.rs:27), and no writer-produced log exceeds that, because every seq is a safe count (packages/session/session-format-v2-to-v3/src/payload.ts:278). TypeScript has no such bound.

## Reachable gaps

Each of these limits refuses input a released writer produces, so D21 requires a port. The writer-spelling numbers port closed the gaps for provider usage numbers, large context windows, payload counts in migration, unsafe integers in free data, and the row encoder; their rows are now unreachable, except the two usage rows listed as undecided. One gap remains open, and D28 accepts its refusal:

- **`Object.prototype` event types** (`object-prototype-type` and the pass-throughs `history-v0-to-v1`, `history-v1-to-v2-decoded`, `v1-to-v2-decoded-payload`, and `history-v2-to-v3`): plugins extend the event vocabulary by declaration merging, and the v0 to v2 `append` checks names only by set membership, so a plugin event named `constructor` is written. D21 names this spelling among its permitted limits on the premise that no writer produces it. TypeScript refuses such a log as well, but only with a V8 `TypeError` (`required is not iterable` before format 2, `Cannot read properties of undefined (reading 'find')` in v2 to v3), so both arms refuse and only the message differs. Porting the inherited-name lookups would mean reproducing V8 error text, which AGENTS.md forbids; [D28](../scope-00/support.md#decision-register) accepts this refusal under D21's `TypeError` clause, so it has no follow-up.

These ports have closed the other gaps:

- **Lone surrogates:** `parse_json` holds a lone surrogate in a string or key, in a collision-free spelling of JavaScript code units in a Rust `String` (`rust/crates/bake-session/src/js_string.rs`), and every writer path writes it back as `JSON.stringify` does, so the scan, both header parsers, restoration, request derivation, the v0 to v2 migrations, the row encoders, `encode_segment`, and `bake-cli` output read and write the lone surrogates `boundContextSummary` (packages/llm/llm/src/message.ts:121-124) and a configured `agents[].sessionId` leave; `scan-json-parser` and `header-json-parser` now refuse only out-of-range numbers, `log-file-scan` follows them, and `log-file-migration` is undecided on its untraced stage names, with `cli-migration-limit` following it.
- **Deep payloads:** the scan, restoration, request derivation, and the older-generation migrations read payloads of any depth, such as a tool schema from an MCP server ([W8](#writer-anchors)), with an iterative parser and stack-safe copies, comparisons, and drops; plain-log-file `migrate-v2-deep-tool-schema` witnesses a v2 row nested 207 levels migrating unchanged.
- **Layout and lookup:** the layout port closed both layout gaps: a compressed generation a writer configured for Zstd leaves behind is refused with TypeScript's exact encoding-mismatch message, and a configured `agents[].sessionId` such as `con`, `nightly.`, or `aux.txt` is laid out on POSIX as TypeScript lays it out. The legacy-layout port closed the `*.jsonl` Session directory gap: the root check refuses only a regular file named `*.jsonl` or `*.jsonl.zstd` in a project directory, as `listSessionDirs` does (packages/session/session-persistence-jsonl/src/index.ts:1518-1520), and the id's flat names are probed by opening them, as `rejectLegacyFlatArtifact` does (index.ts:1539-1551); that open succeeds on a directory on POSIX and on Windows, where libuv opens with `FILE_FLAG_BACKUP_SEMANTICS`, so the id `nightly` beside a Session directory `nightly.jsonl` is refused in both arms with TypeScript's flat-layout message (plain-log-file `legacy-probe-finds-session-directory`). `bake-cli` lookup, which once declined v0 to v2 logs, now migrates plain and Zstd ones as TypeScript's read `open` does.
- **Extra request config members:** the config-members port closed the gap an `agent/request` waterfall listener opens when it returns an object with members outside `LlmCallConfig` (packages/core/agent/src/runtime-types.ts:363), which the loop logs (packages/core/agent-loop/src/agent.ts:590-614). Request derivation and restoration keep such a member, of any value and depth, in the logged order, with array-index keys first, a repeated key's last value, and `__proto__` as an own member, and a request carries it as `{...header.config}` does. Released v0 to v2 payload checks refuse such a member before migration (packages/session/session-format-v0-to-v1/src/payload-validation.ts:799-806), so no migrated Session restores one.

`log-file-windows-name` stays a reachable gap on a Win32 path platform only: a Windows writer with `sessionId: nightly.` writes a log TypeScript reopens and Rust refuses. [D26](../scope-00/support.md#decision-register) accepts this refusal as an owner exception to D21, so it has no follow-up.

On this pass a read-only Node script, kept outside the repository, decompressed each Session log under the owner's `~/.bake/sessions` in memory and counted conditions without writing, moving, or locking anything there; only these aggregate counts were recorded. The home held 93 Zstandard logs, all format 3 (40,514 rows, 151 MB decompressed), one `session.lock` beside each, and no v0 to v2 log. Every log decoded as UTF-8 and every row parsed. Counts per condition:

- string escapes of a surrogate code unit: 0 of 40,514 rows, and no lone surrogate in any parsed string or key (8 escaped-backslash `\\ud...` literals in 2 rows are ordinary text);
- `request/header` config members outside `provider`, `model`, `reasoningEffort`, `temperature`, `maxTokens`, and `stop`: 0 of 113 rows, and no `tools` value that is not a non-empty array of objects;
- usage members: 68,001 in `assistant/message` usage and 6,865 stream usage chunks, every member a number; no non-object sample;
- own `__proto__` members: 0 rows; event types outside `KNOWN_SESSION_EVENT_TYPES` or named after an `Object.prototype` member: 0 rows;
- negative zero, an integral number outside the safe range, or a number `JSON.stringify` writes with an exponent: 0;
- entries in a project directory that are not Session directories: 0; files in a Session directory other than `session.v<N>.jsonl[.zstd]` and `session.lock`: 0; a project or Session directory name that differs from `projectKey(cwd)` or `encodeSegment(id)` of its header: 0 of 93; the sessions root is not a symlink.

## Resource and filesystem bounds

`source-output-budget`, `v1-codec-source-output-budget`, `cli-header-budget`, `cli-entry-budget`, and the `--max-bytes` refusal behind `cli-session-limit` are caller-chosen budgets of at most 2^53 - 1 that TypeScript does not have; at that maximum no writer-produced log exceeds them, so they are unreachable in the D21 sense, and production callers must size them from the log. `scan-event-count` is bounded by the safe-count seq. No reader has a depth bound: the current-format reader and the older-generation migrations parse rows of any depth. The filesystem limits concern names and layouts rather than row spellings; writers name every file from a non-empty id, generated or configured, that encodeSegment escapes to ASCII, which makes `create-empty-id`, `log-file-empty-id`, `log-file-non-utf8-name`, and `cli-non-utf8-name` unreachable. A configured id may still end in `.` or name a Windows device, so `log-file-windows-name` is a reachable gap; one ending in `.jsonl` is laid out and refused as TypeScript does.

## Keeping the classification current

[`native_limit_classification.rs`](../../../../rust/crates/bake-session/tests/native_limit_classification.rs) reads the JSON, every case table, and the crate's sources. It requires every limit-enum variant and every table limit name to belong to exactly one row, the row's case counts to equal the tables', and every settled row that is not a pass-through to cite a source line. A new limit-enum variant, a new limit case, or a removed one fails it until this page and the JSON are updated together. String-named stage limits, such as `v2-to-v3/row-count` (rust/crates/bake-session/src/v2_to_v3/mod.rs:360) and `migration/finish-order` (rust/crates/bake-session/src/plain_log_file.rs:687), are not enumerated from the source: each row's `stageNames` is kept by hand, and a new stage limit that no case witnesses passes the test until it is added.

(cd rust && cargo test --locked -p bake-session --test native_limit_classification)

## Dev Note

Non-authoritative. The classification was written from the TypeScript sources at this checkout, the historical trunk commits named above, `pi-ai` 1.0.0 in `node_modules`, and the archived release schemas, and, for the undecided-limits pass, the aggregate counts of the [real-log scan](#real-log-scan); no network call was made. Line citations are to this checkout unless prefixed with a commit. The historical writers were identified from `git log -G 'SESSION_FORMAT_VERSION = '`, and the upstream release tags themselves were not inspected.

The event-types port removed `ReplayLimit::EventType`. The TypeScript `replayRequests` helper admits every event type, and `replay_requests` now does too: an unknown type is log-only, refused only when it is required and carries a surface marker (`seed/non-surface-marker`), and `session/end-seed` is an ordinary known log-only type. `replay_requests` still ports a test helper; production derivation is `restore_plain_log` with `replay_restored_requests`, which refuses an unknown required type as restoration does.

The config-members port removed `ReplayLimit::ConfigMember` and `RestoreLimit::ConfigMember`. `replay_requests` and `restore_plain_log` keep every `config` member as Session construction does, and `Request::to_json` spreads `config` first, so a member named `messages`, `toolHistory`, `tools`, or `sessionId` keeps its place and takes the request's value, and a `tools` member stays when the header declares no tools. The restore conformance arms now also compare the restored request header as `JSON.stringify` text.

The stored-identity port removed `LogFileLimit::Identity`. `PlainLogFile::open` checks a current or older generation's header as `assertStoredIdentity` does (packages/session/session-persistence-jsonl/src/index.ts:1432-1498): a requested id the header does not carry, or a selected path its id and `cwd` do not name, by spelling or else by `realpath`, is refused with TypeScript's message, as `LogFileRefusal::StoredIdentity` or inside a migration's corruption message. `fs::canonicalize` calls the `realpath(3)` or `GetFinalPathNameByHandleW` that libuv's `uv_fs_realpath` calls for Node, so the arms agree on every volume: macOS and Windows resolve a case alias to the on-disk spelling, while Linux, a casefold volume included, keeps the spelling it is given. A writer reaches a case alias by writing Sessions whose `cwd` values differ only by case on a case-insensitive volume (`projectDir` and `materialize`, packages/session/session-persistence-jsonl/src/format.ts:253-256 and index.ts:1100), which `identity-case-alias-written` witnesses on macOS and Windows.
