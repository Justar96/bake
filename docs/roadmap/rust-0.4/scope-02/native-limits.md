# Scope 02: native limit classification under D21

## Summary

[D21](../scope-00/support.md#decision-register) lets a native reader refuse, as a named native limit, only a spelling no released Bake writer produces; every log a released writer can produce must be decided as TypeScript decides it. This page classifies every native limit the Rust crates name, so each one is either justified by writer evidence, listed as a gap to port, or marked as undecided with the evidence that would decide it. [`native-limits.json`](native-limits.json) holds the same classification for tools, and [`native_limit_classification.rs`](../../../../rust/crates/bake-session/tests/native_limit_classification.rs) checks it against the sources it classifies.

There are 344 limit cases in 33 conformance case tables, grouped into 116 classified limits that cover all 106 limit-enum variants of 25 enums in `bake-session` plus string-named stage limits and `bake-cli` refusals. 87 limits (270 cases) are unreachable, 9 (14 cases) are reachable gaps, and 20 (60 cases) are undecided. The classification changed no limit's behavior; the event-types port later removed `replay-event-type`, whose gap request derivation now decides as TypeScript does, and the writer-spelling numbers port closed the provider-usage, context-window, unsafe-integer, payload-count, and row-encoder gaps; two usage rows it narrowed and four pass-through rows that followed it are now undecided.

## How limits were counted

A limit case is one conformance expectation that names a native limit. In a case table (`conformance/**/*-cases.json`) it is a string `limit` member, 321 in all, or a `bake-cli` refusal whose `kind` is `native-limit`, 23 in the list, lookup, and stat tables. A `limit` member under a nested object of a `rust` marker is named with that scope, as `inbox:count` and `consumedWork:inserted` in the inbox tables, because the same name means a different limit there. A `bake-cli` refusal is named `<stage>/<reason>`, or `<stage>/` when its reason is `null`; such a refusal passes a `bake-session` limit or a byte budget through. Files under `conformance/invalid/` are malformed synthetic-runner inputs, not case tables. A figure of 398 native limits has been quoted, but it appears nowhere in this checkout and no count reproduces it: counting every occurrence of the text `limit` in the JSON files gives 473, which includes history prose and other keys, and counting `"limit"` keys alone gives the 324 above.

A limit variant is a variant of a `pub enum` named `*Limit` or `*Coercion` in `rust/crates/bake-session/src`: 106 variants in 25 enums. `bake-cli` defines no limit enum of its own. Stage limits that a migration names with a string, such as `v2-to-v3/payload-float-lexeme`, are listed by name; one row may carry several spellings of the same limit, such as `seq-float-lexeme` in the v1 codec and the v0-to-v1 edge. A pass-through variant, such as `ScanLimit::Codec`, wraps another limit; it has its own row, its cases are those its tables name with its wrapper name, and its classification is that of the limits it is seen passing through.

## Writer domain

The released writers are every Bake release, all of which write format 3 (`SESSION_FORMAT_VERSION = 3` at every tag from `v0.1.1`), and the upstream DeepSeek Harness releases whose format 0 to 2 logs Bake reads ([D23](../scope-00/support.md#decision-register)). Their release tags are not in this repository, so the historical citations name the last trunk commit before each format change: format 0 at `3efd4b51e0` (parent of `d1521ea783`), format 1 at `0bb7bba015` (parent of `f99b06eaed`), and format 2 at `81dcacbb44` (parent of `f7a6221158`). A citation `<commit>:<path>:<line>` reads that tree with `git show`.

A value counts as writer-produced when a first-party producer, a provider, an MCP server, a model, or a plugin using the documented API can put it in a log. A plugin that violates its declared TypeScript type at run time, for example by passing a number as an event type, is outside this domain; rows that rely on that rule say so. Lane N's number port is part of the baseline: restoration and request derivation admit every `JSON.stringify` spelling, so the number limits that remain refuse only spellings no writer produces.

## Writer anchors

These facts recur across rows and are cited by tag.

- **W1:** Every released writer serializes rows and headers with JSON.stringify: v3 packages/session/session-persistence-jsonl/src/format.ts:322 and index.ts:1208; v2 81dcacbb44:packages/session/session-persistence-jsonl/src/format.ts:321 and index.ts:1212; v1 0bb7bba015:packages/session/session-persistence-jsonl/src/format.ts:350 and index.ts:1026; v0 3efd4b51e0:packages/session/session-persistence-jsonl/src/format.ts:256 and index.ts:659. Number::toString writes an integral double below 1e21 without a fraction or exponent, 0 for -0, and the shortest round-trip digits.
- **W2:** Session.append snapshots data as lossless JSON and throws on -0, non-finite numbers, and non-plain values: packages/core/session/src/index.ts:737-740 with packages/util/values/src/index.ts:180; 3efd4b51e0:packages/core/session/src/index.ts:678, 0bb7bba015:...:670, 81dcacbb44:...:688, each with packages/util/values/src/index.ts:129.
- **W3:** Session.append assigns seq from the log length and time from Date.now(): packages/core/session/src/index.ts:751-752; 3efd4b51e0:packages/core/session/src/index.ts:693-694; 0bb7bba015:...:684-685; 81dcacbb44:...:702-703.
- **W4:** The v3 encoder runs assertV3Event before writing (packages/session/session-format-v2-to-v3/src/codec.ts:71-75), which requires a count seq, a safe-integer time, count surfaceOp endpoints below seq, and unique earlier count sourceEventSeqs (packages/session/session-format-v2-to-v3/src/payload.ts:278-309).
- **W5:** Headers are written by toHeaderLine through JSON.stringify (packages/session/session-persistence-jsonl/src/index.ts:1208) from a header whose createdAt is Date.now() (packages/core/session/src/index.ts:151) and whose version is SESSION_FORMAT_VERSION = 3 (packages/core/session/src/types.ts:89).
- **W6:** Turn and step are integer counters: packages/core/agent-loop/src/agent.ts:307-313 (turn/start) and 325-340 (step/start); settlements and tool calls copy them (agent.ts:452-493, packages/core/agent-loop/src/tool-calls.ts:329).
- **W7:** Provider usage reaches the log unvalidated: pi-ai 1.0.0 (bun.lock, also in v0.3.8) copies wire counts in parseChunkUsage (node_modules/@earendil-works/pi-ai/dist/api/openai-completions.js:1160-1180), mapUsage copies them (packages/llm/llm-pi-ai/src/stream.ts:25-33), and the stream accumulator records the usage chunk as is (packages/llm/llm/src/assistant-stream.ts:170-172); the v2 writer did the same (81dcacbb44:packages/llm/llm-deepseek/src/translate.ts:55-71), checking only its own total with Number.isSafeInteger. A provider count such as 12.5, 2^53, or the string "5" (which `cacheRead > 0` and `completion_tokens || 0` keep) is written.
- **W8:** An MCP server's inputSchema is kept as parsed (packages/mcp/mcp-client/src/protocol.ts:300-302, mode keep), becomes the tool's parameters (packages/mcp/mcp-client/src/tools.ts:143,243), and is logged in request/header tools (packages/core/agent-loop/src/agent.ts:640-653); the v2 and v0 writers did the same (81dcacbb44:packages/mcp/mcp-client/src/tools.ts:168 and 81dcacbb44:packages/core/agent-loop/src/agent.ts:552; 3efd4b51e0:packages/mcp/mcp-client/src/tools.ts:168 and agent.ts:508). No depth or magnitude bound applies, so a schema nesting past 64 containers or holding an integer such as 9223372036854775807 (written 9223372036854776000) is logged.
- **W9:** The llm/retry delayMs is fractional: retryDelayMs multiplies by a random jitter (packages/llm/llm/src/retry-policy.ts:233-234) and is logged at packages/llm/llm-retry/src/index.ts:182; the v2 writer jittered the same way (81dcacbb44:packages/llm/llm-retry/src/index.ts:62).
- **W10:** A caller-chosen budget, not a spelling: the limit fires only when the caller's budget is below the log's size. Budgets reach 2^53 - 1 (rust/crates/bake-cli/src/inspect.rs:27), and no writer-produced log exceeds that, because every seq is a safe count (packages/session/session-format-v2-to-v3/src/payload.ts:278). TypeScript has no such bound.

## Reachable gaps

Each of these limits refuses input a released writer produces, so D21 requires a port. The writer-spelling numbers port closed the gaps for provider usage numbers, large context windows, payload counts in migration, unsafe integers in free data, and the row encoder; their rows are now unreachable, except the two usage rows below.

- **Deep payloads:** `replay-depth`, `restore-depth`, and `scan-json-parser` refuse nesting a tool schema from an MCP server can reach ([W8](#writer-anchors)). Proposed slice: deep payloads in the scan, replay, and restore, which needs serde_json's `unbounded_depth` feature or another stack-safe parser, a `Cargo.toml` change.
- **Layout and lookup:** `log-file-opposite-encoding` refuses a compressed generation a writer configured for Zstd leaves behind, where TypeScript reports an exact mismatch; `log-file-windows-name` refuses on every host a configured `agents[].sessionId` such as `con` or `nightly.`, whose directory the writer creates on POSIX; and `cli-migration-required` declines to migrate v0 to v2 logs. Proposed slice: port the mismatch refusal, match TypeScript on POSIX for Windows names, and route `bake-cli` lookup through released-history migration.

The pass-through rows `migrated-restore-restore`, `log-file-scan`, and `log-file-migration` are gaps only because they carry one of the limits above.

## Undecided limits

Each needs the evidence named in its follow-up before it can be classified. The two largest are `v1-to-v2-unchecked-shape`, 21 cases over many cast members, and `v1-to-v2-float-lexeme`, whose printing half disappears if refused values are printed with `json_number_text`; `content-kind-diagnostic` can be removed the same way. `header-json-parser` waits on the lone-surrogate question D21 leaves open. `replay-config-member` and `restore-config-member` need an audit of config waterfall listeners; `object-prototype-type` needs an event-type name rule; `relationship-precondition`, `relationship-prototype-member`, and `history-interleaved-emission` need producer traces; `log-file-legacy-layout` and `log-file-identity` need filesystem cases. `usage-usage` and `pressure-usage` keep only non-object samples and counts that are neither numbers nor strings, and need a trace of whether a provider sends a boolean or array count that pi-ai's `completion_tokens || 0` and mapUsage's `> 0` checks pass. The pass-through rows `history-v0-to-v1`, `history-v1-to-v2-decoded`, `history-v2-to-v3`, and `v1-to-v2-decoded-payload` follow `object-prototype-type`, and `history-v2-to-v3` also `content-kind-diagnostic`.

## Resource and filesystem bounds

`source-output-budget`, `v1-codec-source-output-budget`, `cli-header-budget`, `cli-entry-budget`, and the `--max-bytes` refusal behind `cli-session-limit` are caller-chosen budgets of at most 2^53 - 1 that TypeScript does not have; at that maximum no writer-produced log exceeds them, so they are unreachable in the D21 sense, and production callers must size them from the log. `scan-event-count` is bounded by the safe-count seq. The 64-container payload depth and serde_json's 128-level parse depth have no TypeScript equivalent short of the V8 stack and are reachable gaps above. The filesystem limits concern names and layouts rather than row spellings; writers name every file from a non-empty id, generated or configured, that encodeSegment escapes to ASCII, which makes `create-empty-id`, `log-file-empty-id`, `log-file-non-utf8-name`, and `cli-non-utf8-name` unreachable. A configured id may still end in `.` or name a Windows device, so `log-file-windows-name` is a reachable gap.

## Keeping the classification current

[`native_limit_classification.rs`](../../../../rust/crates/bake-session/tests/native_limit_classification.rs) reads the JSON, every case table, and the crate's sources. It requires every limit-enum variant and every table limit name to belong to exactly one row, the row's case counts to equal the tables', and every settled row that is not a pass-through to cite a source line. A new limit-enum variant, a new limit case, or a removed one fails it until this page and the JSON are updated together. String-named stage limits, such as `v2-to-v3/row-count` (rust/crates/bake-session/src/v2_to_v3/mod.rs:360) and `migration/finish-order` (rust/crates/bake-session/src/plain_log_file.rs:623), are not enumerated from the source: each row's `stageNames` is kept by hand, and a new stage limit that no case witnesses passes the test until it is added.

```sh
(cd rust && cargo test --locked -p bake-session --test native_limit_classification)
```
