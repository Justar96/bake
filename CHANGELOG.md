# Changelog

Notable changes to Bake. `/changelog` in the terminal prints the section for the running version, so each release heading must match the root `package.json` version.

## [Unreleased]

- Identical edits refused for unread or stale files skip repeated tool dispatch within the same turn until another tool settles. The filesystem guard remains strict, and tool guidance explains how to reread and recover, scope searches, run long commands in background jobs, and respect subagent depth limits.
- Failed command exits, signals, and HTTP responses appear as failed tool outcomes in the terminal.
- `/model` refreshes CLIProxyAPI's model list while keeping models used by the current session, default selection, and subagents. Advanced settings use the same subagent model pickers as the Agent section.
- Alt-Up sends queued steering immediately by interrupting the current turn. Markdown has clearer headings, lists, tables, and inline code, and reasoning efforts share colours across the model picker and status line.
- The terminal loads its renderer, fullscreen view, and syntax highlighting on demand; disabled telemetry leaves the OpenTelemetry SDK unloaded.

## [0.2.0] - 2026-09-30

- The composer's key hint (`Enter sends`, `Tab completes`) and the goal at the end of the header no longer lose their last characters in Warp and other terminals that erase a full row's last cell when the rest of the row is cleared. Every row the terminal redraws is now cleared before it is drawn.
- Installing and updating Bake has a new look in place of the loaf. The installers and `bake update` open with a `BAKE` heading, print each step once it finishes (`✓  Downloaded  18.4 MB · 2.1s`), and close with what was installed and the command to run. The step still running is one live row: an orbit of Braille dots circling a square, then a meter the download fills from orange to amber with a glint sweeping across it, beside its percentage and bytes. Steps without a known length run a comet back and forth instead of a guessed percentage, and a failed step is marked `✗` above the error. The installers now show real download progress from the size the signed manifest records. `/update` draws the same live row above the composer. Colour is 24-bit where the terminal says it supports it, and Windows Terminal gets the Unicode glyphs.
- `/model` is one sheet instead of two pickers. It leads with Recent (the current model and up to four chosen before), then lists each signed-in provider's models under its name, newest first, so `GPT-6.1` comes before `GPT-4` rather than after it. Each row shows the model's name, its context window, `think` when it offers reasoning efforts, and `image` when it accepts images. The effort row under the list follows the selected model: ←→ change it, and Enter chooses the model and effort together. The sheet takes up to half the screen, and on a narrow terminal the facts give way before the names are cut. `/model ` completion names each route's model where its id does not.
- Bake has no default provider. With nothing signed in, a new session starts on no model: the status line reads `no model  /login to start`, `/login` leads the `/` menu, and a message stays in the composer with a notice instead of failing. The first sign-in selects that provider's model and saves it as the default. `bake -p` and the desktop bridge, which cannot sign in themselves, stop with a line saying to sign in and choose a model in the terminal. An exported `DEEPSEEK_API_KEY` still counts as signed in.
- `/login` offers OpenAI (Sign in with ChatGPT), Anthropic (Claude Pro/Max), GitHub Copilot, OpenRouter, Kimi, and xAI beside DeepSeek and CLIProxyAPI. Each asks whether to use the subscription sign-in or an API key, and signing in adds the provider's models to `/model` at once.
- `/logout [name]` removes a stored key, the CLIProxyAPI route and key, or a sign-in and the route it added. A key the environment or a `.env` file supplies is named instead of claimed as removed.
- `/login` names targets as people know them: the picker and the `/login ` menu show DeepSeek, CLIProxyAPI, and the rest with whether each is configured and where it lives, and `/login deepseek`, `/login DeepSeek`, or `/login DEEPSEEK_API_KEY` all work. A typo is answered with the nearest name.
- A sign-in field is one panel naming the provider, its step (`●○ 1/2`), the default it keeps, and guidance. A refused answer asks again in the panel with the reason instead of ending `/login`: an empty or malformed key, a key CLIProxyAPI rejects (`HTTP 401`), or an address it cannot reach (`Could not reach 127.0.0.1:8318 (ECONNREFUSED)`), which returns to the address with what was typed. Enter on an empty CLIProxyAPI address keeps the default, as the prompt always said. Keys are masked with `•`, and the `Checking…` notice no longer stays after a failed check.
- A turn that fails for want of a key says under the error to run `/login`, and the error no longer points at a web Models page Bake does not ship.
- Providers reached through pi-ai use its 0.99.1 catalog, so `/model` lists the models those providers publish now, and pi-ai's sign-ins are the ones `/login` offers.
- The subagent sheet stays readable when a session has many children. A bar and counts at the top show how many are done, working, failed, or stopped, each child takes one row, and only the child under the pointer shows its mode and id. Children that finished cleanly are dimmed until selected. The subagent row and tab now count done children too: `↳ Subagents 12 · 2 working · 9 done`.
- Switching on subagent model choice in `/settings` no longer fails with an empty model list. The panel asks for the allowed models first and saves both together, and it keeps the last model while the choice stays on.
- In `/settings`, the models subagents may pick come from the same catalog `/model` lists. Enter adds or removes one, and each change is saved at once.
- Tab and Shift-Tab in `/settings` move to the next or previous section, named on a row of tabs under the title.
- List and map settings under Advanced open as JSON in `$VISUAL`, then `$EDITOR`, then `vi` (Notepad on Windows). JSON with comments is accepted. Text that does not parse, or an editor that exits non-zero, leaves the value unchanged and shows why.
- Auto routing (beta): `/settings` › Agent can turn on a task router once subagents may pick a model, and says first what it sends and where. It is off by default and points at the hosted ing router (`router: {enabled, url, tokenEnv, timeoutMs}`, `url` defaulting to `https://ing.gissx.org`). When a delegation names no model, Bake sends the task and the session's allowed models to `<url>/v1/bake/select` and runs the child on the route it picks, such as a cheap model for a rename and a frontier model for a concurrency design. Each allowed model travels with what Bake knows about it (its reasoning efforts, default effort, context window, and input types) and the user's optional `router.hints` (`sameAs`, a `quality` tier, a `cost` tier such as `free` for a local model), so the router can rank gateway aliases, local models, and fine-tunes it does not recognize. `router.priority` states the trade-off instead of letting the router guess it from the task text. The answer is used only when it is one of the allowed models and the router does not mark it as a fallback. An effort the model does not list becomes the nearest one it does. A failed, slow, or out-of-policy answer falls back to the default route with a warning. The subagent tool's description now tells the model that leaving out the model lets the host choose. Model calibration in `/settings` lists how the router sees each allowed model (the benchmarked model it matched, its quality score and price, and whether it is ranked) and sets each model's quality tier, cost tier, or the model it serves; the routing priority is set there too. Router account in `/settings` signs in to ing by email with a six-digit code, registering on first sign-in, and stores the issued token through the credential store, so no token has to be exported; switching routing on while signed out offers `Sign in and turn on`. An exported `ING_API_TOKEN` still wins.
- `job_output` and `job_kill` explain an unknown job id: it points to `job_list` and says that a continuable subagent's id is an agent id for the subagent control tools, not a job id. The `job_id` parameter description says the same, so the model stops passing subagent ids to the job tools.

## [0.1.9] - 2026-09-28

- Closing Bake between logging a tool call and starting it records a cancelled turn. Source and built tool runtimes also share their scheduler identity, preventing the `Cannot read properties of undefined (reading 'prepare')` failure.
- On Windows, Bake locks each session's `session.lock` file across desktop and SSH login sessions, so two Bake processes cannot write the same log at once. A crashed process releases the lock; a live holder still blocks a second writer.
- The `cordis` preset now teaches plugin authors to add tools and terminal slash commands, verify them in Bake, and choose a copied preset with `--preset`. It no longer sends drawing and widget requests to a Web UI Bake does not ship.
- The npm `dsh` command now starts Node with the same diagnostic flags as `bake`, so the runtime watchdog can save fatal-error reports without environment variables or network details. It defaults to `~/.bake`, preserves an explicit `DSH_HOME`, and preserves shutdown signals and exit status through its one-time restart.
- Fullscreen scrolls with the mouse wheel, three rows a notch, and scrolls an open sheet the same way. Reading history, the row above the input offers `↓ Latest · Ctrl+End`, which turns to `↓ New output · Ctrl+End` when output arrives below; click it or press Ctrl+End to jump back. Fullscreen now takes the mouse, so select text with Shift-drag (Option-drag on macOS).
- Bake no longer sends your sessions to DeepSeek. `/feedback` used to upload the session's history to DeepSeek's telemetry service; telemetry now has no default destination and stays off unless you set `DSH_TELEMETRY_OTLP_URL` to a collector of your own, and `/feedback` says whether the feedback stays in the local session log or is uploaded there. Requests to DeepSeek's own API no longer carry the session log in `dsh_session_log`; set `session-log-deepseek` `enabled: true` to send it again.
- Every request to a pi-ai route names its session in `x-deepseek-harness-session-id`, so a proxy that balances several upstream accounts, such as CliRelay with `session-sticky` routing, keeps a session on one account. Prompt caches belong to one account, so a session that hopped between them re-sent its whole context at full price on most steps.
- `/login cliproxyapi` writes two defaults for multi-account proxies: a retry delay of up to 60 seconds, and session affinity (`x-session-affinity`) on its Claude and Chat Completions models.
- A CLIProxyAPI route saved by an earlier release is upgraded when Bake starts, with no new login: each model's protocol, Claude's endpoint and adaptive thinking, and the two defaults above are filled in where missing, and a notice names what changed. Values you set by hand, including `false`, are kept. If the settings file cannot be written, the notice asks you to run `/login cliproxyapi` instead.
- When a proxy answers `429` or `503` with `reset_seconds` because every account for a model is cooling down, Bake waits that long before retrying if it fits the route's `retryPolicy.backoff.maxDelayMs`, and otherwise ends the turn at once instead of spending its retries inside the cooldown.
- A pi-ai route or model can set `compat.sendSessionAffinityHeaders` to send the session as `x-session-affinity` on Anthropic Messages and Chat Completions.
- Automatic compaction no longer trims old tool results just below the context threshold over and over. A trim alone must free at least half the room a summary would; otherwise the same pass also summarizes. Each rewrite invalidates the provider's prompt cache, and one long session had re-sent about 200k tokens after trims that saved 2k.
- `update_goal` accepts an objective or round cap copied unchanged from `get_goal` in an action that does not use it, instead of rejecting the call.
- Closing the task, subagent, or goal view no longer leaves a blank block above the prompt until new output fills it. The history the view pushed up is redrawn back down against the prompt, which stays on the bottom rows.
- The status line keeps the cache-hit reading when tasks, a goal, and subagents crowd it; only the input and output totals give way. It used to disappear as soon as a session with a task list spawned a subagent.
- A prompt a command prints just before it waits for input, such as `Password:`, is no longer missing from the terminal tool's result on a busy machine. The tool now waits for output already on its way before reporting that the command is waiting.
- A programmatic tool call that times out, is cancelled, or exits early keeps the console output it printed before it stopped. Output the program had sent but Bake had not yet read used to be dropped on a busy machine.
- Bake no longer writes to a session, or takes its lock, after the session closes. An event arriving as a session closed could leave the session's lock file open, which on Node 26 could crash Bake later or make that session report as already in use until restart. It could also write to the session after its lock was released.
- The model's instructions are shorter and plainer, about a quarter smaller per request. The system prompt shrinks by four fifths to what Bake is and how to work: the model introduces itself as Bake instead of a DeepSeek Harness agent, is told the user sees its tool calls and Markdown replies, and gets one short paragraph of working guidance (follow the surrounding code's conventions, commit or push only when asked, leave changes it did not make alone, keep replies concise and neutral, and report results accurately, including failures and skipped checks). How to use each tool now lives once, in that tool's description, stated as facts where possible, such as which changes `write` and `edit` refuse. Internal names such as "DSH file policy" no longer reach the model, and AGENTS.md files read as instructions to follow rather than optional guidance.
- The model creates a goal only when you ask for one, instead of inferring one from a long request.
- `glob` lists the newest files first, so a result cut off at 100 paths shows recently changed files instead of the oldest ones.
- Claude models on Anthropic Messages routes now receive request images at most 2000 px on each side, so a conversation holding more than 20 images no longer fails every later turn with `many-image requests: 2000 pixels`. The cap depends only on each image, not on how many a request holds, so earlier images stay byte-identical for the prompt cache; existing sessions re-encode oversized images once. A pi-ai route can set its own cap with `requestImageMaxDimension`; other protocols keep the pixel budget alone.
- Claude turns through a proxy such as CLIProxyAPI no longer fail with `Could not parse Anthropic SSE event content_block_delta: Unexpected end of JSON input` when the proxy's keep-alive lands between an event's name and its data. Bake drops the empty event and names the data that follows from its own `type`, so no streamed text is lost. The same happens for OpenAI routes already.
- Each terminal agent now has one automatic compaction engine, its preset's own. The shared engine also checked every agent's context, so history compacted at whichever threshold was lower. It now runs only for `/compact` where a preset has no `/compact` of its own. Agents on the `minimal` preset no longer compact automatically, as that preset describes, and a request that overflows the context window shows the provider's error. `/compact` still works under every preset.
- Skills work again in `standard` and `ptc` sessions: the model sees the list of available skills, and `/skill-name` sends the skill once instead of twice. The terminal profile had also mounted every tool, AGENTS.md, skills, plan mode, goals, and the task list for each agent on top of its preset's own; each preset now provides these alone. `ptc` no longer receives the `workflow` tool its preset leaves out, about 900 tokens a request, and `--preset minimal` is shell-only as intended: one persistent shell and `/compact`, about 4,500 tokens a request lighter. `--preset cordis` starts again instead of waiting forever for its inspection service.
- Closing the terminal (SIGHUP, or closing the console on Windows) now shuts Bake down like Ctrl+C: the session is saved, running commands are stopped, and Bake exits with status 129 instead of dying and leaving commands running.
- Bake starts about 10–17% faster by using Node's module compile cache. Set `NODE_DISABLE_COMPILE_CACHE=1` to turn it off.
- Starting two Bake processes on the same profile at once no longer occasionally fails with "config file must be a top-level array of entries", and two processes writing the profile's `cordis.yml` at once no longer share one temporary file.
- A `.lock` file left by a Bake process that crashed or was killed no longer blocks later settings, credential, and profile writes until you delete it. On Linux and macOS the next writer removes an abandoned lock at once, including one left by an earlier release, while a running Bake of any version still holds its lock. Windows keeps the previous behavior.
- Opening a session that another Bake process has open now says so instead of reporting that it "is already owned by an active write handle". `/resume` keeps the current session and suggests closing the other one or starting a new one with `/new`; `bake --resume <id>` prints one line saying the same and exits with status 75, leaving the terminal untouched. `--profile headless --resume <id>` does the same; with `--json` the refusal is also the stream's `error` event.
- Long sessions now leave evidence when they stall or run short of memory. Bake records sustained event-loop delay and heap use above 85% of Node's limit in `~/.bake/diagnostics/watchdog.*.jsonl`, at most a few lines an hour and never on the terminal or in the model's context. The `bake` command starts Node with `--report-exclude-env --report-exclude-network --diagnostic-dir=<Bake home>/diagnostics`, so a fatal error such as running out of memory also writes Node's diagnostic report there, without environment variables or network details. An installed Windows `bake.cmd` picks this up at the update after this release, or on reinstall. Each session-migration check now runs with at most half of Bake's heap limit.
- Release archives no longer ship group- or world-writable files; nine bundled command scripts, `vendor/cordis/bin.js` among them, were mode 0777. Installed releases on Linux and macOS now use the same hoisted `node_modules` layout as development and CI, so the shipped command resolves modules the way it was tested.
- Tool calls take less room in the terminal. The built-in tools (terminal, read, edit, write, search, web, tasks, and others) draw their own compact rows again: the terminal was looking up how to show a call in the wrong place and fell back to printing the raw arguments. A tool without its own row shows a one-line summary of its arguments, at most 96 columns, instead of a JSON dump, and a long result line is cut at 240 columns. The workflow tool's result shows again; it used to print only its heading. Goal and reminder tools show one-line results, such as `Goal created · 0/8 rounds`, instead of repeating the objective in raw JSON. `ask_user_question` shows its question headings and one answer per line. Subagent, message, and `present` calls show a short title instead of the whole prompt. `ask_user_question` now asks the model for short questions, headings, and option labels.
- The task, subagent, and goal views have a dim grey frame instead of one in the view's colour, and the question box's frame is neutral like the approval and sign-in boxes. The colour stays on the open tab, the pointer, and the question's title.
- You can keep typing while `/compact` runs: Enter queues the prompt on the pending panel, and it runs as its own turn once compaction finishes, fails, or is cancelled, instead of being refused. Compaction now shows in blue with its own spinner, a sheet of dough folded into a block and rolled out again, both for `/compact` and when a turn compacts its context automatically; Enter still steers such a turn. The transcript's "Context compacted" line is blue too.
- Ctrl+J and Alt/Option+Enter start a new line in the prompt in every terminal. Before, the only way to write a multi-line prompt was to paste one, because Shift+Enter sends the prompt in most terminals and Alt+Enter did nothing. Shift+Enter adds a line where the terminal sends it as a distinct key, and the new `/terminal-setup` makes it do so: it binds Shift+Enter in VS Code, Cursor, Windsurf, Windows Terminal, Ghostty, kitty, or Alacritty after showing the change and backing up the file, and prints the steps for WezTerm, iTerm2, Apple Terminal, and remote sessions. The welcome box names the keys once, and `/help` ends with the editing keys. Up and Down move between the lines of a multi-line prompt, and earlier prompts come back only from its first or last line. A prompt taller than the input shows `^` and `v` with how many lines are above and below, and the empty input reads `Ask anything · / commands · @ files`.
- The status line keeps what matters on narrow terminals. It reads `deepseek-v4-flash  think high  ctx ~11% (15.2k/128k)  ⎇ main +2  in 42.3k  out 3.1k  cache hit 81%  ~/bake`, without the `Model:` label and with short lowercase labels, and keeps the same layout when tasks, a goal, and subagents are showing. As it narrows, the token counts in brackets give way first, then the input and output totals, so the cache hit outlasts them; the context percentage never gives way.
- The context reading shows where automatic compaction will start, `ctx ~61% · compacts at 80%` (`▸80%` when narrow), taken from the compaction settings for the model in use. The percentage warms from the normal text colour through yellow and orange to red as the context fills, turning orange about 10 points before compaction and red from 90%.
- The task, goal, and subagent rows read alike: `☐ Tasks 1/4 ━━━─── ▸ current task  Ctrl+T`, `● Goal 3/256  Ctrl+O`, and `↳ Subagents 3 · 2 working  Ctrl+G`, each naming its key at the right edge. The goal keeps its round count however crowded the rows are, and only its dot is coloured.
- Less colour on the screen's frame: the tree lines that connect a step's tool calls are grey, a failed call's name turns red instead, and a healthy cache hit, the thinking level, and the task bar use the normal text colour. The finished-turn line gives the output speed, `✓ Completed 1m 12s · ran 3 · 42 tok/s`, when the turn ran for at least a second and wrote at least 64 tokens; the separate `N tokens · X tok/s` line under each answer is gone.
- Quitting Bake waits for its own background work, such as saving the session and stopping git and update checks, even when the quit comes from a signal. A quit that finishes but leaves something holding the process open now exits after the shutdown grace period instead of hanging.
- A fatal error while Bake runs prints its `dsh:` line at once, before shutdown cleanup, so a slow cleanup can no longer hide why Bake exited.
- `/resume` on a session with no recorded preset says the session must be resumed from the command line with `--preset`, in the interface language, instead of showing an English error.
- The first turn of a session resumed from an earlier release adds one runtime-context message, because the wording of runtime context and approval notices changed.
- Disabling or removing a plugin in `cordis.yml` while it is still loading no longer mounts it anyway, and a plugin that reloads in place no longer keeps a configuration hook from its previous load that could reject the new configuration.

## [0.1.8] - 2026-09-28

## [0.1.2] - 2026-09-25

- Slash commands complete their arguments: `/goal`, `/plan`, and `/permission` offer their choices, `/login` offers sign-in targets, and `/model` offers models.
- Enter on a command that needs input fills it in instead of running it, and its usage line stays visible while you type the arguments.
- An unknown slash command keeps your draft and suggests the nearest command.
- A new session starts on CLIProxyAPI when it is set up and no DeepSeek key is, and the "no credential" notice appears only when no provider is configured.
- `/help` lists commands in columns, and `/help <command>` explains one.
- Usage errors from `/compact`, `/feedback`, `/permission`, and `/plan` show the expected form, with the reason on the next line.

## [0.1.1] - 2026-09-25

- `bake update` installs the newest release in place, and `bake update --check` only reports; any failure leaves the install as it was. Installs of 0.1.0 run the installer once more to get it.
- Releases are signed: the installers and `bake update` refuse a manifest the Bake release key did not sign. Every release is also published on GitHub Releases.
- The status line names a newer release when one is available.
- Installs and updates show a small progress line in interactive terminals; `BAKE_NO_ANIMATION=1` turns it off.
- A header row above the composer shows what the current turn is doing and the active goal.
- Final answers end with a dim tokens-per-second line.
- Shift+Tab cycles the reasoning effort.
- The live area fits the terminal's size, and a long batch of tool calls keeps its heading, folding older calls into a count.
- Tool calls show a `●` heading with a `⎿` result line.
- Models whose streams report empty token usage no longer reset the context meter to 0%.

## [0.1.0]

- Bake is an independent terminal coding agent with a Bun-managed workspace, a Node runtime, and `~/.bake` as its default home.
- A fresh session opens with a welcome block showing the Bake version, a short notice, and example commands.
- `/changelog` shows what changed in the running version.
- The terminal follows the newest line, prints answers as they stream, and merges each action's call and result into one block.
- Tool cards, a task checklist, and a subagent panel sit above the composer.
- Session discovery skips damaged compressed headers instead of hiding healthy sessions.
