# Changelog

Notable changes to Bake. `bake` compiles this file in, and `/changelog` shows its released sections. Each release heading names the version in `[workspace.package]` of `Cargo.toml`.

## [Unreleased]

- **Read a spawned agent's transcript.** Ctrl+X opens the transcript of an agent in the crew panel under the composer, read from its session file and updated as it works: ↑↓ and PgUp/PgDn scroll, ←→ move between agents, and Esc or Ctrl+X closes it. The crew panel's header names the key.
- **Background jobs always report back.** A background job's completion now wakes an idle session unless it ends a chain of three turns each opened by the one before: jobs started side by side, or one after another from the same turn, each wake it. Before, the fourth notice since your last prompt waited silently for the next one, which left a spawned agent waiting on a job forever.
- **Spawned agents' reports arrive whole.** A spawned agent's finished run always wakes the session that started it, as a telecom message does, and its answer is carried up to 16 KiB instead of 4,000 bytes; a longer one says how much was cut and to ask the agent for the rest.
- **Truecolor in more terminals.** Without `COLORTERM`, Bake now recognises terminals that draw 24-bit colour (kitty, Ghostty, WezTerm, Alacritty, foot, iTerm2, VS Code, Windows Terminal) and WSL outside SSH, so tool cards get their boxes there. A set `COLORTERM` still decides.
- **Bake 0.3 is gone.** `DSH_HOME`, `DSH_OFFLINE`, and `DSH_CODEMODE_MAX_WORKERS` are no longer read: the Bake home is `BAKE_HOME`, else `~/.bake`. A 0.3 home's `settings.yaml` and `.credentials.yaml` are no longer imported, so a CLIProxyAPI route, key, default model, or default permission preset saved only there no longer applies; sign in with `/login` or describe the provider in `models.json`. MCP stdio servers now inherit `DSH_*` variables like any other.
- **Installers.** `install.sh` and `install.ps1` no longer recognize or take over a Bake 0.3 command; `--uninstall-links` can no longer restore one taken over before. A `bake` command no Bake installer made is still left alone unless `--replace-command` is given.
- **Download service.** The frozen 0.3 update route (`latest.json`) and its archive redirects are retired with the next deploy.
- **Unknown commands.** A `/word` that names no command or prompt template is refused with the draft kept; the commands that used to say they were planned for a later release now say the same.
- **Releases.** `bake-release prepare <version>` sets the version, lockfiles, and changelog section for a release, and `bake-release publish <version>` tags, creates the GitHub release, signs, uploads, deploys, and checks the live channel in one resumable run (`--dry-run`, `--from <step>`). The release workflow is removed.

## [0.4.8] - 2026-11-14

Bake 0.4.8 draws SVG images and five more chart kinds in `visualize`, sharp where the terminal shows images, and turns the tool on in the interactive terminal by default. Tool cards sit in dim boxes as wide as their content, the status line drops its context bar, `/settings` gains Telecom and Visualize tool, and the prompt and tool texts were audited.

- **More to draw with in `visualize`, and the model can check its drawing.** Five more chart kinds: `stacked` bars, `area`, `scatter`, `pie`, and `heatmap` (up to 24 columns of values). `size: "large"` gives line, area, and scatter plots twenty rows, a taller pie, and an SVG image up to 144 by 32 cells. An SVG image's source may be 128 KiB, four times as much, and may reuse shapes with `<use>` freely: Bake now counts what the copies and markers expand to, at most 20,000 elements, in place of allowing twelve `<use>` elements. The tool's answer warns the model about what it cannot see for itself: text outside the canvas or cut by its edge, labels that overlap, text too small to read, shapes off the canvas, and a transparent background. With `preview: true` the model gets the drawing back, an SVG image as a PNG when it reads images and a diagram as text, so it can fix what is wrong. A long SVG image keeps drawing while it streams, every 4 KiB past 32 KB.
- **SVG images in `visualize`, drawn as they stream.** The model can show an SVG image with `kind: "svg"`. The card draws it in half blocks, two pixels to a cell, and redraws it tag by tag while the model writes it. Once finished and wholly on screen, it is shown sharp where the terminal shows images: Kitty graphics in kitty and Ghostty, iTerm2 images in iTerm2 and WezTerm, and Sixel in Windows Terminal, foot, and mlterm (`BAKE_IMAGES` chooses or turns them off). Bake never loads what an SVG links to, and refuses entity declarations and runaway `<use>` nesting. Text in an image uses the system's fonts.
- **`visualize` on by default, with a setting.** Sessions in the interactive terminal now start with the `visualize` tool; `/settings` has `Visualize tool` under Answers, which saves `"visualize"` in `settings.json` and applies from the next session. Print and RPC runs still leave it opt-in.
- **Tool boxes fit their content.** A tool card's box is as wide as its widest row instead of spanning the screen, with the same gap before its right edge as after its left one, a diff's tinted rows included.
- **No context bar.** The status line reads the context as `ctx ~23% (23k/100k)`, without the five-cell gauge; the share still warms from 60%.
- **Tool cards in dim boxes.** On a truecolor terminal, a tool call with output is drawn in a rounded box with a dim edge (muted red when it failed), the call riding in its top edge, in place of the tinted background. Every call's state mark sits in one column, and its output lines up under the tool's name.
- **Telecom in `/settings`.** `/settings` has an Agent team group with `Telecom`, which saves `"telecom"` in `settings.json` and applies from the next session (`/new`, `/resume`, or a restart); the row says when `BAKE_TELECOM` overrides it. `/telecom` and `/spawn` with telecom off say where to turn it on, and a startup tip names it.
- **Prompt and tool text audit.** An interactive or RPC session's prompt now says someone can answer; it said every run was non-interactive, even with `ask_user` declared. When an `edit` or `write` fails, the commands sent after it in the same response are answered with an error instead of run, so a check cannot report on a file the change never reached; later edits and reads still run. `edit` contributes one guideline where it had four, the `bash` rule names `grep` for machines without `rg`, `ask_user` and the run rule agree on when to ask, and a session with both `subagents` and `telecom` is told which way of delegating is for what. The `schedule_*`, `run_in_background`, and MCP resource descriptions are plainer. A paired evaluation on three models found no change in passes, requests, or tokens beyond noise; a narrower `codemode` guideline was tried and withdrawn after it cost GPT-6.1 Terra 31% more requests.

## [0.4.7] - 2026-11-14

Bake 0.4.7 adds native Windows x64 releases, opt-in agent teams over telecom with headless spawned agents and a crew panel, lets the model ask you questions with `ask_user`, and makes tool cards clearer. It is signed with a new release key, so 0.4.6 and earlier installs reinstall once. Bake 0.4.6 was the last Linux arm64 release.

- **Windows x64 releases.** Bake now publishes a native Windows x64 build: `irm https://bake.justar.dev/install.ps1 | iex` installs it, and `bake update` updates it. Windows has no qualified sandbox yet, so commands under `read-only` and `workspace-write` are refused there; use `danger-full-access`. Bake 0.4.6 was the last Linux arm64 release.
- **A new release signing key.** This release is signed with a new native release key. Bake 0.4.6 and earlier cannot verify it, so `bake update` refuses it there: reinstall once with `curl -fsSL https://bake.justar.dev/install.sh | sh`, and updates work from then on.
- **Agent teams, opt-in.** With `"telecom": true` in `settings.json`, or `BAKE_TELECOM=on` for a run, the Bake sessions working in one repository form a team: each takes a callsign (`alpha`, `bravo`, ...), and the model can see the board and message, ask, and answer the others with the `telecom` tool. `/telecom` shows the board, and `/telecom msg <agent> <text>` messages one as you. Incoming messages show in the transcript as `← bravo: ...`. Telecom is local to your machine and needs Unix sockets, so it does not start on Windows. See `bake docs team`.
- **Spawned agents.** A session in the team can start headless Bake agents, with `/spawn <task>` or the model's `spawn_agent`. Each runs as a separate `bake --mode rpc` process with your sandbox and approvals, joins the team as `alpha-1`, `alpha-2`, ..., and reports back each time it finishes a run. A crew panel above the composer shows each agent: a spinner and its current tool while it works, `?` while it waits for you, `+` when idle, and `x` with the reason when it failed. Its questions and approvals come to you.
- **The model can ask you questions.** In the terminal and over RPC, the model's `ask_user` tool puts one to four questions with options to you, as lists in the terminal, or as `select` and `input` requests over RPC, when a decision is yours to make. `-t -ask_user` or `"defaultTools": ["-ask_user"]` removes it.
- **Clearer tool cards.** A call with nothing after its name drops the colon (`Jobs`, `codemode`), tool names read as words (`Task document`, `Schedule`, `MCP resource`), the task, schedule, MCP resource, telecom, spawn, and question tools lead with what they act on, and a JSON value a `codemode` script returns reads a member a line.

## [0.4.6] - 2026-11-12

Bake 0.4.6 starts new sessions with full access, as Pi does, adds `/permission` and more answers to an approval, draws Mermaid diagrams in answers, adds an opt-in `visualize` tool for charts, tables, and diagrams drawn while the model writes them, and gives the status line a state dot, a context gauge, and one palette. Linux remains its only released platform.

- **New sessions have full access, as in Pi.** A new session now starts with the `danger-full-access` preset: tools change any file you can, `bash` runs outside the sandbox, and nothing asks. Sessions you resume keep the permission they had. To keep the sandbox, set `"permission": { "defaultPreset": "workspace-write" }` in `settings.json` or run `bake --permission workspace-write`; a `defaultPreset` already saved in `settings.json` still applies. Under `never`, a Claude Code hook's `ask` is denied without asking; choose `workspace-write` to be asked.
- **`/permission` switches the session.** `/permission` lists the presets with their sandbox and approval policy and switches this session; Ctrl+S also saves the default for new sessions, and `/permission workspace-write` switches at once. The session file keeps the switch, and the next prompt tells the model.
- **More answers to an approval.** The approval panel says what the tool wants in words, such as `bash wants to run outside the sandbox`, shows the command or path first with the model's justification under it, and offers four choices, picked with ↑↓ or a key and confirmed with Enter: allow once (`y`), allow the same tool the same access for the rest of the session (`a`), switch the session to full access (`f`), or deny (`n`) with an optional note that the model reads with the refusal. Esc still cancels. A session grant is kept in the session file, so a resumed session does not ask again.
- **A status line that shows the session's state at a glance.** A dot leads the screen's last row: `○` idle, an orange `●` while a turn or compaction runs, a yellow `◆` while Bake waits on you for an approval or a model, and a red `!` after a failed turn, until the next prompt. A five-cell gauge before the context's share fills green and turns yellow, orange, and red as the context nears its limit; the prompt cache's share, when shown, is green when most of the prompt came from the cache and warms as less did; and a detached branch is yellow. The model name is in the terminal's normal colour and the rest stays dim. The colours come from one small palette: warm colours mean attention, and the thinking levels moved to cool ones, so `xhigh` is now violet rather than orange. Under `NO_COLOR` each state keeps its own glyph.
- Text copied from the transcript no longer carries an invisible byte-order mark (U+FEFF) from the output it was copied from, such as a CI log; it pasted as a stray character.
- **Mermaid diagrams in answers.** As in Pi 1.5, a ```` ```mermaid ```` code block in an answer is drawn as a diagram in box-drawing characters: flowcharts, sequence diagrams, and flat state, class, and entity-relationship diagrams, in the answer's colours, and in ASCII under the classic frame. A diagram too wide for the screen, or one using Mermaid that Bake cannot draw, shows its source as before, with a dim line saying why. While an answer streams, a diagram is drawn as far as its finished lines go. `markdown.mermaid` in `settings.json`, also under `/settings`, takes Pi's values: `streaming` (the default), `final` to draw a diagram once its code block is complete, or `off`. The model sees no change. The renderer is a port of OpenAI Codex's `codex-mermaid` (Apache-2.0).
- **Charts, tables, and diagrams in the conversation, off by default.** The new `visualize` tool lets the model show you a bar chart, a line chart, a table, or a Mermaid diagram, drawn as text while the model is still writing it: bars in eighth-of-a-cell steps ending in their values, a braille line plot ten rows high with its axis and labels, tables in box-drawing borders with numbers aligned right, and diagrams as an answer's Mermaid code block draws them, from the longest run of finished lines while they arrive. Several series get colours and a legend; with `NO_COLOR` they are told apart by glyph, and the classic frame draws in ASCII. The drawing reflows when the window is resized and is drawn again when a session is resumed. A diagram is drawn whatever `markdown.mermaid` says, since the model asked to show it. The model gets back one line saying what you were shown, never the drawing, and a call with a mistake, such as a row with the wrong number of values or Mermaid Bake cannot draw, fails with what to fix, naming the diagram's line or the limit it passes. Turn it on with `bake -t +visualize` or `"defaultTools": ["+visualize"]` (`bake docs cli`); it stays off by default until its effect on models has been measured.

## [0.4.5] - 2026-11-12

Bake 0.4.5 gives each tool its own card with previews that Ctrl+O expands, shows subagents and background shells as one tasks list, puts what a turn is doing under its latest output and the status line on the screen's last row, and takes Pi 1.5.2's fixes to the file tools, bash timeouts, images, branch summaries, and provider requests. Linux remains its only released platform.

- **One place for work beside the conversation.** Subagents and background shells show together as tasks under the composer. One quiet row says how many run, how many failed or finished, and names the newest running one, a shell with its command and time; once everything has finished it stays, dim, while the session keeps them. Ctrl+G, or ↓ past the draft, opens one list of both, subagents then shells, with one selection across them and the selected task's last line of output or last words under it. Enter opens a shell's output or a subagent's details, `x` stops it, and Esc steps back one level. Marks match the conversation's: a running task shows a running call's mark, held steady, and done, failed, and stopped look alike in both places. `bake preview` shows sample tasks.
- **Cards for more tools.** A write shows the first lines it writes, numbered and coloured, a search its matches under their files, a listing its first entries, and a web search its results by title and site. A read or a fetch says what came back, such as `40 lines` or `HTTP 200 · 12.4 KB`, without repeating it, and an MCP tool's card names its server and tool, `github · create_issue`, with its arguments as quiet `key value` pairs.
- **Previews that keep what matters.** A failed call keeps the last lines of its output, where the error is. A run of blank lines reads as one, and a reply that is one JSON value, as many MCP tools send, is laid out a member a line and coloured. A card counts its lines only when its preview leaves some out, a long line in an edit's diff is cut to a few rows, and a call whose whole output was saved to a file names that file under its card.
- **Ctrl+O shows every call whole.** Every line, the whole diff, every match and entry, a read's content numbered from the line it started at and coloured by its language, and a fetch's text, up to 400 rows a card; Ctrl+O again returns to the previews. It works while a turn runs and while reading back, and keeps your place. Until it is first used, the count of the newest card that has one names it: `⋯ 26 more lines · Ctrl+O`. Counts of one read `1 line`, as in `↓ 1 line below` while reading back.
- **What a turn is doing sits under its latest output, and names the work.** While a turn or a compaction runs, one row under the conversation's newest line shows its word, what the latest call is doing, such as `reading transcript.rs`, `running cargo test`, or `searching ctx.effect`, with `+2` when two more run beside it, in place of `running bash`, and its time; the row moves down as the output grows, and scrolled up to read, it stays on the last line above the composer. How the turn ended stays under the newest output until the next prompt, and scrolls out of sight with it. The status line, with the model, its thinking level, the context, and the working directory, is now the screen's last row, under the tasks, and the row above the composer appears only while the tasks list or one task is open, to name it and its keys.
- **Prompt-template arguments keep apostrophes.** `/review why doesn't the user's cache work` no longer drops its apostrophes or shifts `$1` and `$2`: as in Pi 1.5.2, a quote starts quoting only at the beginning of an argument, a quote with no closing match is kept as text, `\"` inside `"..."` (or `\'` inside `'...'`) is a literal quote, and `""` or `''` is an empty argument.
- **The thinking level survives `/tree`.** After `/tree` returns to a point recorded with another thinking level, the next prompt records the level in use there, so resuming the session restores it rather than the old one.
- **Image-only messages leave the queue.** A steering or follow-up message with images and no text no longer stays listed as queued after the model has received it.
- **Sessions whose project is gone are refused in scripts.** `bake -p`, `--output-format`, `--mode json`, and `--mode rpc` refuse a session whose saved working directory no longer exists, say which directory, and exit 1 before anything is sent or written. `--fork` copies it into the current directory.
- **Fewer wasted retries.** A Z.ai usage limit (error code 1308) is no longer retried, a gateway stream cut short after the reply began is retried, and LiteLLM's "Context Window exceeded" starts compaction, as in Pi 1.5.2.
- **Exported pages from Pi 1.5.2.** `/share` and `bake --export` pages show the session's system prompt and tools where the session recorded them, open sessions too deep for the old page, and count each reply's recorded cost.
- **`grep` globs are relative to the searched path.** As in Pi 1.5.2, `grep` with `path: "src"` and `glob: "sub/*.rs"` searches `src/sub`, a leading `./` is ignored, and a glob without `/` still matches file names at any depth.
- **`find` and `ls` limits from Pi 1.5.2.** A limit below 1 means 1 and a fractional limit is rounded down, and `find` says its result limit was reached only when more files exist.
- **Resized photos are sent as JPEG.** When `read` shrinks an image, it sends the smaller of PNG and JPEG, so a large photo no longer reaches the model as a bigger PNG; screenshots and other flat images stay PNG.
- **Cut lines keep whole characters.** `grep`'s long lines and the tool results quoted in compaction and branch summaries are cut before a character such as an emoji rather than through it.
- **Clearer bash timeouts.** Outside the sandbox, when a command's shell has exited but a background process it started keeps writing until the timeout, `bash` says so, with the shell's exit code and when it exited. In the Linux sandbox, such processes end with the shell.
- **Branch summaries think.** The summary `/tree` writes of the branch it leaves asks a reasoning model at the session's thinking level, and summarizes the branch as the model's context last showed it, with context edits such as `contextMasking`'s placeholders applied.
- **Room for the answer near the context limit.** The output allowance keeps 15% of the estimated input, at least 4,096 tokens, free below the model's context window, so providers that count tokens more generously, such as OpenRouter, no longer refuse a long conversation; when that would leave less than 32,768 tokens for the answer, only the 4,096 are kept and the answer may use up to 32,768.
- **Anthropic models get MCP tools' shared definitions.** A tool schema's `$defs` or `definitions` is no longer dropped when Bake sends it to an Anthropic model, so its references resolve.
- **Codemode prints `NaN` and `Infinity`.** `console.log`, `text()`, and thrown values show `NaN`, `Infinity`, and `-Infinity` instead of `null`; inside objects and arrays they are still JSON's `null`.

## [0.4.4] - 2026-10-26

Bake 0.4.4 is easier to run from scripts and other agents, groups `/settings` by the command each setting shapes, writes compaction summaries from the prompt cache, shows compaction as it runs, and can show token and cache usage in the status line. Linux remains its only released platform.

- **Easier to run from scripts and other agents.** `bake -p --output-format json` prints one JSON object when the run ends: the answer, how the run ended (`success`, `error`, `truncated`, `budget_exhausted`, or `cancelled`), the session id and file to continue with `--session`, and the run's turns, model calls, time, tokens, and cost. `--output-format stream-json` prints every event and then that object, and `text` prints the answer, as Claude Code's and Gemini CLI's `--output-format` do. A startup failure, such as a model that does not exist, prints a result object too. `bake docs headless` describes it.
- **No more hanging on an open standard input.** Beside a prompt argument, piped standard input that sends nothing within a second is left unread with a warning, so a caller that starts `bake -p "…"` with standard input open no longer waits forever. A bare `-` waits for piped input however long it takes; with no prompt argument, standard input is still read to its end.
- **Cut-off answers fail.** As in Pi 1.4.0, print mode prints an answer cut off at the model's output limit, then says so on standard error and exits 1.
- **`/settings` is grouped.** Its rows sit under the command or part of the screen they shape: `Compaction · /compact`, `Prompts sent during a turn`, `Branches · /tree`, and `Status line`. Each shows its value and, while selected, what it does. A change applies at once and returns to the list, so several settings can be changed in one visit; Esc closes it and lists the changes.
- **Choose when auto-compaction starts.** `Compact at` in `/settings`, or `compaction.thresholdPercent` in `settings.json`, starts automatic compaction once the context passes a share of the model's window, such as 80%, instead of only when the reserve is reached. `Keep recent` sets how much recent conversation a compaction keeps, and `Branch summary` whether `/tree` asks to summarize the branch it leaves.
- **Cached summaries, on by default.** A compaction repeats the conversation the provider has cached and asks for the summary as the next turn, so most of the request is read from the prompt cache and the summary sees every tool result in full rather than its first 2,000 characters. Bake sends it only when the request repeats the last one; otherwise the usual summary runs, and the compaction says why. Turn it off with `Cached summary` in `/settings` (`compaction.cachedSummary: false`). Adapted from pi-cached-compaction 0.2.0.
- **Clearer compaction.** While history is compacted, the bar says `Compacting history…` in blue with what it is doing (`reading 182.3k tokens from the cache`, `summarizing 182.3k tokens`) and its time, the composer says Esc cancels it, and an automatic compaction hands the bar back to the turn when it ends. A ruled mark in the transcript shows the context before and after, `Compacted · 182.3k → 21.1k tokens`, with how much the cache served or why it was not used; resumed sessions mark earlier compactions the same way. `--mode json` reports each summary request as a `compaction_summary` event.
- **Token and cache readings in the status line.** `Status line` in `/settings` (`statusLine.tokens` and `statusLine.cache`) adds the session's input and output tokens, `↑12k ↓3.4k`, and its prompt cache, `cache 99% (R180k W2k)`: the share of the latest prompt read from the cache, then the cache's reads and writes, as Pi's footer counts them.
- **One set of file lists per summary.** A summary whose model copied the previous summary's read and modified file lists no longer ends with them twice.

## [0.4.3] - 2026-10-26

Bake 0.4.3 opens with a clearer header, says when an update is published, shows its state in the terminal title, Ghostty, and Herdr, and streams long tool calls faster. Linux remains its only released platform.

- **A clearer opening screen.** An interactive session opens with a header in place of the bare "Session saved to" note: the Bake wordmark in a warm gradient on truecolor terminals, the version, the working directory, the session in plain words (`new`, or `resumed · 6 prompts · 2h ago`), and tags for the sandbox mode, approval policy, and offline mode. `/session` still shows the session file.
- **Tips in place of the scroll hint.** The scroll keys no longer sit above the status line. In fullscreen, the header shows a dim `tip` row for about 25 seconds after startup, or until the first turn: the scroll keys first, then two other tips that change from launch to launch.
- **Update notice.** On a native install, an interactive session says, under an `update` tag, when a newer release is published and that `bake update` installs it. The check runs in the background at most once a day, remembers its answer in `update-check.json` in the Bake home, and is left out by `--offline`.
- **Terminal status.** The window title names the session and directory, `bake - <name> - <directory>`, and starts with `◐` while a turn runs or `?` while an approval waits; quitting restores the previous title where the terminal keeps it. In Ghostty, a progress bar moves while a turn runs, pauses while an approval waits, and shows an error after a failed turn. A desktop notification says when a turn finishes or a tool needs approval while the window or tab is out of focus. The `terminal.showTerminalProgress` and `terminal.notifications` settings turn either on or off in any terminal.
- **Richer Herdr status.** A `blocked` report says what it waits for, such as `bash needs approval`. A dialog opened by a command such as `/model` no longer reports `blocked`. Herdr's agent sidebar can show `$model`, `$thinking`, `$context`, `$session`, and `$activity`, which quitting clears.
- **Faster streaming of long tool calls and answers.** A tool call's arguments are no longer parsed again from the start for every streamed piece, so a file of about 150 KB that a model writes costs about 1 second of CPU instead of 11. Long answers stream with fewer copies, and `--mode json` and RPC output no longer build each update's discarded snapshot.

## [0.4.2] - 2026-10-25

Bake 0.4.2 is the first release since 0.4.0 that the installers and `bake update` deliver: it carries every change of 0.4.1, which was tagged in source only.

- **Updates are published again.** `curl -fsSL https://bake.justar.dev/install.sh | sh` and `bake update` install 0.4.2 on Linux x64 and arm64.
- **From 0.4.1:** the shells' and agents' lists open under the input bar with the conversation kept in view, Shift+Tab cycles the thinking level, `/model` is grouped by provider and lab, `/login` is clearer, answers render as Markdown, long bash commands and output are kept to a few rows, Ghostty's Kitty keyboard reporting and Herdr reporting are supported, and a `defaultTools` list of only `+`/`-` entries keeps code mode, the job tools, and the web tools on.
- **Release tooling:** releases are built, checked, signed, and published by `bake-release`, a Rust tool that checks every step with the updater's own code, in place of the retired Bun scripts. The archives keep the same layout and license bundle.

## [0.4.1] - 2026-10-25

Bake 0.4.1 polishes the terminal and keeps Linux as its only released platform.

- **Lists open under the input.** The background shells' and agents' lists, one shell's output, and a subagent's details open in a panel under the input bar. The conversation stays in view above it, the selection stays visible on short terminals, and rows out of view are counted.
- **Shift+Tab cycles the thinking level** of the session's model.
- **`/model` is grouped** by provider and then by lab, in natural order, with each model's id beside its name.
- **Clearer `/login`:** step titles, the default address as a placeholder that Enter accepts, hints, and a working indicator while the key is checked.
- **Easier-to-read transcript:** answers are drawn as Markdown with colour, long bash commands and output keep a few rows with a `+N` count, a running call shows its newest output, and code mode is labelled like the other tools.
- **Terminals:** Ghostty's Kitty keyboard reporting is supported with balanced cleanup, and Bake reports its activity and the command that restores a saved session to Herdr.
- **Settings:** a `defaultTools` list of only `+` and `-` entries now changes Bake's default tool set, so code mode, the job tools, and the web tools stay on.
- **Windows (not yet released):** a killed process tree whose short children reused an ended child's process id now finishes settling instead of waiting forever.
- **Repository:** the Cargo workspace is at the repository root, and the retired TypeScript agent, Bun tooling, distribution automation, eval runners, and archived evidence are removed. This release is tagged in source only; installers and `bake update` stay on 0.4.0.

## [0.4.0] - 2026-10-22

Bake 0.4.0 is a new native agent, `bake`, written in Rust. This first release is for Linux.

- **Linux first.** Releases are published for Linux x86_64 and arm64 with glibc 2.34 or newer. macOS and Windows support is coming in a later 0.4 release; until then the installers stop on those platforms before they download anything, and on Windows you can install Bake inside WSL.
- **Install.** `curl -fsSL https://bake.justar.dev/install.sh | sh` installs `bake` into `~/.local/share/bake-native` and links it into `~/.local/bin`; it needs no Node or Bun.
- **The Bake home.** `bake` keeps its settings, credentials, and sessions in `~/.bake` (`BAKE_HOME`). Sessions are saved in pi's session format.
- **What it does:** interactive sessions, fullscreen or inline, where you can steer or stop a turn; model, thinking, session, tree, fork, compaction, and settings commands; `/login` for a CLIProxyAPI account and `models.json` for any OpenAI- or Anthropic-compatible provider; sandboxed bash, file, search, web, and code-mode tools under permission presets and approvals; background shells, and opt-in subagents and reminders; `AGENTS.md` context files, skills, prompt templates, MCP servers, command hooks, and Wasm plugins that can veto tool calls; print, JSON, and RPC modes; and `bake update` with `--rollback`. `bake docs` describes each.
- **Not in 0.4.0:** goals and the task router, MCP OAuth, MCP resource subscriptions and prompts, and further slash commands come in later releases.
