# Changelog

Notable changes to Bake. `/changelog` in the terminal prints the section for the running version, so each release heading must match the root `package.json` version.

## [Unreleased]

- Development: the opt-in Rust preview splits its pure view into `bake-tui-view` and frames the composer in a rounded box with its hints on the edges. It adds a sample transcript with calls, diffs, and a code-mode script, a scrollbar, wheel scrolling, mouse selection and copy, readline editing with a yank ring, prompt recall, collapsed pastes, staged images, a slash-command menu over a sample catalog, and a double Ctrl+C to quit. It still runs no model or tools.
- Development: typing `@` in the opt-in Rust preview opens a file menu over the working directory's paths, found and ranked as the TypeScript TUI finds them; Tab puts the selected path into the draft. Only paths are listed, and the preview still sends nothing to a model.
- Development: Enter in the opt-in Rust preview sends the draft through a runtime port to a scripted fixture, which streams one fixed turn into the transcript. A prompt sent while that turn runs joins it as a steer and is listed under `Pending input` until it does or Alt+↑ sends it at once; Esc interrupts the turn. No model or tool runs, and the answer says so.
- Development: the opt-in Rust preview restores Session logs that offload images or carry known event types marked `ignorable`, such as a routed subagent's routing decision, in plain and Zstd restoration and `bake-rs session inspect`, instead of refusing them as native limits. Its request derivation refuses `image/offload` and an ignorable tool update as the TypeScript test helper does. Other native limits remain.
- Development: the opt-in Rust preview adds `bake-rs session inspect` to read an explicitly named current-format plain or Zstd Session log and print its header, counts, and recovery metadata as JSON. Both input and decoded data have caller-supplied limits; the command leaves the file unchanged.

- Shell change reports detect same-size edits made within Git's timestamp precision and show the bytes present before the command, including files that were already dirty.
- Closing a terminal flushes the session and stops managed tools even when a terminal I/O error arrives before `SIGHUP`; that error no longer races shutdown through the fatal-exception handler.
- Core workspace packages use `bake-<name>` names, including `bake-agent`, `bake-session`, and `bake-tools`. Custom plugins and profile rows that import these packages must use the new names; the core package README lists all eight. The workspace generators, dependency graphs, license checks, and terminal build support both Bake and retained upstream package names.
- Internal workspace libraries, the 48 packages no profile loads by name, use `bake-<name>` names as well, for example `bake-fs`, `bake-session-format`, `bake-shell`, and `bake-util-values`. Custom plugins that import them must use the new names; plugin and bundle packages keep their `@deepseek-ai/dsh-<name>` names for now. Session logs, tool text, and other model-visible output are unchanged.
- Plugin and bundle packages use `bake-<name>` names too, completing the rename of every runtime package under `packages/`: the bundles are `bake-base`, `bake-headless`, and `bake-desktop`, and plugins include `bake-llm-pi-ai`, `bake-tool-bash`, and `bake-mcp-client`. Existing installs keep working. On launch, a profile whose `package.json` still lists `@deepseek-ai/dsh-*` bundles is rewritten once to the new names, with the old file kept as `package.json.bak` and one line naming the renames. A `cordis.patch.yml` or `--patch` row that names an old package loads the new one and prints one deprecation warning naming it. An out-of-tree plugin that imports an old package name, or a subpath of one, gets the renamed package's module. These aliases cover every renamed package, including the core packages and internal libraries above; they are deprecated and will be removed in a later release. Session logs, tool text, and other model-visible output are unchanged.
- The launcher command is `bake`: the CLI package is `bake-cli` (the root workspace already owns the name `bake`), and the terminal app packages are `bake-tui-app`, `bake-tui-ui`, and `bake-tui-harness`. The package still installs `dsh` as a second bin for the same launcher, and release installs add a `dsh` link (`dsh.cmd` on Windows) beside `bake`, so Bake Desktop's `dsh --profile desktop` and existing scripts keep working. `bake update` adds the link to an earlier install, and an existing `dsh` command or link to another install is left in place on both Unix and Windows. Launcher and app help name `bake`; stderr diagnostics keep their `dsh:` prefix. Profiles and imports that name `@deepseek-ai/dsh` or `@dsh-tui/*` resolve to the new packages with the same deprecation aliases.
- Product environment variables use `BAKE_*` names, for example `BAKE_HOME`, `BAKE_PERMISSION_MODE`, `BAKE_TELEMETRY_DISABLED`, and `BAKE_TOOLS_MODE`. Each `DSH_*` name still works when its `BAKE_*` name is unset or blank, an opt-out such as `TELEMETRY_DISABLED` takes effect under either name, and the release launchers set both homes. Model shell commands receive every session fact under both names, for example `DSH_SESSION_ID` and `BAKE_SESSION_ID`, and no longer inherit an outer Bake's `BAKE_*` session facts from the launching environment; `BAKE_*` settings such as `BAKE_NO_UPDATE_CHECK` still reach child processes.
- Profile manifests list their bundles under `bake.profile.bundles`, and new profiles are named `bake-profile-<name>`. On launch, a profile that still uses `dsh.profile` gains a `bake.profile` with the new bundle names, written under the same lock as `bake plugin` and with the old file kept as `package.json.bak`. The `dsh.profile` block stays as it was, so after `bake update --rollback` an earlier release still boots the profile with the bundles it last saw.
- The agent-loop eval measures the system prompt Bake ships. Its overlay had replaced the headless `system-prompt` config, so every earlier record's prompts opened with the `powered by DeepSeek Harness` line and lacked the working-directory line; each arm now keeps its own headless config with its standard-preset persona, and a run stops if a rendered prompt differs. `EVAL_ROSTER=tui` runs the terminal's tool configs, an opt-in `extended` scenario set covers large files, exploration, chained and noisy failures, background checks, `AGENTS.md`, ambiguous edits, and compaction, and records add loop-shape metrics and a requests regression check.
- Development: model-surface snapshots pin the system prompt, context messages, and tool declarations that the shipped `headless` and `desktop` profiles and each terminal preset send on their first model request, so a change to what the model sees shows up as a reviewed diff. The shared helpers live in `bake-loader-smoke`. Bake's behavior and model-visible text are unchanged.

## [0.3.8] - 2026-10-05

- A `bash` or `pwsh` call's command is coloured as shell or PowerShell, on the call's head and on any lines under it, so a multi-line command such as `python3 -c "…"` reads apart from the output that follows. A failed call in a step gives up the colour so its head reads wholly red.
- In a step of several calls, a call that finished cleanly under the step's own icon no longer repeats that icon past its branch; running, failed, and other kinds of call keep theirs. The cell stays blank, so names do not shift as calls finish.
- Fullscreen's hint row sits at the right edge while following output, apart from the transcript, with each key at full brightness and what it does dimmed.
- The agent no longer holds its turn open waiting on a background job. A `job_output` read that finds the job still running tells the model to end its turn when nothing else needs doing, because the job's completion notice starts the next one, and a single `wait` lasts at most 60 seconds instead of 10 minutes (`maxWaitTimeoutMs`). The terminal goes idle with the job in its Background row instead of spinning for as long as the job runs. The guidance is left out when no completion would reopen the turn: under `completionDelivery: quiet`, or once the owner's consecutive wakes are spent.
- `dsh headless` waits for the background jobs its agent still owns, and for the turns their completions open, before it reports and exits, so a turn that ends while its job runs no longer loses that job. The wait lasts at most 10 minutes (`jobWaitMs`, 0 to not wait), so a job that never ends, such as a dev server, does not hang the run. Past the limit the run writes a `dsh: warning:` line, reports, and stops the jobs.
- Fullscreen selects and copies text with the mouse. Drag across the transcript to select it, double-click a word (a path or hyphenated name whole), or triple-click a row; the selection is drawn in reverse video and copied on release, each row trimmed at its end, and the hint row says `Copied` or `Copy failed`. A drag held on the top or bottom row scrolls on, Escape clears the selection, and the selection stays on its text while output arrives. Bake copies with `pbcopy`, `clip`, `wl-copy`, `xclip`, or `xsel`, and through the terminal with OSC 52 over SSH, under Windows Terminal in WSL, or when no tool works. Shift-drag, or Option-drag on macOS, still selects with the terminal itself.

## [0.3.7] - 2026-10-04

- Settings, credentials, and profile files are synced to disk when Bake saves them. On some filesystems, a crash or power loss right after a save could leave `settings.yaml` or `.credentials.yaml` empty, which Bake then read as no settings or no saved logins, and the next save made the loss permanent. A save now reaches the disk before it replaces the old file, so a crash leaves either the old or the new file whole.
- `bake --help`, a mistyped option such as `bake tui --bogus`, and Ctrl+C or SIGTERM in the first moments of a launch end in about 0.4 s instead of about 5.3 s. Shutdown waited for a configuration reload that could start only once the terminal was up, and the terminal runner waited for its own teardown, so each of these exits lasted until the launcher's 5-second forced exit. Startup also no longer reapplies the `cordis.patch.yml` files it has just loaded.
- An unhandled promise rejection after startup no longer ends the session with status 1. Bake appends the error's name, message, and stack to an owner-only `rejections.<stamp>.<pid>.jsonl` file under `<Bake home>/diagnostics/` and logs it. The terminal shows `Internal error: <error> · the session continues · details in <file>` on its notice line, and `dsh headless` writes one `dsh: warning:` line to stderr. Each distinct error is shown once, and at most five a minute. A rejection during shutdown is recorded the same way and leaves the exit status alone. During startup an unhandled rejection still fails the launch, and an uncaught exception is still fatal at any time.
- `bake update` checks that a downloaded release launches before switching to it. Instead of only asking the new command for its version, it runs the release's own `--self-check`, which loads the shipped `tui` and `headless` profiles, the agent presets' plugins, and the terminal's runner modules as a launch does, in a private temporary home it removes afterwards, with no TTY, network, or model key, within 60 seconds. A release that would not start, as Bake 0.3.5 on Windows did, is refused, and the message after `the current install is unchanged:` now names what failed to load. `release:pack` runs the same check on every archive before it ships.
- `bake update --rollback` returns the install to the newest release still installed that is older than the current one: right after an update, the release it replaced. It takes the update's lock, runs the same launch check on that release, says which versions it moved between, and leaves `current` where it was on any failure; with no older release installed it says there is nothing to roll back to and exits 1.
- The input caret is a reverse-video cell over the character it stands before, instead of a `▌` inserted into the text, so moving it with ←/→ no longer shifts every character after it by a column. It keeps its reverse video under `NO_COLOR`, as do selected rows, since reverse video is not colour. The sign-in, question, and picker fields draw it the same way.
- The input edits by word and line, as readline and pi do: Ctrl+←/→, Alt+←/→, and Alt+B/F move a word, stopping at the dots and slashes of a path; Ctrl+W and Alt+Backspace delete the word before the caret and Alt+D the word after it; Ctrl+U and Ctrl+K delete to the line's start and end; Ctrl+Y pastes back what they deleted and Alt+Y then swaps in an earlier deletion; Ctrl+- (or Ctrl+_ or Ctrl+/) undoes, a whole word at a time. Ctrl+B/F move a character and Ctrl+D deletes forward. A masked sign-in field moves and deletes its whole line at once, so word steps reveal nothing about a secret, and an image placeholder deleted this way unstages its image as Backspace does.
- Home and End in a wrapped draft go to the start or end of the row the caret is on, and pressed again to the start or end of the line; Ctrl+A and Ctrl+E still go to the line's directly. In fullscreen, clicking the draft puts the caret there.
- Fullscreen (`--screen fullscreen`) jumps between turns: Ctrl+↑/↓, or Ctrl+Shift+↑/↓ where the system takes Ctrl+↑, brings the previous or next prompt you sent to the top of the transcript. Past the first prompt it reaches the beginning, and past the last it follows output again. The hint row above the input names the keys.
- Fullscreen PgUp/PgDn move a page less four rows of overlap instead of half a page. A mouse-wheel notch on its own scrolls one row instead of three, a fast spin up to six rows a notch, and Alt five times as far. A local macOS terminal, which accelerates the wheel itself, scrolls one row a report.
- Fullscreen turns the terminal's autowrap off while it holds the screen, so a row the terminal draws wider than Bake measured, such as one with a character whose width they disagree on, is clipped at the right edge instead of pushing every row below it down and scrolling the screen. Leaving fullscreen, or handing the terminal to an external editor, turns autowrap back on.

## [0.3.6] - 2026-10-04

- Bake 0.3.5 on Windows starts again. The terminal imported the compaction settings package, which the Windows release did not install for it, so `bake` exited at once with status 1 and printed nothing; Linux and macOS installs found the package by chance. The release now checks that every package the terminal loads is declared and resolves in the platform's installed layout before it ships.
- A terminal that cannot start says why instead of exiting silently: a runner module that fails to load prints `dsh: could not load the terminal: <reason>`, and `bake` with piped input prints that it needs an interactive terminal.

## [0.3.5] - 2026-10-04

- Compaction settings reach the engine that compacts a session. Every shipped preset that compacts runs its own engine beside the host's, and a `compaction-basic` setting reached only the host's, which the terminal keeps manual-only, so a saved threshold or retention never moved when the conversation compacted. Every engine now follows the one section, and the status line's compaction mark moves with it.
- `/settings` has a Compaction tab after Agent: automatic compaction on or off, Compact at and Keep recent as a percent of the context window or a token count (`75%`, `150k`), the summary model from the `/model` catalog or the session's own, the summary length limit, and per-model rules as JSON. Choosing one form of a threshold or retention replaces the other, and Keep recent must stay below Compact at. `auto: false` in the `compaction-basic` settings section switches automatic compaction and overflow recovery off; `/compact` still works.
- Tool calls in a step batch keep their own state icon past the tree, so a step with a running subagent and a finished one shows both. The step head counts the calls still running (`running subagent +2`), and spawned subagents, sent messages, and loaded skills read as such in the verb column.
- The subagents row and its sheet (Ctrl+G) mark each child's outcome with its own glyph and colour (running, waiting, done, failed, stopped), count failures in red, align names in one column, and hang a selected child's details from a tree stem.
- A shell command run in the background is marked `◌` with a `background` tag, a row closes it in the transcript when it finishes (green, red on failure or a nonzero exit, amber when stopped), and a `Background` row under the input names how many run and the newest one while any do.
- A code-mode script draws the calls it makes as a step draws its calls: on a tree under the script, each with its own state dot that blinks while the call runs. Its head counts the calls and, once it ends, the failed ones (`12 calls · 1 failed`). A call that succeeded folds to one row with its size, a failed one keeps its error, and a printed script keeps its first and last two calls and up to three failures, with `+N more calls` for the rest, so a script that loops over many files no longer floods the transcript. A failed script's result is labelled `Script error`.
- `/settings` says what each setting does in a help row under the list, which also names the default a changed setting replaced. Changed settings, and sections holding any, are marked `•`; a value list is titled by its setting and shows `Current · Default` when the value in force is the default. A long setting name no longer runs into its value.

## [0.3.4] - 2026-10-03

- A user message with several text blocks, such as two Claude Code hook contexts or a prompt followed by its attachments, reaches the model as separate text parts instead of one string with the blocks run together. A tool result's text blocks stay apart the same way, joined with a newline on wires that take one string.
- A shell command's change report may take up to 500 ms, instead of 200 ms, to read the workspace before the command starts, so the first command of a macOS session under `workspace-write` no longer loses its report to a cold start.
- `/thinking [effort|default]` changes the reasoning effort without changing the model, also during a turn, from its next step; with no argument it opens a picker of the route's efforts. `/model` still waits for the turn and now says to use `/thinking` or Shift+Tab instead. The composer's key help names Shift+Tab.
- Alt+↑ with several messages queued sends them in one request in the order they were typed; the newest could reach the model before the oldest.
- A model that finishes a tool call's arguments but then streams whitespace instead of closing them no longer holds the turn for minutes. Once the arguments end in more than 2,000 whitespace characters outside JSON strings, the pi-ai adapter aborts the request and fails the step with `TRANSPORT`, which the route's `retryPolicy` retries; the abandoned call is not recorded or run. `llm-pi-ai.providers.<route>.maxToolArgumentWhitespace` changes the bound.
- `llm-pi-ai.providers.<route>.strictTools: true` sends tools as strict JSON-schema declarations to `openai-responses` and `openai-completions` models whose `compat.supportsStrictMode` is true. A tool whose schema has no strict form keeps its ordinary declaration, and the `null`s strict sampling writes for omitted optional arguments are dropped before the call is recorded. Off by default, so requests are unchanged.
- `/compact` typed during a turn no longer shows `Compacting history` over the turn, or holds Alt+↑ back, before it is refused.
- `/new`, `/clear`, and `/resume` refused while a turn runs or input is queued record the reason as the command's error, instead of a success followed by a notice.
- Tool and parameter descriptions are shorter, so the tool declarations sent with every request are about a third smaller, and the persona asks the model to put independent tool calls in one response, send an edit together with the command that checks it, make one edit call per file, and not re-read a file to confirm an edit that succeeded. Together with the tool removals below, a paired eval measured 39% to 67% fewer total tokens per task on Opus 5.5, GPT 6.1 Sol, Gemini 3.8 Flash, and DeepSeek V4 Pro, with fewer model round trips and no new tool errors.
- Removed: the webhook packages, which ran programmatic rules on verified GitHub events to start sessions in a Web workspace, with their GitHub review example, and the workspace registry. No shipped profile mounted them. Sessions that a webhook rule started still open.
- Removed: the `todo_write` tool and the terminal's task list, its row above the header, its Tasks sheet, and Ctrl+T. A compaction checkpoint no longer carries a `<todo-list>` section, and session search no longer indexes task lists. Sessions that recorded task lists still open and resume; their `todo/write` events are kept in the log and skipped.
- Removed: the `workflow` and `ralph` tools, their workflow engine and its Node runtime row, and the terminal's workflow progress in the delegation row and the subagent sheet (Ctrl+G); the sheet no longer marks children `Direct`. The `ptc` preset's description no longer mentions them, and the standard eval suite drops its `workflow_script` scenario. Sessions that recorded workflow runs still open and resume; their `tool-workflow/*` events are kept in the log and skipped.
- Removed: the `subagent_fork` tool and its history-seeded subagent backend. `subagent`, `list_subagent_models`, `send_message`, `list_agents`, and `interrupt_agent` are unchanged, and earlier forked children still open.
- Removed: the `present` tool. Sessions that recorded presented files still open; their `deliverables/presented` events are kept in the log and skipped.
- Removed unused packages: the opt-in `str_replace_editor` tool, the Exa search provider (DeepSeek native search remains), the time and tmux context plugins, the experimental Python PTC runtime, and per-message feedback. `/feedback` is unchanged; released `feedback/message-put` and `feedback/message-delete` records still open and are no longer uploaded by OTel session telemetry.
- Removed unused runtime surfaces that no shipped profile reached: the sandboxed Node backend for `run_code` (`dsh-ptc-runtime-node`), so `run_code` keeps running on QuickJS and a PTC runtime request no longer accepts `timeoutMs: null`; the `tool_help` tool and the `details` field of tool definitions; and subagent parent-history seeding, with `SubagentProvider.inheritsParentContext` and the seed a provider could return from `prepareContinuable`, which now returns nothing. Tool schemas and prompts are unchanged, and children recorded by earlier fork backends still open.

## [0.3.3] - 2026-10-02

- Auto routing (beta) has its own Routing tab in `/settings`, after Agent, once subagents may pick among allowed models. It holds the router's switch and, once it is on, the router account, URL, routing priority, and model calibration.
- A CLIProxyAPI model the proxy lists without its effort levels or limits takes them from the vendor's own catalog entry of the same id, in the terminal and in `dsh headless`, with no new login or settings change. `claude-sonnet-5-5`, which the proxy lists bare, refused every request that named an effort with `UNSUPPORTED_REASONING_EFFORT`; it now offers low through max with adaptive thinking. Other OpenAI, Anthropic, and xAI models the proxy lists bare, such as `gpt-5.4`, `claude-haiku-4-5`, and `grok-4.7`, offer the levels their vendor publishes. This holds for any hand-declared pi-ai route that serves a vendor model under its own id over the vendor's protocol. What the route's settings state still wins, and relay variants such as `:batch` or `-latest` are left as declared.
- DeepSeek runs through the pi-ai adapter, now on `@earendil-works/pi-ai` 1.0.0. The shipped `deepseek-official` route still reads `DEEPSEEK_API_KEY` and speaks DeepSeek's Anthropic-format Messages endpoint, so saved selections keep working. `llm-deepseek` and the packages only it used are removed: `/usage`, Files-API image upload (images are sent inline), the `dsh_session_log` and `dsh_plugin_packages` request fields, and DeepSeek image-token pricing are gone. The `llm-deepseek:` settings section and `DEEPSEEK_BASE_URL` are ignored; set `baseURL` under `llm-pi-ai.providers.deepseek-official` instead. Sessions recorded by `llm-deepseek` resume with provider-neutral replay. The route keeps the old adapter's request shape through the new `messagesWire` option: no `cache_control` markers, no pi-ai placeholder tool, and adjacent same-role messages merged, so DeepSeek's prompt cache hits as before.
- MCP servers are reached through `@earendil-works/pi-mcp` instead of the MCP SDK. Tool names, descriptions, schemas, and content are unchanged. The client negotiates protocol 2025-11-25 at most, stdio servers run in their own process group, and a listing stops with an error after 1,000 pages or a repeated cursor instead of silently after 64.
- `run_code` runs in a QuickJS sandbox from `@earendil-works/pi-codemode` instead of a sandboxed Node process. A program has no file, network, process, or timer access of its own; every effect goes through a declared tool binding under that tool's policy. `run_code` therefore drops its `sandbox_permissions` and `justification` arguments, reading an undeclared binding throws with a suggestion, and a promise nothing can settle fails at once. Workflow scripts still run on the Node runtime.
- A reply cut off at the output token limit no longer drops its tool calls silently. The model is told which calls did not run and the turn continues once, so it can issue them again in smaller pieces. A tool step after a cut-off reply also continues the turn instead of ending it unread.
- A Claude Code hook that returns `continue: false` stops the turn: after PreToolUse the call is denied, after PostToolUse its decision stands, and calls that had not started end as aborted. Tool policies can halt a turn the same way through `ToolHalt`, including from a call made inside `run_code` once the program settles. The terminal shows `Stopped by a hook: <reason>` for such a turn instead of `Interrupted`.
- A running `bash` or `pwsh` command shows its newest output under the call while it runs, and a parallel tool call is marked done as soon as it finishes instead of waiting for the calls before it. The live output is not logged or sent to the model; the logged result replaces it when the call completes.
- The compaction policy can be changed from the `compaction-basic` section of `settings.yaml`, or `/settings` → Advanced, and applies at the next pressure check without a restart. A `modelPolicies` entry without `model` covers every model on a provider route, such as `cliproxyapi`; an exact model entry layers over it field by field. `thresholdTokens` sets the compaction point in tokens instead of `thresholdRatio`. Defaults are unchanged.
- A compaction checkpoint lists the files the condensed history read and changed, and its open todo list, in `<read-files>`, `<modified-files>`, and `<todo-list>` sections after the summary. They come from the condensed `read`, `read_image`, `write`, `edit`, and `todo_write` calls, carry forward across compactions, and hold at most 50 entries each.
- A compaction summary request that itself overflows the context window is retried as a transcript with tool output cut to 2,000 characters, then over the older half of the span, up to three times. During overflow recovery and `/compact`, a summary request that fails with a rate limit, server, timeout, or transport error is retried up to three times with the provider's backoff.
- Removed: the Chinese interface language, the `locale` setting and its `/settings` row, and all Chinese documentation. Bake's interface and docs are English only; a stored `locale` setting is ignored. The shipped preset names are now English.
- A goal keeps running after a turn whose cut-off reply was recovered by the dropped-call notice. It still pauses when the turn's last reply is itself cut off.

## [0.3.2] - 2026-10-01

- Ctrl+G shows each subagent's recorded model selection: automatic, explicitly selected, or default, with the effective model and reasoning effort, task difficulty, and the router's reasons. Cautious decisions, missing context, and fallback remain visible after resume. Model calibration labels inherited quality estimates separately.

- Security: the status line's `git status` poll no longer runs outside the sandbox for a sandboxed session. Such a session can write `.git/config` and `.gitattributes`, and `git status` runs a `core.fsmonitor` hook and clean filters named there, so a sandboxed command could plant a command that the poll then ran unconfined every two seconds. These reads now run under `read-only` confinement with the fsmonitor hook off. Where no sandbox backend can confine them, the git field is left out. `danger-full-access` sessions read as before.

- A foreground `bash` or `pwsh` command that changes files in a git workspace shows those files under its output, with the changed lines numbered and colored as an `edit` call shows them. A `sed -i` or Python edit is now as visible as an `edit`, even when the command then exits non-zero. The report is display only: the model's result is unchanged, and `changeReport: false` turns it off. Git is read before and after the command against a copy of the index, with its fsmonitor hook off, and under `read-only` confinement for a sandboxed session. On this repository, a command that changes nothing takes about 33 ms longer at the median.
- The download service at bake.justar.dev counts active installs: an installed Bake that checks for updates counts once that day, sent to gissx.org's admin as a daily salted hash of its address, which never leaves the service. `BAKE_NO_UPDATE_CHECK=1` turns the check off and keeps the install out of the count. Nothing is counted until the service has its `GISSX_ACTIVITY_URL`, `GISSX_ACTIVITY_TOKEN`, and `BAKE_ACTIVITY_SALT` variables.
- The subagent sheet (Ctrl+G) shows how each delegated child was routed: `Auto` when the task router chose its model, `Selected` when the call named one, or `Default`. It names the effective model and reasoning effort, the router's explanation and difficulty estimate, and a cautious assessment or missing context. A router fallback says why the default was kept. Each decision is logged as an ignorable `subagent/routing-decision` event, so it survives resume while older Bake versions skip it, and it never reaches model history. Routing stays a beta that is off by default.
- A delegated task longer than 20,000 characters reaches the task router as its opening and its end, the way the router judges it. Bake sent only the opening, so the ask at the end of a pasted log never reached the router.
- `dsh headless` honors the `subagent-model-selection` setting as the terminal does: once it is enabled, the `subagent` tool offers its allowed routes, and with its router on, a delegation that names no route asks the router for one. Headless runs ignored the setting. While it is off, the tools are unchanged.
- With subagent model selection on, `subagent` and `list_subagent_models` read a blank `provider`, `model`, or `reasoning_effort` as left out, and a refused provider or route names the allowed routes. GPT models send every optional field, with an empty string for each they leave out. Both tools refused the empty provider, and the errors never named a route GPT could use, so in the eval GPT-6.1 Sol made up to 20 failing calls in one delegation and never reached the router.
- A headless run stopped by SIGTERM, SIGINT, or SIGHUP no longer reports `dsh: session "…": flush on a closed handle` and a JSON `error` event.
