# @dsh-tui/ui

English | [中文](README.zh.md)

## Summary

This library renders terminal state supplied by `@dsh-tui/app`. `App` displays committed history, live response text, pending input, status, and one human request. Components use typed locale dictionaries and callbacks. They do not access Cordis, Node services, storage, or a clock; the composer's rule is timed only from an optional `clock` prop, which `App` ignores under a screen reader, and animates only while the `motion` prop is not false. The runner always passes the clock and turns motion off under `NO_COLOR`, which leaves the elapsed seconds counting and nothing else moving.

## Use this package

For command argument completion, set `choices: true` on a command entry, supply the query-tagged `completion.argument` snapshot, and handle `onArgumentQuery` through the commands service. `argumentQuery` identifies the first argument at the cursor. The menu filters matching choices; Tab or Enter inserts a partial choice, while Enter on an exact complete choice submits. With no matches, the command's usage row remains visible. Argument rows consume the same claimed row budget as slash-name rows.

Import `App` and `AppProps` from the package entry point. Supply authoritative state and callbacks as demonstrated by the [runner](../app/src/runner.ts) and [component tests](tests/shell.spec.tsx). `project(event, projector)` maps a committed Session event to zero or more rows; build the projector with `projector(copy, lookup)`, one per transcript, where `lookup` resolves a recorded tool name to its `presentCall` / `presentResult` — pass `() => undefined` to render every tool at its raw arguments. `formatRow` provides a plain-text representation. Supply `completion` with session-owned command/skill metadata and discovery status, plus a positive integer `completionLimit` for visible menu rows and a non-negative integer `resultLines` for the tool-result lines the transcript keeps under each outcome and the reasoning rows it keeps from each step. The menu filters a leading slash token, shows registered `/model`, `/resume`, `/new`, and `/clear` commands first, shows each command’s `hint` beside its description, runs the selected command on Enter, inserts the selected name on Tab, and closes on Escape before cancellation reaches the application. A command whose hint opens with `<` requires input: Enter fills it with a trailing space instead of running it, and once the menu closes at that separator a single usage row (`commandUsage`) stays under the composer. `requiresInput` and `suggestCommand` are exported for the application's own dispatch. Enter inserts a selected skill name unless its full name is already typed. Paste only edits the draft. This is a library dependency, with no Cordis mount row.

The optional `AppProps.version` supplies the running root package version for a `BAKE v<root version>` welcome block. When the session surface mounts with an empty `committed` transcript and is not a child inspection, it prints the block once through `Static`, carrying the session line the heading would otherwise print. Resumed history has no welcome banner, and omitting `version` suppresses it. Ink `Box` owns the welcome border, section margins, and command columns; text is not padded for alignment. The welcome card is at most 64 columns wide, draws the line style the application resolved from the terminal, and has no border below 40 columns; it belongs to terminal scrollback, not the dynamic region. The application owns `/changelog`, which prints the running root package version’s section of the root `CHANGELOG.md` to the transcript; `/help` lists commands only. `/changelog` remains available with staged attachments.

Supply query-tagged `files` and `onReferenceQuery` for workspace-path discovery. The callback receives the active query or `undefined` when the menu closes. Only results matching the current query can be selected. Pure `activeAtToken` and `formatFileMention` imports from the Harness grammar own token detection and quoting; file Tab completion preserves surrounding text and directory Tab completion keeps discovery open.

The composer supports cursor insertion, grapheme movement and deletion, logical-line Home/End, and Shift-Enter for newlines. Enter submits the full draft when the slash menu is closed. Up/Down browses human input when completion is closed. Up past the oldest entry selects the goal when one exists and restores the unsent draft; Down from an empty composer selects subagents when present. Ctrl-P/N recalls history, including while a menu is open. Returning past the newest entry restores the original draft and cursor. See the [keyboard controls](../app/README.md#use-this-package) for completion and editing behavior.

The composer has no box and no fill. A dim rule, exactly the terminal's width, sits directly over the draft, and the draft is in the terminal's own foreground, so it reads on light and dark themes alike. The rule is drawn in box-drawing or ASCII glyphs, whichever the application resolved the terminal can draw. A second dim rule sits directly under the draft and the status line directly under that, with no blank row between them. Both rules are bare: what the session is doing has its own header row directly over the upper rule, and the header's label, the draft, and the status line start at the same column. Pass `goal` (a `GoalEntry`) to show the session goal at the header's right edge: `● Goal active` with its round count while it may continue, `○ Goal on hold` or `○ Goal paused` while it waits on `/goal resume`, `✗ Goal blocked` with the reason, and `✓ Goal complete`, each followed by the objective; the goal's details are cut before the turn's label, and the goal is dropped whole below its own label. `goalState` returns what the header draws for an entry. The goal always shares this row with the turn status when both are present, led by a dim `Ctrl+O` hint that a tight row gives up after the goal's details and before its label. `StandingState.key` carries that hint. Up past the oldest history entry selects the goal header and restores the unsent draft; Enter opens a scrollable panel with the full objective and status. The panel uses Up/Down, PgUp/PgDn, and Home/End for navigation, and Escape or Enter closes it without changing the draft. Ctrl+O opens it directly even while drafting. `/goal` also shows the complete objective and available actions.

Supply `update` with a newer release's `version` and whether it is `installed` to name it in the status line as `update v<version> · /update`, or `· restart to use` once installed, after every reading of the session and before the path, so it is the first field a narrow line drops. Supply `onCycleThinking` to receive Shift-Tab, which the app reads before the completion menu and the composer, so it never completes or inserts a tab. Supply `subagents` with child identities and activity from the Harness catalog. When children exist, the status line shows their total and working count. From an empty composer, Down selects that field; Enter calls `onSubagents` to open the child picker. Up, Left, or Escape returns to the composer, and Ctrl+G opens the picker directly. The field takes priority over other status readings when width is tight. The picker shows each child's state and latest recorded outcome, when available; `inspection` displays a read-only child transcript while retaining the parent composer draft. Escape calls `onCancel` to return. Supply `todos` with the agent's current task list, or `undefined` before it writes one. While work remains it takes one row above the header: a bold `Tasks`, a progress bar of heavy and light rules, the count, and the task in progress as a bold `▸` in ocean blue, or the next open one as a dim `□` (`Tasks  ━━━━────────  1/3 · ▸ Thread the home`), with a dim `Ctrl+T` at the right edge that gives way before the task is cut below a few cells. The row leaves once every task is done. Up past the oldest history entry selects it when no goal is set, and Up from the selected goal otherwise; Down walks back. Enter on the row, or Ctrl+T at any time, opens a scrollable sheet of every task in the agent's order, wrapped: finished as a green `✓` with dim struck-through text, the current one bold, the rest as dim `□`. Escape or Enter closes the sheet. The goal's view is the same kind of sheet, framed in the terminal's resolved border style. Supply `attachments` with staged metadata; pending inputs and user rows can also carry attachment summaries. The UI renders names, byte lengths, and available image metadata, without reading bytes or paths. `onSubmit` may return `false` or a promise: refusal/rejection preserves the draft and cursor, while successful asynchronous acceptance clears them. Pending acceptance suppresses edits, paste, recall, and repeated Enter, including keys decoded in the same read; Escape and Ctrl-C remain active. An empty draft can submit when staged attachments exist.

Use `dictionaries.en` or `dictionaries.zh` for application labels. Model text, tool output, question details, and service diagnostics remain verbatim. Build `committed` from `emptyTranscript` and `appendTranscript(previous, rows)`. Snapshots and their row batches must remain immutable and append-only because Ink `Static` prints each suffix once. `transcriptRows(snapshot, start)` reads only the suffix following a previously rendered count; streaming updates do not scan committed rows. Changing `sessionId` remounts session presentation, resets draft/cursor/recall and completion state, and prints a localized session heading before its history. Set `inputBlocked` during navigation to suspend composer input while retaining Escape and Ctrl-C; choice interactions remain usable. The status line opens with `Model: <name>` rather than a state word, since the header over the composer and its placeholder already say what the session is doing. The model and context fields, including their labels and values, use the terminal's normal foreground without dimming; plan mode, token totals, the cache-hit label, and the working directory stay dim. Pass the optional Harness `plan` projection to show active or pending plan mode beside the model. Pass `usage` once the provider has reported any: it shows `in` and `out` totals and, only when `cached` is set, the share of input read from cache as `cache hit N%`. The percentage is coloured: green from 70%, yellow from 30%, and red below, beside a dim label. Pass `permission` from the session’s `permissions.currentValue` to show `Access <mode>` beside the model and plan. The mode is blue for `read-only`, green for `workspace-write`, red for `danger-full-access`, and yellow for other policies. It reserves its width before the model, retaining the full built-in names at 40 columns; profiles without the projection show no badge. Child inspection takes its own permission value. Pass `thinkingLevel` from the selected model’s reasoning effort or advertised default to show an ocean blue `Think <level>` badge. The model name no longer repeats the level in parentheses. Unknown or unsupported levels are omitted; a short level remains visible with access at 40 columns, while longer values yield whole. Child inspection uses its own level. Narrowing drops the supporting bounded fields whole, from the end, and the working directory keeps its tail. When the full context field will not fit, it reserves a compact localized percentage beside the access and thinking badges before shortening the model name; if even that cannot fit, it omits the field. Context estimates display a `~` prefix. A child inspection renders only the child's supplied context and usage; neither falls back to the parent. Pending input includes the localized `/clear-pending` hint.

## Understand the implementation

<details>

<summary>Input and presentation</summary>

Bake's [Ink patch](../../../../patches/ink@7.1.1.patch) bounds each process-wide text measurement and wrapping cache to 1000 entries and 1,048,576 UTF-16 code units of keys and string values. Oversized values render without entering the cache; older entries are evicted in least-recently-used order. Streamed text and tool updates can therefore release obsolete layouts. Durable history and resize scrollback retain their own lifetimes. The [renderer regression](tests/memory.spec.ts) checks retained heap with real Ink under Node; its [measurement record](../app/performance/README.md#renderer-memory) describes the scope.

Ink `usePaste` inserts text without actions; `useInput` handles typed keys. `useComposer` keeps same-read edits available before React paints. History visits lazily traverse pending human input, committed user rows, and commands, retaining local edits only for visited entries. Logged command arguments rebuild the submitted line. Commands whose arguments were omitted from the log are recalled only when the controller supplies a process-local line; a redacted command replayed after resume is skipped. The controller never supplies a line for `/login` with arguments. Typing and rendering do not scan history, and recalling or editing an entry never mutates the transcript. Text questions and login prompts share cursor editing without a history source.

The composer rests on the terminal's bottom rows from the first frame: from the top, a blank row, the header, the rule, the draft, the base rule, and the status line. That height depends only on the terminal's rows; a short terminal drops the blank, the base rule, the rule, the status line, and then the header, and never the draft. The header keeps its row, blank, while it has nothing to say. History prints above it and scrolls up; one blank row separates the latest transcript or streaming row from the header and the input. The frame never gets shorter than the history printed above it can make up: rows a closing menu, notice, or finished task gives up stay blank above the controls until the next printed rows take them, so the composer never rises. The runner's output layer starts the first frame, and each replay after a resize, on the bottom row. While a turn runs, the header names it and keeps one word for the whole turn (`  ⠠⠞⠁ Kneading…  thinking · 12s`), with the phase and elapsed time beside it; the rules stay still and dim. The six-column, three-row dot wave occupies three Braille characters before the word, moving right every 300 ms and looping every 1.8 seconds. Without motion the wave holds centered; under a screen reader it uses a static `>` instead. Manual compaction takes the header the same way. When the turn ends, the header holds how it went (`  ✓ Completed  42s · ran 2`) until the next begins. Streaming reasoning is shown above the header in a thinking window: up to three of the newest wrapped rows, a dim italic paragraph at the rail with no verb, using the same Markdown formatter as the transcript, with one blank row between it and the header. The window grows to its rows and then holds its height rather than scrolling the live region. When the step commits, history keeps the first `resultLines` wrapped rows of the reasoning and a dim count of the rest; the full text stays in the Session log. The application prints settled Markdown blocks of a streaming answer to history (rows marked `continued` carry the rest of a block without reopening it), so the live region holds the unfinished block and any call still streaming, and the composer stays on the bottom row of a full screen. Completion lists, notices, queued input, and quit feedback open between the blank row and the header, sharing the available rows. Wrapped drafts grow within the composer limit. Narrowing the terminal repaints it so a reflowed rule is not left behind; normal streamed turns preserve native scrollback without full-screen clears.

The composer follows the caret within wrapped text, including Home/End moves and Unicode input. Drafts wrap like an editor: a row breaks after whitespace, which stays at the end of the row it breaks, so no wrapped row opens with a space. Wide characters can break anywhere, and a word longer than a row starts its own row. Tabs draw as spaces to four-column stops. Moving the caret never reflows a draft. Short terminals drop spacing, status, and framing as needed to keep input visible. A stable `Static` instance retains committed history across resize and reads only each new suffix. Long replay is admitted in bounded display batches, yielding to input and waiting for terminal output between batches. A forward cursor presents each source row once, preserving complete ordered output without constructing the whole history’s layout tree together. Returning from child inspection starts a fresh replay and keeps the parent draft.

A dim divider opens each user message. A slash command prints as typed, flush with the left edge and its name bold, behind a blank row, and its outcome (a `command/done` notice placed `command`) hangs from it on a `└` branch, red when the command failed. Assistant replies are paragraphs at the rail with no marker, at full brightness behind the blank row that opens them. A final answer, one that finished with `stop`, is followed directly by a dim `rate` row, `856 tokens · 42.3 tok/s`: the provider's reported output tokens over the logged time from the first streamed token to the finish (`outputRate`), left out when the log cannot say, as for a tool-call step, an interrupted answer, or no usage. Reasoning is a dim italic paragraph at the rail, with no verb or marker, wrapping at the current terminal width minus the rail like the answer. The live response and reasoning preview rewrap when the terminal resizes; at very narrow widths the verb column's label joins its text instead of consuming a fixed gutter. A call and its result draw as one block opened by `●` and headed as the call: the tool's name from `toolLabel` and its argument in parentheses, `Bash(cargo check --workspace)`. A tool without a card is headed by the argument field it acts on (`argumentsTitle`), never raw JSON. While the call runs, the marker blinks between orange and a blank cell, with no half-bright state; when the result arrives it holds, green, or red on failure. A title's first word is dropped when it repeats the tool's action (`Grep(Grep TODO)` reads `Grep(TODO)`), but a command keeps every word. The output's first line hangs from the head on a dim `⎿` in the verb column. No call ids are drawn. `Actions` folds each result into its call and holds a step's calls until the step ends (`SETTLES`), then releases them in call order, so out-of-order results cannot reorder the blocks; the application draws the calls it still holds in the live region through `Actions.live`, together with the calls still streaming and those the committed message announced (`announcedCalls`) but the loop has not dispatched, so the block keeps its calls and shape from the first streamed call to its print and leaves no blank rows behind. A step with two or more calls prints as one `tool-group` block: a `●` head counting the calls by verb (`ran 2 · edited 1 · 1 failed`), and each call hanging from it on a `├`/`└` branch in the rail, coloured by its state as its `●` would be but never blinking, since only the head blinks for the step, with a dim `│` joining its lines to the next call and no blank row between them. While the step runs and is taller than the live region, it fits itself to the window (`fittedGroup`) instead of losing its head off the top: finished calls fold to their head lines oldest first, then the oldest calls fold into one dim `+N earlier calls` branch; the head, the newest calls, and every running call stay, down to just the head on the shortest window. Rows are counted wrapped at the current width, and the live region is ten rows or 40% of a tall terminal (`LIVE_BUDGET`, `LIVE_SHARE`), so the fit follows every resize. The step prints whole once it ends. The marker and tool name are bold, and `error` is bold red. Arguments use normal brightness. A result's preview (its headline, output, diff, and `+N more lines` count) has no background; its plain text is drawn in the softer `output` grey, which is quieter than an answer and brighter than the dim of reasoning. Failures, diffs, and syntax colour keep their own tones, and `NO_COLOR` drops the grey with the rest. Every colour comes from `PALETTE` in `palette.ts`, which names a role — `running`, `done`, `failed`, `asking`, `waiting`, and the preview text's `output` — rather than a hue, so a marker, its verb, the status word, and the rule cannot drift apart. The header's word carries the `running` orange. The spinner and the blink of every running `●` share one beat from `Beat`: one timer for the surface, present only while something moves, and a beat redraws only when a glyph or the elapsed seconds change. A running turn draws about five frames a second, with or without running actions. When the turn ends, the header holds a summary until the next turn: `✓ Completed`, an yellow `■` with the reason a turn stopped, or `✗ Failed`, then the elapsed time, the calls counted by past-tense verb, and how many failed. A resumed session shows its newest ended turn the same way, without a time. A result's output is bounded rather than printed whole: command output, file reads, search and web results, and failures show their first and last lines, `resultLines` in all, around a dim count of the rest, an edit's diff shows its first changed lines. A count that would stand for one line is that line instead. A card's summary (a search's count, a partial read's window, a fetch's status, a command's non-zero `exit` in red) is drawn on the head, where no bound hides it. A call's multi-line input and description are bounded the same way; an input its title already names is left out, and a card's fenced block is drawn as its code. It prints once and is never removed, so a result does not move the composer after it appears. The full text stays in the Session log. A completed turn leaves no line in the transcript, because the summary row says so. Every other recorded turn outcome — interruption, blocking, output-token limits, and errors — stays as a separate footer without a turn number; it does not imply that the Agent is idle. Completion windows keep the selection visible after height changes and count omitted entries on both sides.

Responses and reasoning render CommonMark and GFM headings, emphasis, inline code, lists, task lists, quotes, links, and fenced code. Answer headings and link labels, targets, and images use the reference blue; reasoning retains its dim italic tone instead. Code uses the supplied syntax highlighter when its grammar is ready; unknown languages remain readable without colour. Tables render as stacked labeled cells so values wrap in narrow terminals. Reasoning keeps its dim, italic tone through inline emphasis. Raw HTML, reference links, and reference definitions remain literal; terminal controls are escaped. Formatting never changes logged source text or user and tool output. Paragraphs settle after a blank line; lists, tables, and fences wait for the next block or the message commit. Unfinished blocks remain visible within the live region's row limit.

`cards.ts` maps the `card`-tagged render intents of `dsh-tools` into card lines, and `present.ts` places them under the call they belong to. A tool with no presenter, one the lookup does not find, a card kind newer than this build, and a presenter that throws all keep the raw arguments and result text. The presenters are pure over the call's arguments and the durable result, including the `meta` the session log persists, so a replay reproduces the identical card.

A `diff` card draws only the lines an edit changed, each numbered on its own side from the hunk's `oldStart` and `newStart` when the tool recorded them, with `⋯` between separate changes and a path over each file only when an edit touched several. The head carries the change's size, `+N −M` in green and red, and the preview counts changed lines. The words that changed within an edited line are reversed in the side's tone. When the application passes a `highlight` function, code takes its syntax colour over the side's tone, a run of one side at a time; a highlighter that does not know the language, or has not loaded it yet, leaves the side's tone.

Tool results use the same syntax highlighter for source reads, search matches, fenced snippets, and valid JSON or JSONL. File paths and URLs are blue; leading log labels use red for errors, yellow for warnings, and green for successful checks. Code and ordinary output keep normal brightness, and a failed result stays red throughout. Read and search previews obey `resultLines`; setting it to zero keeps them collapsed. Source line numbers remain outside the grammar, and gaps between search matches start fresh syntax state. Only the lines a preview draws reach the highlighter, so a large read costs what it shows; the tail after a `+N more lines` count starts fresh syntax state too. Tool ANSI sequences are stripped before styling and measurement. Unknown languages remain plain, and `NO_COLOR` retains the same text and structure.

`InteractionView` renders questions and plan details, masks secrets, and submits exact option labels. A question picker keeps an Other answer visible while Up/Down moves through options; typing or pasting edits that answer without accepting it. Space toggles multi-select options, and Enter submits the focused single choice or the selected multi-select choices with any Other text. A `select` interaction displays a filterable `Picker` using `completionLimit` rows. Every selection panel (model, effort, session, sign-in target) reads the same way down: the title, a filter row, the choices, and a key line with the position. Typing filters by every word, in any order, across a choice's label, value, and description, and underlines the matched letters; the caller's order is kept. Up/Down (or Ctrl-P/N) moves and wraps, PgUp/PgDn move a page, and Home/End jump to either end; Enter returns one exact value, including the empty value used for provider defaults. The list scrolls only when the selection would leave it, and an edge that hides choices spends a row saying how many. Labels, a `status` column (`Current`, `Configured`), and dim descriptions align in columns sized over every choice, so they hold still while the list scrolls or narrows. A `pinned` choice stays below the list however far it scrolls. Pasting filters without accepting, and no-match input stays editable. `filterChoices` and `scrollTo` in `choices.ts` are the pure rules behind this. Request ids let the application reject stale callbacks.

Session choices can set `role` to `session-new`, `session-current`, or `session-saved`. The picker adds a distinct marker, and the current session a `Current` status, while keeping the choice value unchanged. Approval, question, and sign-in panels share the same order and emphasis: a bold title, the answer being entered after the `>` prompt, and dim keys last.

See [the wiring reference](../../DESIGN.md) for ownership and [current dependency APIs](../../DEPENDENCIES.md) for the Ink and React versions. No independent runtime invariant is installed because these components only render their supplied props.

<a id="known-limitations"></a>

## Known Limitations and Deferred Work

- Inline terminal output has no virtual scrolling or rich attachment viewer.

- Replay bounds temporary layout work; the session log and saved terminal output still grow with history. One oversized display line is admitted alone, and parsing a single large message still requires its full text.

- A `diff` card shows no context lines, so a change whose meaning depends on the lines around it has to be read in the file. A diff drawn before its language's grammar loaded stays uncoloured in scrollback.

- The composer has no mouse positioning, word movement, or vertical movement through wrapped lines; Up/Down browses history when completion is closed.
