# @dsh-tui/ui

[English](README.md) | 中文

## 概要

此库呈现 `@dsh-tui/app` 提供的终端状态。`App` 展示已提交历史、实时回复文字、待处理输入、状态和一个人工请求。组件使用类型化的语言字典和回调，不访问 Cordis、Node 服务、存储或时钟；输入框上方的分隔线只在传入可选的 `clock` 属性时才计时，`App` 在屏幕阅读器下忽略它；只有 `motion` 属性不为 false 时才有动画。运行器始终传入时钟，并在 `NO_COLOR` 下关闭动画，此时只有已用秒数继续计数，其他内容都不会自行变化。

## 使用此包

命令参数补全需要在命令条目设置 `choices: true`，提供带查询标记的 `completion.argument` 快照，并通过命令服务处理 `onArgumentQuery`。`argumentQuery` 识别光标所在的第一个参数。菜单筛选匹配选项；Tab 或 Enter 插入尚未输入完整的选项，完整输入某个选项时按 Enter 会提交命令。没有匹配项时仍显示命令用法。参数选项与斜杠命令名称共用同一行数预算。

从包入口导入 `App` 和 `AppProps`。按[运行器](../app/src/runner.ts)和[组件测试](tests/shell.spec.tsx)所示提供权威状态和回调。`project(event, projector)` 将已提交的会话事件映射为零个或多个行；用 `projector(copy, lookup)` 为每条记录构建一个投影器，其中 `lookup` 把日志记录的工具名解析为它的 `presentCall` / `presentResult`——传入 `() => undefined` 则所有工具都按原始参数呈现。`formatRow` 提供纯文本表示。通过 `completion` 提供会话拥有的命令和技能元数据及发现状态，并用正整数 `completionLimit` 指定可见菜单行数，用非负整数 `resultLines` 指定对话记录在每个结果状态下保留的工具结果行数，以及从每个步骤的推理中保留的行数。菜单筛选开头的斜杠词，优先显示已注册的 `/model`、`/resume`、`/new` 和 `/clear` 命令，在每个命令的描述旁显示其 `hint`，按 Enter 运行选中的命令，按 Tab 插入所选名称，Escape 先关闭菜单，随后才向应用传递取消操作。`hint` 以 `<` 开头的命令需要输入：按 Enter 不会运行它，而是填入命令名并补上末尾空格；菜单在该分隔处关闭后，输入框下方保留一行用法提示（`commandUsage`）。`requiresInput` 和 `suggestCommand` 已导出，供应用自行分派命令。除非已输入完整名称，否则按 Enter 插入选中的技能名称。粘贴只修改草稿。此包是库依赖，没有 Cordis 挂载行。

可选的 `AppProps.version` 提供当前运行的根包版本，用于显示 `BAKE v<root version>` 欢迎块。当会话界面挂载时，若 `committed` 对话记录为空且不是子会话查看界面，欢迎块会通过 `Static` 打印一次，并带上原本由会话标题打印的会话信息行。恢复已有历史时不显示欢迎横幅；省略 `version` 也不显示。Ink `Box` 负责欢迎块的边框、分区间距和命令列布局，不使用文字填充来对齐。欢迎卡片最宽 64 列，使用应用根据终端判定的线条样式，宽度小于 40 列时不显示边框；它属于终端回滚记录，而非动态区域。应用负责 `/changelog`，将根目录 `CHANGELOG.md` 中与当前运行的根包版本对应的章节输出到对话记录；`/help` 只列出命令。存在暂存附件时仍可使用 `/changelog`。

提供带查询标记的 `files` 和 `onReferenceQuery` 以发现工作区路径。回调接收活动查询，菜单关闭时接收 `undefined`。只能选择与当前查询匹配的结果。从 Harness 语法模块导入的纯函数 `activeAtToken` 和 `formatFileMention` 负责识别词和添加引号；文件 Tab 补全保留周围文字，目录 Tab 补全则保持发现菜单打开。

输入框支持在光标处插入、按字素移动和删除、用 Home/End 移到逻辑行首尾，以及用 Shift-Enter 换行。斜杠菜单关闭时，Enter 提交完整草稿。补全菜单关闭时，上下方向键浏览人工输入；存在目标时，上方向键翻过最早的历史条目后选中目标，并恢复未发送的草稿；输入框为空且存在子代理时，下方向键选中子代理。Ctrl-P/N 可调出历史，菜单打开时也可使用。越过最新条目向后浏览会恢复原始草稿和光标位置。补全和编辑行为见[键盘操作](../app/README.zh.md#use-this-package)。

输入框没有边框，也没有背景填充。一条与终端等宽的暗色分隔线紧贴在草稿上方，草稿使用终端自身的前景色，因此在浅色和深色主题下都清晰可读。分隔线使用应用判定终端能够绘制的制表符或 ASCII 字符。草稿正下方是第二条暗色分隔线，状态栏紧贴其下，中间没有空行。两条分隔线都不带文字：会话正在做什么由上方分隔线正上方独立的标题行显示，标题行的标签、草稿和状态栏从同一列开始。传入 `goal`（`GoalEntry`）即可在标题行右端显示会话目标：可继续推进时显示 `● 目标进行中` 及轮次，等待 `/goal resume` 时显示 `○ 目标待继续` 或 `○ 目标已暂停`，受阻时显示 `✗ 目标受阻` 及原因，完成后显示 `✓ 目标已完成`，其后均跟随目标内容；目标的详情先于回合标签被截断，空间不足以显示目标自身标签时整体省略。`goalState` 返回标题行为某个条目绘制的内容。目标与回合状态始终共用这一行，前面带有暗色的 `Ctrl+O` 提示；空间不足时，该提示在目标详情之后、目标标签之前让出。`StandingState.key` 携带该提示。按上方向键翻过最早的历史输入后选中标题行中的目标并恢复未发送的草稿，按 Enter 打开下文所述的目标面板，草稿保持不变；即使正在编写草稿，也可按 Ctrl+O 直接打开。`/goal` 也会显示完整目标及可用操作。

传入 `update`（更新发行版的 `version`，以及是否已 `installed`）即可在状态栏中以 `可更新 v<版本> · /update` 提示它，安装后改为 `· 重启后生效`；它位于所有会话读数之后、路径之前，因此是窄行最先放弃的字段。提供 `onCycleThinking` 以接收 Shift-Tab；应用会先于补全菜单和输入框读取该按键，因此它不会触发补全或插入制表符。通过 `subagents` 提供 Harness 列表中的子代理标识和活动状态。有子代理时，状态栏显示总数和工作中的数量。在空输入框中按下方向键选中该字段，按 Enter 打开下文所述的子代理面板。按上方向键、左方向键或 Escape 返回输入框；Ctrl+G 可直接打开该面板。终端变窄时，该字段优先于其他状态读数保留。`/agents` 仍会打开同一批子代理的可筛选选择器，`/agents <ID>` 直接打开其中一个；`inspection` 显示只读子会话记录，并保留父会话的输入草稿。Escape 调用 `onCancel` 返回。通过 `todos` 提供代理当前的任务列表，在它首次写入之前为 `undefined`。尚有未完成的任务时，它在标题行上方占一行：粗体 `任务`、由粗细横线组成的进度条、计数，以及海蓝色粗体 `▸` 标记的进行中任务，没有进行中任务时为暗色 `□` 标记的下一项（`任务  ━━━━────────  1/3 · ▸ Thread the home`）；行的右端为暗色 `Ctrl+T`，在任务文字被截到只剩几格之前让出。全部任务完成后该行消失。未设置目标时，上方向键翻过最早的历史条目后选中该行；设置了目标时，从选中的目标再按上方向键选中该行；下方向键依次返回。在该行按 Enter，或随时按 Ctrl+T，打开任务面板。任务列表、子代理和目标各自以面板打开，边框使用为终端选定的样式；面板上方的标签栏列出所有有内容可显示的视图，并标出当前打开的一个。Ctrl+T 打开第一个视图，并依次切换任务、子代理和目标，越过最后一个时关闭；Tab 和 Shift-Tab 向前和向后切换并循环；Ctrl+O 和 Ctrl+G 直接跳到目标和子代理，若该视图已打开则将其关闭；按 Escape 关闭。页脚列出当前视图可用的按键及其行范围。任务面板开头是进度条以及已完成、进行中和待办的数量，随后按代理给出的顺序为每项任务编号并换行显示：已完成的为绿色 `✓`，文字为暗色并加删除线；当前任务为粗体；其余为暗色 `□`。子代理面板列出每个子代理：其活动状态的符号（橙色 `●` 工作中，蓝色 `●` 在线，`○` 已保存，红色 `✗` 无法读取）、粗体名称及以结果颜色显示的状态，下方一行暗色文字说明运行方式和 ID；上下方向键移动 `▸` 指针，指针初始位于第一个有本地记录的子代理，按 Enter 以该子代理的 ID 调用 `onInspectSubagent`；没有记录的子代理仍会列出但显示为暗色，按 Enter 时面板保持打开。目标面板以其颜色显示状态、已用轮次相对上限的进度条、继续暂停目标的方式，随后在各自标题下显示目标内容和受阻原因。可滚动的面板支持上下方向键、PgUp/PgDn 和 Home/End，按 Enter 关闭。通过 `attachments` 提供暂存元数据；待处理输入和用户行也可包含附件摘要。界面显示名称、字节长度和可用的图像元数据，不读取字节或路径。`onSubmit` 可返回 `false` 或 promise：拒绝或失败会保留草稿及光标，异步接收成功后才清除。等待接收期间暂停编辑、粘贴、历史浏览和重复 Enter，包括同次读取中解码的按键；Escape 和 Ctrl-C 仍可使用。存在暂存附件时，空草稿也可提交。

使用 `dictionaries.en` 或 `dictionaries.zh` 获取应用标签。模型文字、工具输出、问题详情和服务诊断保持原样。使用 `emptyTranscript` 和 `appendTranscript(previous, rows)` 构建 `committed`。快照及其行批次必须保持不可变且只能追加，因为 Ink `Static` 对每段新增内容只打印一次。`transcriptRows(snapshot, start)` 只读取此前已渲染行数之后的内容；流式更新不扫描已提交行。更改 `sessionId` 会重新挂载会话界面，重置草稿、光标、历史浏览和补全状态，并在历史前打印本地化的会话标题。导航期间设置 `inputBlocked` 可暂停输入框输入，同时保留 Escape 和 Ctrl-C；选择交互仍可使用。状态栏以 `模型: <名称>` 开头，不再显示状态词，因为输入框上方的标题行和占位文字已说明会话正在做什么。模型和上下文字段的标签及数值使用终端的正常前景色，不再调暗；规划模式、输入输出总量、缓存命中标签及工作目录保持暗色。传入可选的 Harness `plan` 投影，可在模型旁显示已生效或待切换的规划模式。提供方报告用量后传入 `usage`：状态栏显示 `输入` 和 `输出` 总量，仅当设置了 `cached` 时，才以 `缓存命中 N%` 显示从缓存读取的输入占比。该百分比使用语义颜色：70% 及以上为绿色，30% 及以上为黄色，低于 30% 为红色，旁边的标签保持暗色。从会话的 `permissions.currentValue` 传入 `permission`，即可在模型和规划模式旁显示 `权限 <模式>`。`read-only` 为蓝色，`workspace-write` 为绿色，`danger-full-access` 为红色，其他策略为黄色。该字段优先于模型预留宽度，在 40 列终端中仍保留内置模式的完整名称；没有此投影的 profile 不显示该指示器。查看子会话时使用子会话自己的权限值。通过所选模型的推理强度或已声明的默认强度传入 `thinkingLevel`，即可显示海蓝色的 `思考 <强度>` 指示器。模型名称不再用括号重复显示强度。未知或不支持的强度不显示；在 40 列终端中，较短的强度可与权限同时显示，较长的数值则整体让位。查看子会话时使用其自身的强度。宽度变窄时，辅助有界字段从末尾整体移除，工作目录保留末尾部分。完整的上下文字段放不下时，会优先缩短模型名称，在权限和思考标记旁保留本地化的简短百分比；空间再不足则隐藏上下文字段。上下文估计值显示 `~` 前缀。查看子会话时只显示传入的子会话上下文和用量，不回退到父会话。待处理输入包含本地化的 `/clear-pending` 提示。

## 了解实现

<details>

<summary>输入与展示</summary>

Bake 的 [Ink 补丁](../../../../patches/ink@7.1.1.patch)将进程级文本测量和换行缓存分别限制为 1000 个条目，键和字符串值合计不超过 1,048,576 个 UTF-16 代码单元。超过限额的值仍正常渲染，但不进入缓存；旧条目按最近最少使用顺序淘汰。因此，流式文本和工具更新可以释放过时的布局。持久历史和调整大小时重放的回滚记录各自保留其原有生命周期。[渲染器回归测试](tests/memory.spec.ts)使用 Node 上的真实 Ink 检查保留堆；[测量记录](../app/performance/README.zh.md#renderer-memory)说明其范围。

Ink `usePaste` 插入文字而不执行动作；`useInput` 处理键盘输入。`useComposer` 在 React 绘制前保留同次读取中的编辑结果。历史浏览按需遍历待处理人工输入、已提交的用户行和命令，仅为访问过的条目保留本地编辑。已记录的命令参数可重建提交文字。参数未写入日志的命令只有在控制器提供本进程内的原始文字时才能调出；恢复会话后，没有该文字的脱敏命令会被跳过。控制器绝不为带参数的 `/login` 提供历史文字。输入和渲染不会扫描历史，调出或编辑条目也不会修改对话记录。文字问题和登录提示共用光标编辑功能，但没有历史来源。

从第一帧起，输入框就停留在终端最底部几行：自上而下依次是一个空行、标题行、分隔线、草稿、底部分隔线和状态栏。这一高度只取决于终端行数；终端较矮时依次省去空行、底部分隔线、分隔线、状态栏和标题行，但不会省去草稿。标题行无内容时仍保留为空行。历史打印在其上方并向上滚动；最新的对话记录或流式输出行与标题行及输入框之间只隔一个空行。动态区域的高度不会低于上方新打印的历史所能补足的行数：关闭的菜单、清除的通知或完成的任务让出的行，在下一次打印的行填入之前，保持为控件上方的空行，因此输入框不会上移。运行器的输出层让第一帧以及每次调整大小后的重放都从最底行开始。回合运行期间，标题行会显示该回合，并在整个回合内保持同一个词（`  ⠠⠞⠁ 揉面中…  思考 · 12s`），旁边显示当前阶段和已用时间；两条分隔线保持静止的暗色。六列、三行点组成的波形占三个盲文字符，位于词之前；每 300 毫秒右移一列，每 1.8 秒循环一次。关闭动画时波形保持居中；使用屏幕阅读器时显示静止的 `>`。手动压缩也以同样方式占用标题行。回合结束后，标题行保留该回合的结果（`  ✓ 已完成  42s · ran 2`），直到下一回合开始。流式推理显示在标题行上方的思考窗口中：在边栏列以暗色斜体段落显示最多三行最新的换行后文字，不带动词，并使用与历史记录相同的 Markdown 格式化器，与标题行之间隔一个空行。窗口增长到这个行数后保持高度，不再滚动实时区域。步骤提交后，历史中保留推理的前 `resultLines` 个换行后行，并以暗色统计其余行数；完整文字保留在会话日志中。应用会将流式回答中已经稳定的 Markdown 块打印到历史中（标记为 `continued` 的行承接同一块的其余内容，不再重新开段），因此实时区域保留未完成的块和仍在流式传输的工具调用，屏幕填满时输入框停留在最底部。补全列表、通知、待处理输入和退出提示显示在空行与标题行之间，共享可用行数。自动换行的草稿在输入框行数限制内扩展。终端变窄时会重绘，避免重排后残留分隔线；正常的流式轮次保留原生滚动历史，不会清空整个屏幕。

输入框在自动换行的文本中跟随光标，包括 Home/End 移动和 Unicode 输入。草稿按编辑器的方式换行：在空白之后断行，断行处的空白留在上一行末尾，因此换行后的行不会以空格开头。宽字符之间可以随处断行，长于一行的词从新的一行开始。制表符按四列制表位显示为空格。移动光标不会使草稿重新换行。终端高度不足时，依次省略间距、状态和边框，确保输入始终可见。会话期间保持同一个 `Static` 实例，以便调整终端大小后保留已提交历史；每次追加只读取新增部分。 长历史按有界的显示批次回放，每批之间让出执行时间处理输入，并等待终端输出完成。前向游标对每个源行只生成一次展示内容，完整保留输出顺序，避免同时构建整段历史的布局树。从子会话返回时会重新回放父会话历史，并保留父会话草稿。

每条用户消息前显示一条暗色分隔线。斜杠命令按输入原样打印，从左边缘开始、命令名为粗体，前面隔一个空行；其结果（位置为 `command` 的 `command/done` 通知）通过 `└` 分支挂在命令下方，命令失败时为红色。助手回复是边栏列上不带标记的段落，以正常亮度显示在开启它的空行之后。以 `stop` 结束的最终回答下方紧跟一行暗色的 `rate` 行，如 `856 token · 42.3 token/秒`：即提供方报告的输出 token 数除以日志中从第一个流式 token 到结束的时间（`outputRate`）；日志无法给出时省略，例如以工具调用结束的步骤、被中断的回答或没有用量数据时。推理文字是边栏列上的暗色斜体段落，不带动词或标记，与回答一样按终端当前宽度减去边栏宽度换行。终端大小变化时，实时回答和推理预览会重新换行；终端极窄时，动词列的标签并入其文字，而不占用固定宽度的列。一次调用及其结果绘制为一个以工具图标开头、以调用本身为标题的块（`iconFor`：`$` 为命令，`≡` 为读取，`✎` 为编辑，`⌕` 为搜索，`↳` 为启动子代理，`→` 为向子代理发送消息，其他工具为 `●`）：`toolLabel` 给出的工具名，后跟括号中的参数，如 `Bash(cargo check --workspace)`。没有卡片的工具以其作用的参数字段为标题（`argumentsTitle`），而不显示原始 JSON。调用运行时，标记在橙色与空白单元格之间闪烁，没有半亮状态；结果到达后标记保持为绿色（失败时为红色）。标题的首词若只是重复工具的动作则省略（`Grep(Grep TODO)` 显示为 `Grep(TODO)`），但命令保留全部词语。输出的第一行通过动词列中暗色的 `⎿` 挂在标题下。不显示调用 ID。`Actions` 将每个结果并入其调用，并把同一步骤的调用保留到该步骤结束（`SETTLES`），再按调用顺序释放，因此乱序到达的结果不会打乱块的顺序；应用通过 `Actions.live` 在实时区域绘制仍被保留的调用，连同仍在流式传输的调用，以及已提交消息声明（`announcedCalls`）但循环尚未分派的调用，因此该块从第一个流式调用到打印始终保持相同的调用和形状，不会留下空行。包含两个及以上调用的步骤打印为一个 `tool-group` 块：标题按动词统计调用（`ran 2 · edited 1 · 1 项失败`），调用同属一类时标记为该类图标，否则为 `●`；每个调用通过边栏中的 `├`/`└` 分支挂在标题下，分支本身不显示图标，其颜色与该调用原本的标记一致地表示状态，但从不闪烁，因为只有标题代表整个步骤闪烁；暗色 `│` 将调用的各行连到下一个调用，调用之间不再插入空行。步骤运行中且高于实时区域时，会自行适配窗口（`fittedGroup`），而不是让标题从顶部被截掉：已完成的调用从最早的开始折叠为仅剩标题行，随后最早的若干调用合并为一条暗色的 `+N 个较早的调用` 分支；标题、最新的调用和所有运行中的调用始终保留，窗口最矮时仅保留标题。行数按当前宽度换行后计算，实时区域为十行，或较高终端高度的 40%（`LIVE_BUDGET`、`LIVE_SHARE`），因此每次调整大小后都会重新适配。步骤结束后完整打印到历史中。标记和工具名为粗体，`error` 为粗体红色。参数使用正常亮度。结果预览（其标题行、输出、差异和 `+N more lines` 统计）没有背景；普通文字使用较柔和的 `output` 灰色，比回答更安静，又比推理的暗色更亮。失败、差异和语法颜色保留各自色调，`NO_COLOR` 下该灰色与其他颜色一同去除。所有颜色都取自 `palette.ts` 中的 `PALETTE`，它按角色（`running`、`done`、`failed`、`asking`、`waiting`，以及预览文字的 `output`）而非色相命名，因此标记、动词、状态词和分隔线不会彼此漂移。标题行上的词使用 `running` 的橙色。旋转图标和每个运行中 `●` 的闪烁共用 `Beat` 提供的同一节拍：整个界面只有一个计时器，且仅在有内容运动时存在；只有图标或已用秒数发生变化的节拍才会重绘。运行中的回合每秒约绘制五帧，与是否有运行中的操作无关。回合结束后，标题行保留摘要，直到下一回合开始：`✓ 已完成`、黄色 `■` 加回合停止的原因，或 `✗ 失败`，随后是已用时间、按过去时动词统计的调用次数，以及失败次数。恢复的会话以同样方式显示最近一个已结束的回合，但不显示时间。结果输出受到限制，不会整段打印：命令输出、文件读取、搜索与网页结果以及失败显示开头和末尾的行，共 `resultLines` 行，中间以暗色统计其余行数；编辑差异显示前几行改动。若统计只代表一行，则直接显示该行。卡片自带的摘要（搜索的匹配数、部分读取的范围、获取的状态码、命令的非零 `exit`，后者为红色）显示在首行，不受行数限制遮挡。调用的多行输入和描述也按同样方式限制；标题已包含的输入不再重复，卡片中的围栏代码块只显示其中的代码。结果只打印一次且不会被移除，因此出现后不会再移动输入框。完整文本保留在会话日志中。已完成的回合不会在对话记录中留下一行，因为摘要行已说明这一点。其他已记录的回合结果——中断、受阻、输出 token 上限和错误——仍作为独立页脚显示，不显示回合编号；这并不表示代理已空闲。补全窗口在高度变化后仍显示所选条目，并统计窗口两侧省略的条目。

回复和推理支持 CommonMark 与 GFM 标题、强调、行内代码、列表、任务列表、引用、链接和围栏代码块。回答中的标题、链接文字和目标以及图片使用引用蓝色；推理仍保持暗色斜体。代码在语法就绪时使用传入的语法高亮器；未知语言以无颜色的可读文本显示。表格按带标签的单元格逐行显示，便于在窄终端中换行。推理中的行内强调保留暗色斜体。原始 HTML、引用式链接和引用定义按原文显示；终端控制字符会转义。格式化不会改变日志中的源文本、用户输入或工具输出。段落在空行后稳定；列表、表格和围栏代码块等待下一块或消息提交。未完成的块始终显示在实时区域的行数限制内。

`cards.ts` 把 `dsh-tools` 中带 `card` 标签的呈现意图映射为卡片行，`present.ts` 将它们放在所属调用之下。未声明呈现器的工具、查找不到的工具、比本次构建更新的卡片类型，以及抛出异常的呈现器，都保留原始参数和结果文本。呈现器对调用参数和持久结果（包括会话日志保存的 `meta`）是纯函数，因此重放会重现完全相同的卡片。

`diff` 卡片只绘制编辑改动的行；若工具记录了补丁块的 `oldStart` 和 `newStart`，每行按其所在一侧编号。不同改动之间以 `⋯` 分隔，只有编辑涉及多个文件时才在每个文件前显示路径。标题行给出改动规模，以绿色和红色显示 `+N −M`，预览只计算改动行。已编辑行中改变的词语以该侧色调反色显示。应用传入 `highlight` 函数时，代码在该侧色调之上叠加语法颜色，每次为同一侧的一段连续行着色；高亮器不认识该语言或尚未加载语法时，保留该侧色调。

工具结果为源码读取、搜索匹配、围栏代码片段及有效的 JSON 或 JSONL 使用同一语法高亮器。文件路径和 URL 显示为蓝色；行首日志标签以红色表示错误、黄色表示警告、绿色表示检查成功。代码和普通输出保持正常亮度，失败结果始终为红色。读取和搜索预览遵守 `resultLines`；设为零时保持折叠。源码行号不传给语法分析器，搜索匹配之间的行号间隔会重置语法状态。只有预览实际绘制的行会交给高亮器，因此大文件读取的开销只取决于显示的部分；`+N more lines` 计数之后的尾部也从新的语法状态开始。工具的 ANSI 序列在设置样式和测量前移除。未知语言按纯文本显示，`NO_COLOR` 保留相同的文字和结构。

`InteractionView` 展示问题和计划详情，对密钥使用掩码，并提交精确的选项标签。问题框的首行为 `等待回答`、问题的简短标题，问题多于一个时还显示每一步一个圆点（已回答的为绿色）和计数；其下为粗体的问题。选项带编号，描述以暗色列对齐在最长的带描述标签之后，按数字可跳到对应选项。“其他回答”是最后一行，编号接在选项之后，选项滚动时仍保持可见，在填写文字前显示暗色提示；在任意行输入或粘贴都只编辑这份回答，不会直接提交。多选问题为每个选项显示 `[ ]` 方框，按空格勾选为绿色 `[✓]`；“其他回答”填写文字后自动勾选，按键说明右侧统计已选数量。按 Enter 提交当前聚焦的单选选项，或提交已勾选的选项及填写的“其他回答”文字；没有可提交的内容时，按键说明处以黄色说明缺少什么。`select` 交互显示可筛选的 `Picker`，行数由 `completionLimit` 控制。所有选择面板（模型、推理强度、会话、登录目标）自上而下的顺序相同：标题、筛选行、选项，以及带位置的按键说明。输入的每个词可按任意顺序匹配选项的标签、值和描述，匹配的字母加下划线；选项保持调用方给定的顺序。上下方向键（或 Ctrl-P/N）移动并循环，PgUp/PgDn 翻页，Home/End 跳到两端；Enter 返回一个精确值，包括用于提供器默认值的空值。只有选择将移出可见范围时列表才滚动，隐藏选项的一端用一行显示隐藏数量。标签、`status` 列（`当前`、`已配置`）和暗色描述按列对齐，列宽依据全部选项计算，因此滚动或筛选时保持不动。`pinned` 选项无论列表滚动到哪里都保留在列表下方。粘贴只筛选而不确认，没有匹配时仍可编辑输入。`choices.ts` 中的 `filterChoices` 和 `scrollTo` 是这些规则的纯函数实现。请求 ID 使应用能够拒绝过期回调。

会话选项可将 `role` 设为 `session-new`、`session-current` 或 `session-saved`。选择器添加不同的标记，并为当前会话显示 `当前` 状态，选项值保持不变。批准、问题和登录面板使用相同的顺序和强调方式：粗体标题、`>` 提示符后的输入内容，最后是暗色按键说明。

<a id="known-limitations"></a>

## 已知限制与后续工作

- 内联终端输出没有虚拟滚动或富附件查看器。

- 回放限制的是临时布局工作量；会话日志和保存的终端输出仍随历史增长。单个超大的显示行会独占一批，解析单条大消息仍需要它的完整文本。

- `diff` 卡片不显示上下文行，因此含义依赖周围代码的改动需要到文件中阅读。在语言语法加载完成之前绘制的 diff，在回滚历史中保持无语法颜色。

- 输入框不支持鼠标定位、按词移动或在自动折行之间上下移动；补全菜单关闭时，上下方向键用于浏览历史。
