# @dsh-tui/app

[English](README.md) | 中文

## 概要

此私有工作区包为基于 base 的 `dsh` 配置添加终端运行器和命令行参数提供器。它记录会话组成，恢复指定的持久会话，并通过 Harness 服务处理人工输入。运行时为 Node，终端模式由 Ink 管理。此包在当前代码库内开发，不单独发布。

## 使用此包

在仓库根目录构建，然后启动 Bake。随附的 `tui` profile 使用 `dsh-base` 和本组合包初始化，包含 standard 预设和本地文件引用提供器。每个会话都运行在一个 agent preset 上，未用 `--preset` 指定时为 `standard`；preset 提供代理的指令、工具、技能、规划模式、目标控制、任务列表和委派。本组合包关闭 `dsh-base` 中这些行的副本，否则它们会触及每个 preset 的代理，因此 `--preset minimal` 只有自己的持久 shell 和本组合包的 `/compact`。本组合包还挂载 `cordis` preset 的 `cordis_inspect_list` 与 `cordis_inspect_query` 工具所读取的检查注册表。Bun 生成生产 JSX；`bun run start` 使用对应的 Node React/Ink 运行时执行现有产物。Bake 默认使用 `~/.bake`，可通过 `DSH_HOME` 覆盖。输入和输出必须是 TTY；设置 `CI` 时仍启用交互渲染。

```sh

bun run build

bun run start

```

使用 `bun run start --screen fullscreen`（安装版使用 `bake --screen fullscreen`）可启用可滚动的对话记录，并将输入框固定在底部。鼠标滚轮每次移动三行，PgUp/PgDn 每次移动半个视口，Ctrl+Home 跳到开头，Ctrl+End 返回最新输出。向上滚动后，新输出不会改变阅读位置；滚动回底部后恢复跟随。暂停跟随时，输入框上方一行以 `↓ 最新 · Ctrl+End` 开头，视图下方有新输出后变为 `↓ 新输出 · Ctrl+End`；点击该提示同样返回最新输出。全屏模式将鼠标事件交给 Bake，因此请用 Shift 拖动（macOS 上用 Option 拖动）选择文字。打开的详情页和选择面板保留各自的导航键。调整终端大小会重新换行可见历史，退出时恢复原来的 shell 屏幕和光标。`--screen inline` 使用终端原生滚动历史，也是默认模式；`INK_SCREEN_READER=true` 同样选择 inline 模式。全屏模式暂不支持对话记录搜索。

`/settings` 打开设置面板，设置按分区保存在设置文件（`~/.bake/settings.yaml`）中；终端自身的设置位于 `tui` 部分，`tui-runner` 配置中的值作为默认值，位于用户设置之下。面板首页列出各分区，并显示其取值或所含内容：会话（默认模型，以及挂载权限插件时的默认权限预设，两者都标为 `新会话生效`）、终端（屏幕模式，默认 inline 或 fullscreen、语言、边框、标题行是否显示目标内容、工具输出行数、菜单行数和 Ctrl+C 退出确认时长），以及组合中注册了相应设置时的代理（并行工具调用数、同时运行的子代理数、子代理嵌套深度、子代理是否可选择模型、可选择的模型，以及允许选择模型后的自动路由（测试版））、Shell（命令超时、命令可请求的最长超时和内存中保留的命令输出）和网页搜索（每次请求的搜索次数、搜索模型和搜索回答令牌上限）。高级列出除 `tui` 外所有已注册的设置命名空间，并按插件注册的 schema 编辑每个字段：开关字段直接切换，常量从列表中选择，数字和文本通过输入填写，密钥以掩码输入且只显示为 `已设置` 或 `未设置`，列表和映射则以 JSON 在 `$VISUAL` 中打开，其次是 `$EDITOR`，最后是 `vi`（Windows 上为记事本）。编辑器退出前终端归其使用，退出后面板重新绘制；可以使用带注释的 JSON，无法解析的文本或以非零状态退出的编辑器不会改动取值，并显示原因。子代理可选择的模型来自 `/model` 所列的同一模型目录：Enter 添加或移除一个模型，每次更改立即保存，选择 `完成` 或按 Escape 返回。子代理插件不接受在未允许任何模型时开启该选项，因此从空列表开启时会先询问模型，并将两者一起保存；选项开启期间最后一个模型会被保留。自动路由（测试版）让任务路由器为未指定模型的委派从这些模型中选择一个，并选择其推理强度。开启前会先说明它发送的内容：每次此类委派的任务文本和允许模型的名称会发送到路由器地址（默认为托管的 ing 路由器），而所有模型仍由用户自己的提供方运行。若 Bake 尚未登录路由器也会一并提示，并优先提供 `登录并开启`；在 `开启` 上按 Enter 则不登录直接保存。开启后，代理分区还会提供路由器账户、路由器地址、路由优先（默认 `按任务判断`，也可选质量、成本、速度或均衡）以及模型校准。校准会询问路由器如何识别每个允许的模型：匹配到的已评测模型或 `路由器未识别`、质量分、每百万令牌价格，以及 `已评估` 或 `需要提示`。在某个模型上按 Enter 可设置其质量等级、成本等级或其所服务的已评测模型，每项立即保存，每次更改后都会重新询问路由器。若为路由器已有基准数据的模型设置了质量等级，该等级会被标为未使用，因为以基准数据为准。没有已评估的模型时，列表会提示路由的委派将使用默认模型；无法连接路由器时会显示原因。路由器账户通过邮箱登录：先询问邮箱地址，路由器随即发送六位验证码，接着输入的验证码会换取一个由凭据存储保管的令牌，此后路由的委派都会携带它。首次登录即创建账户。被拒绝的地址或验证码会显示在输入框上并再次询问，按 Escape 则保留已存储的令牌不变。已登录时，该行显示账户，按 Enter 可使用其他邮箱登录或退出登录。若启动环境提供了令牌，该行改为显示其变量名，且不提供登录。每次写入只涉及对应字段，因此面板从未显示过的密钥不会丢失。在首页输入文字会搜索所有分区中的所有设置，并标明其所在位置（`Shell › 命令超时`），按 Enter 即可编辑找到的设置。上下方向键选择，Enter 打开分区、可选值列表或切换开关类设置，Tab 和 Shift-Tab 切换到下一个或上一个分区（分区以标签形式列在标题下方），Escape 返回上一页，在首页则关闭面板。可选值列表将生效中的值标为 `当前`，将默认值标为 `默认`；可输入值的设置在列表末尾提供 `输入值…`：时长接受 `500ms`、`30s`、`2m` 或 `1h`，大小接受 `64KB` 或 `1MB`，超出设置范围的值会被拒绝，并说明违反的界限。用户设置过的项还会固定显示 `恢复默认值`；分区中有任何用户设置时会提供 `将本节恢复为默认值`，确认框默认选择保留。屏幕模式和语言在下次启动时生效，此前面板将其标为 `下次启动生效`；插件只在启动时读取的命名空间，其字段同样如此标记。`--screen` 或配置中设置的 `screen` 会覆盖已保存的屏幕模式，面板将其标为 `由 --screen 指定`。其余设置立即生效，手动编辑文件也是如此。保存失败时（包括所属插件拒绝的值），面板顶部会显示原因，面板保持打开。有更改时关闭面板，会提示保存到的文件。没有设置文件时，只提供会话和终端两个分区，并提示更改仅在本次运行有效。

模型选择也会被记住。`/model` 的选择或 Shift-Tab 的切换会更改当前会话，同时作为默认模型保存到同一文件的 `agent-default-model` 部分，因此下次启动和 `/new` 都从该模型开始；恢复的会话保留其记录的模型。面板中的默认模型一行会打开同一张模型表。`/model` 先列出“最近使用”（当前模型，以及之前选过的至多四个，保存在 `tui` 部分的 `recentModels` 中），再按提供方分组列出其余模型，每组内较新的在前。每行显示模型的上下文窗口、提供推理强度时的 `思考`，以及接受图像时的 `图像`。←→ 在列表下方的一行中切换所选模型的推理强度，Enter 同时选定模型和推理强度。

Bake 没有默认提供方。尚未登录任何提供方时，会话启动时没有模型：状态行显示 `未选模型  /login 开始`，`/` 菜单首项为 `/login`，发送的消息会留在输入框中，并提示先登录。`/login` 列出配置提供的全部登录方式，并显示各自的状态和所在位置：DeepSeek API 密钥、CLIProxyAPI（地址和 API 密钥），以及 OpenAI（ChatGPT）、Anthropic（Claude Pro/Max）、GitHub Copilot、OpenRouter、Kimi 和 xAI 登录，它们也都接受 API 密钥。`/login <名称>` 直接进入某一项，可使用名称、显示名或密钥引用，不区分大小写；输错时会给出最接近的名称。每个字段是一个面板，显示提供方、所在步骤、适用时的默认值和说明。答案被拒绝时，同一面板会说明原因并再次询问：空的或格式不对的密钥会重新询问密钥，CLIProxyAPI 拒绝的密钥会重新询问密钥，无法连接的地址会回到地址并保留已输入的内容。登录后，该提供方的模型会立即出现在 `/model` 中；若会话尚无模型，第一次登录还会选中该提供方的模型并保存为默认值。`/logout [名称]` 移除已保存的密钥、CLIProxyAPI 路由和密钥，或某项登录及其添加的路由；由环境变量或 `.env` 文件提供的密钥只会被指出，因为它需要在设置它的地方修改。

Enter 提交输入；运行期间输入会引导下一步。Alt+↑ 立即发送引导，而不是等到下一步：回合进行中会提交已输入的草稿、中断当前回合，并以它开始新回合；草稿为空时，Alt+↑ 对排队输入执行同样操作。`/` 命令草稿不受影响。Shift-Tab 将所选模型的推理强度切换到该路由提供的下一档，最后一档之后回到提供器默认值，并以通知和状态栏的 `思考` 读数显示所选档位；回合进行中切换时从下一步生效，路由不支持推理强度时会给出提示。Escape 先关闭打开的补全菜单，再取消当前问题、活动命令或运行中的代理。按两次 Ctrl-C 退出：第一次会在 `doubleInterruptMs`（默认 2 秒）内显示 `再次按 Ctrl-C 退出`，时间结束或按下任何其他键时提示随即消失。粘贴只插入文字，不会提交。`/login` 打开可选择的登录目标列表，每个目标的 `已配置` 或 `未设置` 状态单独成列；`/login <target>` 直接启动该目标。选择 CLIProxyAPI 或运行 `/login cliproxyapi`，分两步输入地址和 API 密钥。再次配置时会提供已保存的地址作为默认值。Bake 会验证 `GET /v1/models?client_version=pi`，将密钥存入凭据存储，并在 `/model` 中以 `cliproxyapi/` 前缀列出返回的模型。地址可以是服务器根路径、`/v1` 或 `/backend-api`；每个模型走其上游能干净转发的协议。Claude 模型（按 id 识别，或按目录中的 `owned_by: anthropic`）使用服务器根路径下的 Anthropic Messages `/v1/messages`，使提示带上缓存断点；经代理的 Responses 转换时 Claude 无法缓存。目录列出 `xhigh` 或 `max` 强度的 Claude 模型使用带强度的自适应思考，较早的模型保留预算式思考。Kimi、Moonshot、GLM、Qwen、DeepSeek 与 MiniMax 模型使用 `/v1/chat/completions`，使代理不必自行把其工具调用历史转换为 chat 格式。OpenAI、Gemini、Grok 等其余模型使用 `/v1/responses`。只输出图片或视频的模型不会出现在 `/model` 中。该路由还带有两项面向多上游账号代理的默认值：最长 60 秒的重试延迟，使 `reset_seconds` 表明全部账号都在冷却的 `429` 会被等过去而不是结束本轮；以及会话亲和，使每个会话始终留在缓存着其提示的那个账号上。每次启动时会在终端打开后于后台重新读取代理的模型列表，因此登录后代理新增的模型也会出现在 `/model` 中；代理不再列出的模型会被移除，但当前会话、新会话默认模型或子代理允许列表正在使用的模型会保留。无法读取代理时沿用已保存的列表。再次登录可更改连接。旧版本登录写入的路由会在启动时仅凭已保存的路由升级为当前登录所写的内容：在路由缺少时补上各模型的协议、Claude 的端点与自适应思考、重试延迟以及会话亲和，并以通知列出改动。手动设置的值（包括 `false`）会被保留。设置文件只读或拒绝升级时，路由保持原样，通知改为提示运行 `/login cliproxyapi`。模型目录为空时保留原有路由。`/help` 只列出组合后的命令。`/changelog` 将根目录 `CHANGELOG.md` 中与当前运行的根包版本对应的章节输出到对话记录。空闲时 `/model` 打开模型表；`/model <provider/model> [effort]` 可直接选择路由。

运行器通过可选的 `AppProps.version` 传入根包版本。空会话在非子会话查看模式下打开时，显示带有会话行的 `BAKE v<root version>` 欢迎块。Inline 模式将其打印一次到终端滚动历史；全屏模式在对话内容出现前显示它，之后在可滚动对话记录的开头保留会话标题。恢复已有历史时不显示欢迎横幅。

新会话默认使用 `workspace-write` 和 `ask` 审批策略；显式设置的 `DSH_PERMISSION_MODE` 或权限默认值设置优先。会话的 `permissions` 投影在会话开启处显示 `权限 <模式>`：新会话显示在欢迎区块的会话行下方，恢复的会话显示在标题之后。状态行不显示该字段；之后的 `/permission` 更改由命令结果报告。`/permission` 列出可用模式，`/permission read-only`、`/permission workspace-write` 或 `/permission danger-full-access` 会立即切换当前会话。恢复会话保留已记录的模式；`/new` 使用配置的默认值。查看子会话时显示子会话自己的权限模式。未提供此投影的 profile 不显示该指示器。状态栏的 `思考` 读数显示所选模型显式指定的推理强度，或模型声明的默认强度。未提供推理控制的模型不显示强度；切换 `/model` 会更新它，恢复会话则还原已选强度。

左右方向键每次将光标移动一个可见字符。Home/End 或 Ctrl-A/E 移到当前行的开头或末尾。Backspace 删除光标前的字符，Delete 删除光标后的字符。Ctrl-J 或 Alt-Enter（Option 作为 Meta 键时为 Option-Enter）在任何终端中都插入换行，问题和登录输入框同样适用；终端以 CSI-u 报告 Shift-Enter 时（按此配置的终端会这样做），Shift-Enter 也插入换行，而大多数终端将其作为普通 Enter 发送。`/terminal-setup` 让终端在按下 Shift-Enter 时发送 Escape 加回车，即 Alt-Enter 的序列。它根据环境变量识别终端。对于 VS Code、Cursor、Windsurf、Windows Terminal、Ghostty、kitty 和 Alacritty，它先显示配置文件及将要添加的内容，用户确认后才将文件复制为 `<文件>.bak-<毫秒数>` 并添加绑定，同时保留文件原有的注释和格式。报告会列出备份文件和撤销更改的命令，并说明终端是否需要重新加载配置。再次运行时，它会报告绑定已设置，不做任何更改；若 Shift-Enter 已绑定到其他操作，它会报告并保留原绑定。对于 WezTerm、iTerm2、Apple Terminal、无法识别的终端，以及通过 SSH 或在远程编辑器窗口中运行的会话，它改为输出操作步骤，并在 macOS 上提示将 Option 用作 Meta 键以使用 Option-Enter。在 tmux 中，它设置的是 tmux 外层的终端。无论光标位于何处，Enter 都提交完整草稿。粘贴在光标处插入文字并保留换行。欢迎卡片会提示一次 Ctrl+J，并提示用 `/terminal-setup` 设置 Shift+Enter，`/help` 的末尾列出输入框的所有按键。

草稿有多行时，上下方向键将光标移到上一行或下一行，并保持所在列。补全菜单关闭时，光标在第一行按上方向键调出较早的人工输入，在最后一行按下方向键调出较新的输入；Ctrl-P/N 在补全菜单打开时也可调出历史。向前调出的多行条目以光标位于首行打开，因此再按上方向键会继续向前。历史包含当前会话中已提交的用户消息和待处理人工输入。越过最新条目向后浏览会恢复未发送的草稿及其光标位置。编辑调出的条目不会修改会话日志，调出历史也不会自动提交。设置目标后，上方向键翻过最早的条目会选中标题行中的目标并恢复未发送的草稿，按 Enter 打开完整视图；Ctrl+O 可随时打开该视图，包括正在编写草稿时。任务列表所在行位于目标上方：从选中的目标再按上方向键，或未设置目标时翻过最早的条目，即可选中该行；按 Enter 或 Ctrl+T 查看全部任务。问题和登录提示支持光标编辑，但不提供历史浏览；这些回答不会进入输入框历史。

回答问题时，用上下方向键选中选项或“其他回答”。按 Enter 选择当前选项；允许多选的问题可用空格切换选项，再按 Enter 提交。输入或粘贴文字会开始填写“其他回答”，浏览选项时这份草稿仍会显示。多选时可同时提交选中的选项和自定义文字。按 Escape 关闭问题。

在模型选择器中输入路由中的任意词进行筛选（如 `v4 flash`），使用上下方向键和 Enter 选择；只是重复路由的目录名称不会再显示在路由旁。具有推理控制的模型会打开第二个选择器，包含提供器声明的推理强度和提供器默认选项。最终选择完成后才更新模型；Escape 可取消任一阶段。选择期间若有回合开始，此次更改会取消。部分目录读取失败会显示提示；未列在建议目录中的精确路由仍可使用。

输入 `/` 可发现当前会话的命令和允许用户调用的技能。菜单优先显示可用的 `/model`、`/resume`、`/new` 和 `/clear`；尚未登录任何提供方时，`/login` 排在它们之前。输入前缀筛选，使用上下方向键选择。每行显示命令的参数占位符，`<…>` 表示必填，`[…]` 表示可选。按 Enter 运行选中的命令；需要必填参数的命令改为补全名称并附加空格，输入参数期间其用法显示在输入框下方。按 Tab 插入名称以继续编辑。输入命令及空格后，同一菜单会显示匹配的已注册参数选项，包括权限预设、`plan off`、目标子命令、带状态的登录与退出目标，以及模型路由。按 Tab 或 Enter 插入尚未输入完整的选项；完整输入某个选项时按 Enter 会提交命令。没有匹配选项时仍显示用法行。模型路由成功读取后会在本次菜单会话内缓存。按 Enter 插入选中的技能名称；若已输入完整名称，则按 Enter 提交。命令与技能重名时，已注册命令优先；`/Model` 等大写形式的命令名也会运行对应命令。既不是命令也不是技能的斜杠名称不会发送：草稿保留，并在有相近命令时提示该命令。以空格开头可将该行作为文本发送给模型。技能发现仍在加载或不完整时，无法识别的名称会照常发送。技能斜杠输入原样发送给 Harness，由其在步前阶段加载识别到的技能指令并记录到会话中。`/help` 列出所有命令及其占位符，随后列出可用技能；`/help <命令>` 显示单个命令的用法。命令结果（包括 `/model` 和 `/login`）记录在转录中的命令行下方；加载模型或登录地址等进度信息显示在提示行。

`/compact` 会在存在合适的范围时为较早的已完成历史生成摘要。运行期间，标题行以蓝色显示 `压缩历史…`，旁边是一张正在折叠的面皮，终端空间足够时会依次显示准备、生成摘要和保存阶段及已用时间；按 Escape 可取消。此时按 Enter 会将提示排入队列：它显示在待处理面板中，并在压缩完成、失败或取消后作为独立回合运行；按 Alt+↑ 会提示它已排在下一回合。其他命令需等压缩结束。命令结果会报告折叠的历史条目数和估计 token 数，或说明目前没有可压缩的历史。对话记录会以同样的蓝色标记摘要，但不显示发给模型的摘要正文。运行中的回合自动压缩上下文时，标题行同样显示蓝色的压缩状态直至结束，Enter 仍会引导该回合。

使用 `/usage` 查看 DeepSeek API 的剩余额度。结果按币种列出总额、赠送额度、充值额度及 API 调用是否可用。命令读取已配置的 DeepSeek 端点和凭据；自定义网关需要兼容的 `/user/balance` 端点。这里显示的是账户余额，不是当前对话的 token 用量。

在词首输入 `@` 可发现工作区路径。上下方向键选择；Tab 将光标处的词替换为文件引用或进入目录，并保留后续文字。含空格的路径使用 `@"path with spaces"`；目录补全将光标留在闭合引号内。Enter 提交原样草稿。发现范围由会话工作区以及 Harness 提供器配置的排除项和限制决定。缺少提供器或搜索失败时会在菜单中显示提示，仍可手动输入。

使用 `/attach notes with spaces.bin` 为下一条普通提示暂存文件。命令后经首尾去空格的全部内容视为一个原样路径，相对于会话工作区解析；不要添加 shell 引号。`/remove-attachment <编号>` 移除显示的条目，`/clear-attachments` 丢弃全部暂存条目。每条命令都会在转录中报告更改的文件或数量。Enter 将文字与附件一起发送，也可仅发送附件。PNG、JPEG、WebP 和 GIF 扩展名选择图像接收流程；Harness 验证其字节并规范化图像。其他文件保留原始字节。

附件提交期间输入框暂停编辑，直到接收流程结束。Escape 取消提交；失败或取消会保留文字、光标和暂存源数据，以便重试。`/attach` 读取期间拒绝提交，直到读取结束。代理将消息接收到收件箱后才清除暂存源数据。待处理输入和恢复后的对话记录显示附件元数据；调出历史文字不会重新暂存附件。有暂存文件时，TUI 允许运行已注册命令，除非其元数据声明 `input.attachments: true`；这类命令可能接收附件，而输入框会把暂存文件留给下一条普通提示。切换会话另行要求清空暂存区。本进程内的命令历史恢复完整提交文字，包括未写入 `command/run` 的参数；恢复会话后，没有本地文字的脱敏命令不会出现在历史中。带参数的 `/login` 从不进入历史调出。退出时丢弃未发送的源数据。

中断代理会保留排队输入。Alt+↑ 立即发送下一步和下一轮收件箱中排队的人工消息：中断正在运行的回合，并按排队顺序以这些消息开始新回合；插件上下文仍保留在队列中。待处理面板会显示此操作。上下文用量显示 Harness 预测的占用估计值，以 `~` 为前缀，包含输出增长和压缩的影响。同时，TUI 会读取该路由的自动压缩起点：组合中的压缩引擎与会话 preset 自身引擎在应用按模型策略后报告的最低阈值。此组合包把组合中的引擎设为仅手动压缩，因此只有 preset 自身的引擎会报告阈值。preset 没有自己的引擎时（例如 `minimal`），或关闭了自动压缩时，不显示该起点。`/model` 切换路由后，状态栏会暂时隐藏占用量，直到新路由报告用量；会话累计计费量仍会显示。窄终端无法容纳完整读数时显示 `上下文 ~N%`，同时保留权限标记。查看在线或已保存的子会话时，状态栏读取该子会话自己的上下文和计费量，不借用父会话的数据。输入框与状态栏之间的一行暗色文字显示此会话委派的代理总数，并以各自的颜色和活动符号列出每个子代理，包括已保存的子会话和活动的远程运行；该行始终只占一行，放不下的名称会被截断。在空输入框中按下方向键选中该行，再按 Enter 打开子代理选择器；按上方向键、左方向键或 Escape 返回输入框。“在线”表示子会话当前驻留；“工作中”依据子 Agent 状态或活动的子代理运行显示。已结束的子代理还会在“已保存”等驻留状态旁显示最新记录的结果：“已完成”、“失败”或“已停止”。只读取子会话自身的轮次边界；新轮次会清除上一结果，缺失或无法读取结果不代表成功。也可以按 Ctrl+G 或运行 `/agents`；按标签或标识筛选，再用上下方向键和 Enter 打开子代理的只读会话。父代理继续工作时，子会话记录会实时更新；Escape 返回父会话并保留未发送的草稿。父代理的审批请求会将焦点移回父会话。打开已保存的记录不会恢复子代理运行。远程运行没有本地记录或记录无法读取时，会说明无法打开的原因。状态栏首先显示模型名称；请求报告用量后，再根据令牌计量器的 `tokenUsage` 投影显示会话计费的 `输入` 和 `输出` 令牌数。输入包括未缓存、缓存读取和缓存写入的令牌。`缓存命中 N%` 是缓存读取在输入中的占比，仅当提供方报告缓存流量时显示，例如 DeepSeek 通过 `prompt_cache_hit_tokens` 报告。在 git 仓库中，状态栏还会在上下文读数之后显示当前会话工作区的分支及其未提交的更改。`WorkspaceGit` 通过 `git --no-optional-locks status --porcelain=v2 --branch` 读取：每次读取结束两秒后再读一次，显示的会话切换到其他工作区时立即读取；读取从不获取索引锁，因此不会导致代理同时执行的提交失败，运行器退出时会停止并等待这些读取结束。在仓库之外或没有 git 时不显示该字段。

在由安装脚本创建的安装中，状态栏会以 `可更新 v<版本> · /update` 提示更新的发行版，位于所有会话读数之后；窄行会在其他读数之前放弃它。结果来自在 Bake 主目录下缓存一小时（失败后为十分钟）的检查，于首帧之前读取，并在终端运行期间每十分钟在后台刷新；运行器退出时会停止并等待该计划完成。该提示从不自动安装任何内容。`/update` 会检查并在正在运行的版本旁安装新版本，在输入框上方的一行显示进度：当前步骤、随下载填充并附百分比和字节数的进度条，长度未知的步骤则显示彗星；当前会话继续运行自己的版本，状态栏随后显示 `可更新 v<版本> · 重启后生效`。源码检出不显示提示，设置 `BAKE_NO_UPDATE_CHECK=1` 可关闭检查。参见[更新安装](../../../../distribution/README.zh.md#updating-an-install)。

会话的 preset 提供规划模式时，状态栏会在模式生效期间显示“规划”；`minimal` 没有规划模式，也没有 `/plan` 和任务列表。“待进入规划”或“待退出规划”表示请求的切换仍在等待下一次被接受的步骤。这些标签读取 Harness 的规划投影，并在恢复会话或运行 `/plan` 命令后更新。

请在会话记录的工作目录中使用 `--resume <id>`，或其别名 `--session-id <id>`（headless profile 的写法）。已保存的预设为唯一依据；冲突的 `--preset` 会被拒绝。未记录预设的旧会话必须显式指定 `--preset`。未知 ID 不会创建替代会话。已在另一个 Bake 进程中打开的会话会在触碰终端之前被拒绝：启动向 stderr 输出 `dsh: <id>: 已在另一个 Bake 进程中打开；…` 及处理方法，并以状态 75（`EX_TEMPFAIL`）退出，因此在那里关闭该会话后重新运行同一命令即可成功。新建空会话遵循 Harness 的持久化策略，退出后不一定保留。恢复会话时从最后一次已记录请求恢复模型和显式推理强度；提供器默认强度保持隐式。

工作流运行时，输入框下方的委派行会显示其名称。Ctrl+G 展示已记录的工作流进度、各成员所属的工作流与阶段，并将直接委派标为“直接委派”。首个子代理启动前也能打开面板。缺少最终记录的已保存运行显示为“未完成”；重新打开会话不会将其显示为正在运行。

使用 `/resume` 或其别名 `/sessions` 选择当前工作区中保存的会话或新建会话。`/new` 和 `/clear` 直接开始新会话。绿色实心圆和 `当前` 状态标记当前会话，暗色空心圆标记按最近使用时间从新到旧排列的历史会话；每行显示会话上次使用于多久之前及其简短 ID。没有标题的会话显示为 `未命名会话`，而不是其 ID。光标初始位于最近使用的历史会话上，因此 `/resume` 后按 Enter 即可返回该会话；没有历史会话时位于当前会话上。海蓝色加号标记新建操作，它固定在列表下方，历史再长也不会被滚出视野。没有颜色时标签仍可区分。输入标题或 ID 筛选，使用上下方向键和 Enter 选择，按 Escape 取消。列表排除子代理以及由其他活动代理持有的会话。导航要求代理空闲且收件箱为空，包括插件上下文；请先完成排队工作，或按 Alt+↑ 立即发送排队的人工输入。选择器打开期间若代理开始工作或收到新的排队输入，导航会取消。准备失败或取消时仍显示当前会话。选择已在另一个 Bake 进程中打开的会话时，仍显示当前会话，并在提示行说明原因和处理方法：在那个进程中关闭它，或使用 `/new` 新建会话。

成功切换后会重置输入框及历史浏览，打开所选会话记录，并等待上一个代理句柄完成清理。Inline 模式将先前输出保留在终端回滚区；全屏模式用所选会话替换视口并跟随其最新输出，可用 `/resume` 重新打开已保存的会话。恢复会话时使用已记录的预设和最后请求的模型配置；新会话使用配置默认值。选择器不切换工作区，也不为旧会话补充预设；这类会话请使用 `--resume <id> --preset <name>`。会话列表和标题通过 Harness 服务读取；标题不可用时仍可按 ID 选择。

运行器的[配置表](../../DESIGN.md#8-configuration)包含语言、退出间隔和凭据引用。[无密钥 PTY 检查](../../scripts/pty-smoke.ts)会创建独立的临时配置和工作区，无需修改用户配置。

## 了解实现

<details>

<summary>会话和终端所有权</summary>

`session.ts` 负责注册表设置和记录的会话组成。`controller.ts` 合并查询历史与实时事件，并分发命令。`catalog.ts` 观察会话范围内的命令和技能元数据，取消已被替代的读取，并在清理时停止发现工作。`references.ts` 将路径搜索交给 `agent.ctx.fileReferences.list`，中止被替代的查询，并在关闭时等待未完成的读取结束。`model.ts` 读取提供器目录并验证精确路由和推理强度，之后控制器才更新 Harness 选择引用。`attachments.ts` 通过限定范围的文件系统暂存有界读取，将图像批次和文件存储交给 Harness，并在清理前等待不可取消的提供器调用结束。`interactions.ts` 排队处理限定范围的请求，在中止或释放时结束请求。`terminal-setup.ts` 执行 `/terminal-setup`：读取终端的配置文件，通过交互队列询问用户，备份文件，并用 `dsh-atomic-write` 写入；遇到符号链接时写入其目标，而不是替换链接本身。`terminal-bindings.ts` 是其纯逻辑部分：根据环境变量识别终端、各终端文档中的配置文件位置以及具体编辑。它通过 `jsonc.ts` 编辑带注释的 JSON，后者将文件解析为保留偏移量的节点，并在不重新格式化文件的前提下插入新条目。`navigation.ts` 在准备替代会话之前等待 `/sessions` 或 `/resume` 命令结束，重新检查旧代理的状态和收件箱，并仅在替代会话成功重放后释放旧句柄。`runner.ts` 在配置加载和会话打开的同时从独立产物加载 UI 与 Shiki 图，并在等待导航结束和释放句柄之前同步释放 Ink。`external-editor.ts` 在 Ink 的 `suspendTerminal` 将终端交给用户编辑器期间，用私有临时文件运行编辑器，并在此期间停止本进程对 stdin 的读取，使输入的行不会被本进程读走；运行器在 Ink 重新绘制之前暂停自身的重新渲染。`output.ts` 在 `NO_COLOR` 非空时移除 SGR 样式并保留终端控制序列，将 Ink 的每次渲染作为一次写入交给终端。在 inline 模式下，打印转录行的帧直接覆盖上一帧，而不是先擦除它，并让第一帧以及每次调整大小后的重放从终端最底行开始；运行器在释放终端时同步刷新它。`syntax.ts` 把 Shiki 封装为呈现层为回复代码、工具源码、结构化输出及差异调用的同步 `highlight`：常用语言在会话打开时开始加载，其他语言在首次绘制该语言的文件时加载语法，在此之前其行保持无语法颜色。它保留最近绘制的代码段，数量和文本总量（1 MiB）都有上限，更大的代码段照常绘制但不保留；运行器在等待导航结束后关闭它。启动器的致命错误释放钩子会释放同一个 Cordis effect。

运行器在挂载前解析 `screen`，全屏模式下由 Ink 管理备用屏幕。该模式下，`output.ts` 合并定位更新，不执行 inline 模式的底部定位或换行转换；进入备用缓冲区后将光标移到原点，随备用缓冲区开启 SGR 鼠标报告并在离开前关闭，并移除清除滚动历史的控制序列。退出、释放和致命错误均通过同一释放路径恢复主屏幕。

此包不声明新的持久化类型或运行时不变量：会话存储、收件箱状态和代理生命周期仍由对应的 Harness 服务管理。参见[连接说明](../../DESIGN.md)和[依赖文档](../../DEPENDENCIES.md)。

</details>

<a id="model-experience"></a>

## 模型体验

终端 profile 将新生成工具预览的 `spill-policy.maxInlineBytes` 设为 16 KiB；过大的输出由现有 spill 服务保存。内置编码预设也将文件读取所选文本限制为 16 KiB。这些限制保持已记录结果和工具 schema 不变。

此组合包省略 harness 固定的身份开场白，因此系统提示词以 preset 的 persona 开头；随附的 `standard` 与 `ptc` preset 把 agent 介绍为 Bake。普通人工输入成为已记录的用户消息。`@` 所选文件以原样路径引用保留；选择文件不会读取或注入内容。当代理具有 `read` 工具时，组合的 Harness 提供器会提供路径引用指导。显式附件成为持久化的图像或文件块。Harness 将普通文件投影为可读取的文件句柄，并为所选模型准备图像输入。命令通过 Harness 注册表负责其所有模型可见影响。只有会话 preset 自身的引擎会自动压缩历史：在上下文压力下的步骤开始前，以及上下文溢出失败之后。此组合包把基础引擎仅留给 `/compact` 使用，否则它的监听器会触及每个 preset 的代理。`minimal` 会话的历史只在用户运行 `/compact` 时才会被摘要；超出上下文窗口的请求会直接失败，而不会先压缩再重试。`minimal` 的请求只携带 preset 固定的 persona、唯一的 shell 工具和对话本身：没有工作区指令、技能目录或运行时上下文。模型选择使用 Harness 的请求路由引用；下一次请求会记录其配置和模型切换提示。批准和问题答案返回请求它们的服务；登录密钥不会进入模型输入或会话历史。

### KV Cache 影响

TUI 不构建模型请求，也不修改缓存设置。

## 已知限制与后续工作

- 同时仅显示一个根会话；会话导航仅限当前工作区。选择器读取所有匹配的会话记录和标题，但限制可见行数。

- 选择器会列出已在另一个 Bake 进程中打开的会话；拒绝发生在选中之时。两种拒绝都无法指明是哪个进程：会话的内核写锁不记录持有者。

- 不支持剪贴板图像、向已注册命令传递附件参数或内联图像预览。图像提交会检查当前所选模型；最终请求接收由 Harness 管理。

- 尚未被请求使用的模型选择不会持久化；选择不会修改配置默认值。

- 工具执行验证使用构建后的配置；源码启动的模块重复问题见[运行手册](../../PLAN.md#132-build-from-a-clean-checkout)。

- 上下文压缩后，终端回滚区保留原始输出。

- 长历史恢复有较大的瞬时内存开销；[整进程诊断](performance/README.zh.md)记录可复现的工作负载、测量结果及尚未解决的大型历史失败。
