# @dsh-tui/app

[English](README.md) | 中文

## 概要

此私有工作区包为基于 base 的 `dsh` 配置添加终端运行器和命令行参数提供器。它记录会话组成，恢复指定的持久会话，并通过 Harness 服务处理人工输入。运行时为 Node，终端模式由 Ink 管理。此包在当前代码库内开发，不单独发布。

## 使用此包

在仓库根目录构建，然后启动 Bake。随附的 `tui` profile 使用 `dsh-base` 和本组合包初始化，包含 standard 预设和本地文件引用提供器。Bun 生成生产 JSX；`bun run start` 使用对应的 Node React/Ink 运行时执行现有产物。Bake 默认使用 `~/.bake`，可通过 `DSH_HOME` 覆盖。输入和输出必须是 TTY；设置 `CI` 时仍启用交互渲染。

```sh

bun run build

bun run start

```

使用 `bun run start --screen fullscreen`（安装版使用 `bake --screen fullscreen`）可启用可滚动的对话记录，并将输入框固定在底部。PgUp/PgDn 每次移动半个视口，Ctrl+Home 跳到开头，Ctrl+End 返回最新输出。向上滚动后，新输出不会改变阅读位置；滚动回底部后恢复跟随。打开的详情页和选择面板保留各自的导航键。调整终端大小会重新换行可见历史，退出时恢复原来的 shell 屏幕和光标。`--screen inline` 使用终端原生滚动历史，也是默认模式；`INK_SCREEN_READER=true` 同样选择 inline 模式。全屏模式暂不支持鼠标滚动或对话记录搜索。

`/settings` 打开设置面板，设置按分区保存在设置文件（`~/.bake/settings.yaml`）中；终端自身的设置位于 `tui` 部分，`tui-runner` 配置中的值作为默认值，位于用户设置之下。面板首页列出各分区，并显示其取值或所含内容：会话（默认模型，以及挂载权限插件时的默认权限预设，两者都标为 `新会话生效`）、终端（屏幕模式，默认 inline 或 fullscreen、语言、边框、标题行是否显示目标内容、工具输出行数、菜单行数和 Ctrl+C 退出确认时长），以及组合中注册了相应设置时的代理（并行工具调用数、同时运行的子代理数、子代理嵌套深度，以及子代理是否可选择模型）、Shell（命令超时、命令可请求的最长超时和内存中保留的命令输出）和网页搜索（每次请求的搜索次数、搜索模型和搜索回答令牌上限）。高级列出除 `tui` 外所有已注册的设置命名空间，并按插件注册的 schema 编辑每个字段：开关字段直接切换，常量从列表中选择，数字和文本通过输入填写，密钥以掩码输入且只显示为 `已设置` 或 `未设置`，列表和映射则提示在设置文件中编辑。每次写入只涉及对应字段，因此面板从未显示过的密钥不会丢失。在首页输入文字会搜索所有分区中的所有设置，并标明其所在位置（`Shell › 命令超时`），按 Enter 即可编辑找到的设置。上下方向键选择，Enter 打开分区、可选值列表或切换开关类设置，Escape 返回上一页，在首页则关闭面板。可选值列表将生效中的值标为 `当前`，将默认值标为 `默认`；可输入值的设置在列表末尾提供 `输入值…`：时长接受 `500ms`、`30s`、`2m` 或 `1h`，大小接受 `64KB` 或 `1MB`，超出设置范围的值会被拒绝，并说明违反的界限。用户设置过的项还会固定显示 `恢复默认值`；分区中有任何用户设置时会提供 `将本节恢复为默认值`，确认框默认选择保留。屏幕模式和语言在下次启动时生效，此前面板将其标为 `下次启动生效`；插件只在启动时读取的命名空间，其字段同样如此标记。`--screen` 或配置中设置的 `screen` 会覆盖已保存的屏幕模式，面板将其标为 `由 --screen 指定`。其余设置立即生效，手动编辑文件也是如此。保存失败时（包括所属插件拒绝的值），面板顶部会显示原因，面板保持打开。有更改时关闭面板，会提示保存到的文件。没有设置文件时，只提供会话和终端两个分区，并提示更改仅在本次运行有效。

模型选择也会被记住。`/model` 的选择或 Shift-Tab 的切换会更改当前会话，同时作为默认模型保存到同一文件的 `agent-default-model` 部分，因此下次启动和 `/new` 都从该模型开始；恢复的会话保留其记录的模型。面板中的默认模型一行会打开同一个选择器。

Enter 提交输入；运行期间输入会引导下一步。Shift-Tab 将所选模型的推理强度切换到该路由提供的下一档，最后一档之后回到提供器默认值，并以通知和状态栏的 `思考` 标记显示所选档位；回合进行中切换时从下一步生效，路由不支持推理强度时会给出提示。Escape 先关闭打开的补全菜单，再取消当前问题、活动命令或运行中的代理。按两次 Ctrl-C 退出：第一次会在 `doubleInterruptMs`（默认 2 秒）内显示 `再次按 Ctrl-C 退出`，时间结束或按下任何其他键时提示随即消失。粘贴只插入文字，不会提交。`/login` 打开可选择的登录目标列表，每个目标的 `已配置` 或 `未设置` 状态单独成列；`/login <target>` 直接启动该目标。选择 CLIProxyAPI 或运行 `/login cliproxyapi`，分两步输入地址和 API 密钥。再次配置时会提供已保存的地址作为默认值。Bake 会验证 `GET /v1/models?client_version=pi`，将密钥存入凭据存储，并在 `/model` 中以 `cliproxyapi/` 前缀列出返回的模型。地址可以是服务器根路径、`/v1` 或 `/backend-api`；每个模型走其上游能干净转发的协议。Claude 模型（按 id 识别，或按目录中的 `owned_by: anthropic`）使用服务器根路径下的 Anthropic Messages `/v1/messages`，使提示带上缓存断点；经代理的 Responses 转换时 Claude 无法缓存。目录列出 `xhigh` 或 `max` 强度的 Claude 模型使用带强度的自适应思考，较早的模型保留预算式思考。Kimi、Moonshot、GLM、Qwen、DeepSeek 与 MiniMax 模型使用 `/v1/chat/completions`，使代理不必自行把其工具调用历史转换为 chat 格式。OpenAI、Gemini、Grok 等其余模型使用 `/v1/responses`。只输出图片或视频的模型不会出现在 `/model` 中。该路由还带有两项面向多上游账号代理的默认值：最长 60 秒的重试延迟，使 `reset_seconds` 表明全部账号都在冷却的 `429` 会被等过去而不是结束本轮；以及会话亲和，使每个会话始终留在缓存着其提示的那个账号上。再次登录可刷新模型或更改连接。模型目录为空时保留原有路由。`/help` 只列出组合后的命令。`/changelog` 将根目录 `CHANGELOG.md` 中与当前运行的根包版本对应的章节输出到对话记录。空闲时 `/model` 打开模型选择器；`/model <provider/model> [effort]` 可直接选择路由。

运行器通过可选的 `AppProps.version` 传入根包版本。空会话在非子会话查看模式下打开时，显示带有会话行的 `BAKE v<root version>` 欢迎块。Inline 模式将其打印一次到终端滚动历史；全屏模式在对话内容出现前显示它，之后在可滚动对话记录的开头保留会话标题。恢复已有历史时不显示欢迎横幅。

新会话默认使用 `workspace-write` 和 `ask` 审批策略；显式设置的 `DSH_PERMISSION_MODE` 或权限默认值设置优先。会话的 `permissions` 投影在会话开启处显示 `权限 <模式>`：新会话显示在欢迎区块的会话行下方，恢复的会话显示在标题之后。状态行不显示该字段；之后的 `/permission` 更改由命令结果报告。`/permission` 列出可用模式，`/permission read-only`、`/permission workspace-write` 或 `/permission danger-full-access` 会立即切换当前会话。恢复会话保留已记录的模式；`/new` 使用配置的默认值。查看子会话时显示子会话自己的权限模式。未提供此投影的 profile 不显示该指示器。`思考` 指示器显示所选模型显式指定的推理强度，或模型声明的默认强度。未提供推理控制的模型不显示强度；切换 `/model` 会更新它，恢复会话则还原已选强度。

左右方向键每次将光标移动一个可见字符。Home/End 或 Ctrl-A/E 移到当前行的开头或末尾。Backspace 删除光标前的字符，Delete 删除光标后的字符。Shift-Enter 插入换行；无论光标位于何处，Enter 都提交完整草稿。粘贴在光标处插入文字并保留换行。

补全菜单关闭时，上下方向键调出较早或较新的人工输入；Ctrl-P/N 在补全菜单打开时也可调出历史。历史包含当前会话中已提交的用户消息和待处理人工输入。越过最新条目向后浏览会恢复未发送的草稿及其光标位置。编辑调出的条目不会修改会话日志，调出历史也不会自动提交。设置目标后，上方向键翻过最早的条目会选中标题行中的目标并恢复未发送的草稿，按 Enter 打开完整视图；Ctrl+O 可随时打开该视图，包括正在编写草稿时。任务列表所在行位于目标上方：从选中的目标再按上方向键，或未设置目标时翻过最早的条目，即可选中该行；按 Enter 或 Ctrl+T 查看全部任务。问题和登录提示支持光标编辑，但不提供历史浏览；这些回答不会进入输入框历史。

回答问题时，用上下方向键选中选项或“其他回答”。按 Enter 选择当前选项；允许多选的问题可用空格切换选项，再按 Enter 提交。输入或粘贴文字会开始填写“其他回答”，浏览选项时这份草稿仍会显示。多选时可同时提交选中的选项和自定义文字。按 Escape 关闭问题。

在模型选择器中输入路由中的任意词进行筛选（如 `v4 flash`），使用上下方向键和 Enter 选择；只是重复路由的目录名称不会再显示在路由旁。具有推理控制的模型会打开第二个选择器，包含提供器声明的推理强度和提供器默认选项。最终选择完成后才更新模型；Escape 可取消任一阶段。选择期间若有回合开始，此次更改会取消。部分目录读取失败会显示提示；未列在建议目录中的精确路由仍可使用。

输入 `/` 可发现当前会话的命令和允许用户调用的技能。菜单优先显示可用的 `/model`、`/resume`、`/new` 和 `/clear`。输入前缀筛选，使用上下方向键选择。每行显示命令的参数占位符，`<…>` 表示必填，`[…]` 表示可选。按 Enter 运行选中的命令；需要必填参数的命令改为补全名称并附加空格，输入参数期间其用法显示在输入框下方。按 Tab 插入名称以继续编辑。输入命令及空格后，同一菜单会显示匹配的已注册参数选项，包括权限预设、`plan off`、目标子命令、登录目标和模型路由。按 Tab 或 Enter 插入尚未输入完整的选项；完整输入某个选项时按 Enter 会提交命令。没有匹配选项时仍显示用法行。模型路由成功读取后会在本次菜单会话内缓存。按 Enter 插入选中的技能名称；若已输入完整名称，则按 Enter 提交。命令与技能重名时，已注册命令优先；`/Model` 等大写形式的命令名也会运行对应命令。既不是命令也不是技能的斜杠名称不会发送：草稿保留，并在有相近命令时提示该命令。以空格开头可将该行作为文本发送给模型。技能发现仍在加载或不完整时，无法识别的名称会照常发送。技能斜杠输入原样发送给 Harness，由其在步前阶段加载识别到的技能指令并记录到会话中。`/help` 列出所有命令及其占位符，随后列出可用技能；`/help <命令>` 显示单个命令的用法。命令结果（包括 `/model` 和 `/login`）记录在转录中的命令行下方；加载模型或登录地址等进度信息显示在提示行。

`/compact` 会在存在合适的范围时为较早的已完成历史生成摘要。运行期间，终端空间足够时会依次显示准备、生成摘要和保存阶段及已用时间；按 Escape 可取消。压缩期间按 Enter 不会将另一条提示排入队列，草稿会保留以便稍后提交。命令结果会报告折叠的历史条目数和估计 token 数，或说明目前没有可压缩的历史。对话记录会标记摘要，但不显示发给模型的摘要正文。

使用 `/usage` 查看 DeepSeek API 的剩余额度。结果按币种列出总额、赠送额度、充值额度及 API 调用是否可用。命令读取已配置的 DeepSeek 端点和凭据；自定义网关需要兼容的 `/user/balance` 端点。这里显示的是账户余额，不是当前对话的 token 用量。

在词首输入 `@` 可发现工作区路径。上下方向键选择；Tab 将光标处的词替换为文件引用或进入目录，并保留后续文字。含空格的路径使用 `@"path with spaces"`；目录补全将光标留在闭合引号内。Enter 提交原样草稿。发现范围由会话工作区以及 Harness 提供器配置的排除项和限制决定。缺少提供器或搜索失败时会在菜单中显示提示，仍可手动输入。

使用 `/attach notes with spaces.bin` 为下一条普通提示暂存文件。命令后经首尾去空格的全部内容视为一个原样路径，相对于会话工作区解析；不要添加 shell 引号。`/remove-attachment <编号>` 移除显示的条目，`/clear-attachments` 丢弃全部暂存条目。每条命令都会在转录中报告更改的文件或数量。Enter 将文字与附件一起发送，也可仅发送附件。PNG、JPEG、WebP 和 GIF 扩展名选择图像接收流程；Harness 验证其字节并规范化图像。其他文件保留原始字节。

附件提交期间输入框暂停编辑，直到接收流程结束。Escape 取消提交；失败或取消会保留文字、光标和暂存源数据，以便重试。`/attach` 读取期间拒绝提交，直到读取结束。代理将消息接收到收件箱后才清除暂存源数据。待处理输入和恢复后的对话记录显示附件元数据；调出历史文字不会重新暂存附件。有暂存文件时，TUI 允许运行已注册命令，除非其元数据声明 `input.attachments: true`；这类命令可能接收附件，而输入框会把暂存文件留给下一条普通提示。切换会话另行要求清空暂存区。本进程内的命令历史恢复完整提交文字，包括未写入 `command/run` 的参数；恢复会话后，没有本地文字的脱敏命令不会出现在历史中。带参数的 `/login` 从不进入历史调出。退出时丢弃未发送的源数据。

中断代理会保留排队输入。`/clear-pending` 丢弃下一步和下一轮收件箱中排队的人工消息，插件上下文仍保留在队列中。待处理面板会显示此操作。上下文用量显示 Harness 预测的占用估计值，以 `~` 为前缀，包含输出增长和压缩的影响。`/model` 切换路由后，状态栏会暂时隐藏占用量，直到新路由报告用量；会话累计计费量仍会显示。窄终端无法容纳完整读数时显示 `上下文 ~N%`，同时保留权限标记。查看在线或已保存的子会话时，状态栏读取该子会话自己的上下文和计费量，不借用父会话的数据。输入框与状态栏之间的一行暗色文字显示此会话委派的代理总数，并以各自的颜色和活动符号列出每个子代理，包括已保存的子会话和活动的远程运行；该行始终只占一行，放不下的名称会被截断。在空输入框中按下方向键选中该行，再按 Enter 打开子代理选择器；按上方向键、左方向键或 Escape 返回输入框。“在线”表示子会话当前驻留；“工作中”依据子 Agent 状态或活动的子代理运行显示。已结束的子代理还会在“已保存”等驻留状态旁显示最新记录的结果：“已完成”、“失败”或“已停止”。只读取子会话自身的轮次边界；新轮次会清除上一结果，缺失或无法读取结果不代表成功。也可以按 Ctrl+G 或运行 `/agents`；按标签或标识筛选，再用上下方向键和 Enter 打开子代理的只读会话。父代理继续工作时，子会话记录会实时更新；Escape 返回父会话并保留未发送的草稿。父代理的审批请求会将焦点移回父会话。打开已保存的记录不会恢复子代理运行。远程运行没有本地记录或记录无法读取时，会说明无法打开的原因。状态栏首先显示模型名称；请求报告用量后，再根据令牌计量器的 `tokenUsage` 投影显示会话计费的 `输入` 和 `输出` 令牌数。输入包括未缓存、缓存读取和缓存写入的令牌。`缓存命中 N%` 是缓存读取在输入中的占比，仅当提供方报告缓存流量时显示，例如 DeepSeek 通过 `prompt_cache_hit_tokens` 报告。在 git 仓库中，状态栏还会在上下文读数之后显示当前会话工作区的分支及其未提交的更改。`WorkspaceGit` 通过 `git --no-optional-locks status --porcelain=v2 --branch` 读取：每次读取结束两秒后再读一次，显示的会话切换到其他工作区时立即读取；读取从不获取索引锁，因此不会导致代理同时执行的提交失败，运行器退出时会停止并等待这些读取结束。在仓库之外或没有 git 时不显示该字段。

在由安装脚本创建的安装中，状态栏会以 `可更新 v<版本> · /update` 提示更新的发行版；它是最后一个有界字段，也是窄行最先放弃的字段。结果来自在 Bake 主目录下缓存一小时（失败后为十分钟）的检查，于首帧之前读取，并在终端运行期间每十分钟在后台刷新；运行器退出时会停止并等待该计划完成。该提示从不自动安装任何内容。`/update` 会检查并在正在运行的版本旁安装新版本，在输入框上方的一行以逐渐烤熟的面包显示进度，旁边是当前步骤和下载百分比；当前会话继续运行自己的版本，状态栏随后显示 `可更新 v<版本> · 重启后生效`。源码检出不显示提示，设置 `BAKE_NO_UPDATE_CHECK=1` 可关闭检查。参见[更新安装](../../../../distribution/README.zh.md#updating-an-install)。

组合配置提供规划模式时，状态栏会在模式生效期间显示“规划”。“待进入规划”或“待退出规划”表示请求的切换仍在等待下一次被接受的步骤。这些标签读取 Harness 的规划投影，并在恢复会话或运行 `/plan` 命令后更新。

请在会话记录的工作目录中使用 `--resume <id>`，或其别名 `--session-id <id>`（headless profile 的写法）。已保存的预设为唯一依据；冲突的 `--preset` 会被拒绝。未记录预设的旧会话必须显式指定 `--preset`。未知 ID 不会创建替代会话。新建空会话遵循 Harness 的持久化策略，退出后不一定保留。恢复会话时从最后一次已记录请求恢复模型和显式推理强度；提供器默认强度保持隐式。

使用 `/resume` 或其别名 `/sessions` 选择当前工作区中保存的会话或新建会话。`/new` 和 `/clear` 直接开始新会话。绿色实心圆和 `当前` 状态标记当前会话，暗色空心圆标记按最近使用时间从新到旧排列的历史会话；每行显示会话上次使用于多久之前及其简短 ID。没有标题的会话显示为 `未命名会话`，而不是其 ID。光标初始位于最近使用的历史会话上，因此 `/resume` 后按 Enter 即可返回该会话；没有历史会话时位于当前会话上。海蓝色加号标记新建操作，它固定在列表下方，历史再长也不会被滚出视野。没有颜色时标签仍可区分。输入标题或 ID 筛选，使用上下方向键和 Enter 选择，按 Escape 取消。列表排除子代理以及由其他活动代理持有的会话。导航要求代理空闲且收件箱为空，包括插件上下文；请先完成排队工作，或使用 `/clear-pending` 清除人工输入。选择器打开期间若代理开始工作或收到新的排队输入，导航会取消。准备失败或取消时仍显示当前会话。

成功切换后会重置输入框及历史浏览，打开所选会话记录，并等待上一个代理句柄完成清理。Inline 模式将先前输出保留在终端回滚区；全屏模式用所选会话替换视口并跟随其最新输出，可用 `/resume` 重新打开已保存的会话。恢复会话时使用已记录的预设和最后请求的模型配置；新会话使用配置默认值。选择器不切换工作区，也不为旧会话补充预设；这类会话请使用 `--resume <id> --preset <name>`。会话列表和标题通过 Harness 服务读取；标题不可用时仍可按 ID 选择。

运行器的[配置表](../../DESIGN.md#8-configuration)包含语言、退出间隔和凭据引用。[无密钥 PTY 检查](../../scripts/pty-smoke.ts)会创建独立的临时配置和工作区，无需修改用户配置。

<a id="understand-the-implementation"></a>

## 了解实现

<details>

<summary>会话和终端所有权</summary>

`session.ts` 负责注册表设置和记录的会话组成。`controller.ts` 合并查询历史与实时事件，并分发命令。`catalog.ts` 观察会话范围内的命令和技能元数据，取消已被替代的读取，并在清理时停止发现工作。`references.ts` 将路径搜索交给 `agent.ctx.fileReferences.list`，中止被替代的查询，并在关闭时等待未完成的读取结束。`model.ts` 读取提供器目录并验证精确路由和推理强度，之后控制器才更新 Harness 选择引用。`attachments.ts` 通过限定范围的文件系统暂存有界读取，将图像批次和文件存储交给 Harness，并在清理前等待不可取消的提供器调用结束。`interactions.ts` 排队处理限定范围的请求，在中止或释放时结束请求。`navigation.ts` 在准备替代会话之前等待 `/sessions` 或 `/resume` 命令结束，重新检查旧代理的状态和收件箱，并仅在替代会话成功重放后释放旧句柄。`runner.ts` 在等待导航结束和释放句柄之前同步释放 Ink。`output.ts` 在 `NO_COLOR` 非空时移除 SGR 样式并保留终端控制序列，将 Ink 的每次渲染作为一次写入交给终端。在 inline 模式下，打印转录行的帧直接覆盖上一帧，而不是先擦除它，并让第一帧以及每次调整大小后的重放从终端最底行开始；运行器在释放终端时同步刷新它。`syntax.ts` 把 Shiki 封装为呈现层为回复代码、工具源码、结构化输出及差异调用的同步 `highlight`：常用语言在第一帧之前加载，其他语言在首次绘制该语言的文件时加载语法，在此之前其行保持无语法颜色。它保留最近绘制的代码段，数量和文本总量（1 MiB）都有上限，更大的代码段照常绘制但不保留；运行器在等待导航结束后关闭它。启动器的致命错误释放钩子会释放同一个 Cordis effect。

运行器在挂载前解析 `screen`，全屏模式下由 Ink 管理备用屏幕。该模式下，`output.ts` 合并定位更新，不执行 inline 模式的底部定位或换行转换；进入备用缓冲区后将光标移到原点，并移除清除滚动历史的控制序列。退出、释放和致命错误均通过同一释放路径恢复主屏幕。

此包不声明新的持久化类型或运行时不变量：会话存储、收件箱状态和代理生命周期仍由对应的 Harness 服务管理。参见[连接说明](../../DESIGN.md)和[依赖文档](../../DEPENDENCIES.md)。

</details>

<a id="model-experience"></a>

## 模型体验

普通人工输入成为已记录的用户消息。`@` 所选文件以原样路径引用保留；选择文件不会读取或注入内容。当代理具有 `read` 工具时，组合的 Harness 提供器会提供路径引用指导。显式附件成为持久化的图像或文件块。Harness 将普通文件投影为可读取的文件句柄，并为所选模型准备图像输入。命令通过 Harness 注册表负责其所有模型可见影响。模型选择使用 Harness 的请求路由引用；下一次请求会记录其配置和模型切换提示。批准和问题答案返回请求它们的服务；登录密钥不会进入模型输入或会话历史。

### KV Cache 影响

TUI 不构建模型请求，也不修改缓存设置。

<a id="known-limitations"></a>

## 已知限制与后续工作

- 同时仅显示一个根会话；会话导航仅限当前工作区。选择器读取所有匹配的会话记录和标题，但限制可见行数。

- 不支持剪贴板图像、向已注册命令传递附件参数或内联图像预览。图像提交会检查当前所选模型；最终请求接收由 Harness 管理。

- 尚未被请求使用的模型选择不会持久化；选择不会修改配置默认值。

- 工具执行验证使用构建后的配置；源码启动的模块重复问题见[运行手册](../../PLAN.md#132-build-from-a-clean-checkout)。

- 上下文压缩后，终端回滚区保留原始输出。

- 长历史恢复有较大的瞬时内存开销；[整进程诊断](performance/README.zh.md)记录可复现的工作负载、测量结果及尚未解决的大型历史失败。
