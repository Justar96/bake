# @dsh-tui/app

English | [中文](README.zh.md)

## Summary

This private workspace bundle adds a terminal runner and flag provider to a base-backed `dsh` profile. It records session composition, resumes exact persisted sessions, and routes human input through harness services. The runtime is Node; Ink owns terminal modes. The bundle is developed inside this checkout and is not published independently.

## Use this package

Build from the repository root, then start Bake. The shipped `tui` profile initializes with `dsh-base` and this bundle, including the standard preset and local file-reference provider. Every session runs on an agent preset, `standard` unless `--preset` names another, and the preset supplies the agent's instructions, tools, skills, goal controls, task list, and delegation. The bundle turns off `dsh-base`'s copies of those rows, which would otherwise reach every preset's agent, so `--preset minimal` has only its persistent shell and the bundle's `/compact`. The bundle also mounts the inspection registry that the `cordis` preset's `cordis_inspect_list` and `cordis_inspect_query` tools read. Bun emits production JSX; `bun run start` runs existing artifacts with the matching Node React/Ink runtime. Bake uses `~/.bake` unless `DSH_HOME` is set. TTY input and output are required; interactive rendering remains enabled when `CI` is set.

```sh

bun run build

bun run start

```

Use `bun run start --screen fullscreen` (or `bake --screen fullscreen` in an install) for a scrollable transcript with the input pinned at the bottom. The mouse wheel moves three rows, PgUp/PgDn move half a viewport, Ctrl+Home goes to the beginning, and Ctrl+End returns to the newest output. Scrolling up pauses following while new output arrives; scrolling back to the bottom resumes it. While paused, the row above the input leads with `↓ Latest · Ctrl+End`, which turns to `↓ New output · Ctrl+End` once output arrives below the view; clicking it also returns to the newest output. Fullscreen reports the mouse to Bake, so select text with Shift-drag, or Option-drag on macOS. Open sheets and selection panels keep their own navigation keys. Resizing rewraps visible history, and exit restores the shell screen and cursor. `--screen inline` uses native terminal scrollback and is the default; `INK_SCREEN_READER=true` also selects inline mode. Fullscreen has no transcript search yet.

`/settings` opens a panel of settings, saved in the settings file (`~/.bake/settings.yaml`) section by section; the terminal's own are in its `tui` section, where the `tui-runner` profile values are the defaults under the user's. The panel's first page lists sections, each with its values or what it holds: Session (the default model and, when the permission plugin is mounted, the default access preset, both marked `New sessions`), Terminal (the screen mode, inline by default or fullscreen, language, borders, whether the goal's objective is named on the header, tool output lines, menu rows, and the Ctrl+C quit window), then, when the composition registers them, Agent (parallel tool calls, subagents running at once, subagent nesting depth, whether subagents may pick a model, the models they may pick, and, once they may, Auto routing (beta)), Shell (the command timeout, the longest timeout a command may ask for, and the command output kept in memory), and Web search (searches per request, the search model, and its answer token limit). Advanced lists every registered settings namespace but `tui` and edits each field from the schema its plugin registered: on/off fields flip, constants are picked from a list, numbers and text are typed, secrets are typed masked and shown only as `Set` or `Not set`, and lists and maps open as JSON in `$VISUAL`, then `$EDITOR`, then `vi` (Notepad on Windows). The editor has the terminal until it exits, and the panel is drawn again after it; JSON with comments is accepted, and text that does not parse or an editor that exits non-zero leaves the value unchanged with the reason shown. The models subagents may pick come from the same catalog `/model` lists: Enter adds or removes one, each change is saved at once, and `Done` or Escape returns. The subagent plugin refuses the choice switched on with no model allowed, so switching it on from an empty list asks for the models first and saves both together, and the last model is kept while the choice is on. Auto routing (beta) lets the task router pick one of those models, and its reasoning effort, for a delegation that names none. Switching it on first says what it sends: each such delegation's task text and the names of the allowed models go to the router's URL, the hosted ing router by default, while the user's own providers still run every model. It also says when Bake is not signed in to the router, and then offers `Sign in and turn on` first; Enter on `Turn on` saves it without signing in. While it is on, the Agent section also offers Router account, the router's URL, the routing priority (`From the task` by default, or quality, cost, speed, or balanced), and Model calibration. Calibration asks the router how it sees each allowed model: the benchmarked model it matched or `unknown to the router`, its quality score, its price per million tokens, and `Ranked` or `Needs a hint`. Enter on a model sets its quality tier, its cost tier, or the benchmarked model it serves, each saved at once, and the list is asked again after every change. A quality tier set on a model the router has benchmarks for is marked as unused, since benchmarks win. When no model is ranked, the list warns that routed delegations keep the default model; a router that cannot be reached shows why. Router account signs in by email: it asks for an address, the router emails a six-digit code, and the code typed next is traded for a token the credential store keeps, so routed delegations send it from then on. A first sign-in creates the account. A refused address or code is shown on the field and asked again, and Escape leaves the stored token as it was. Signed in, the row names the account, and Enter offers signing in with another email or signing out. When the launch environment supplies the token, the row names its variable instead and signing in is not offered. Every write names only its field, so a secret the panel never showed is never lost. Typing on the first page searches every setting in every section, named by where it lives (`Shell › Command timeout`), and Enter edits the one found. Up/Down choose, Enter opens a section, a value list, or flips an on/off setting, Tab and Shift-Tab move to the next or previous section, named on a row of tabs under the title, and Escape returns to the page above and closes the panel from the first. A value list marks the value in force as `Current` and the default as `Default`, and ends with `Enter a value…` where the setting takes a typed one: durations accept `500ms`, `30s`, `2m`, or `1h`, sizes `64KB` or `1MB`, and a value outside the setting's bounds is refused with the bound it breaks. A setting the user has set also offers a pinned `Reset to default`, and a section with any offers `Reset this section to defaults` after a confirmation that defaults to keeping them. Screen mode and language apply at the next launch, and the panel marks them `Next launch` until then, as it does every field of a namespace whose plugin reads it only at start; `--screen`, or a `screen` set in the profile, overrides the saved screen, which the panel marks `Set by --screen`. The others apply at once, including edits made to the file by hand. A failed save, including a value the owning plugin refuses, shows its reason at the top of the panel and leaves the panel open. Closing the panel after a change names the file it was saved to. Without a settings file, only Session and Terminal are offered, and the panel says the changes last until exit.

The model is remembered too. A `/model` choice or a Shift-Tab step changes the current session and is also saved as the default model in the `agent-default-model` section of the same file, so the next launch and `/new` start on it; a resumed session keeps the model it recorded. The panel's default model row opens the same sheet. `/model` lists Recent first (the current model and up to four chosen before, kept as `recentModels` in the `tui` section), then each provider's models under its name, newest first. Each row shows the model's context window, `think` when it offers reasoning efforts, and `image` when it accepts images. ←→ step the selected model's reasoning effort on the row under the list, and Enter chooses the model and effort together.

Bake has no default provider. A session with nothing signed in starts on no model: the status line reads `no model  /login to start`, `/login` leads the `/` menu, and a message stays in the composer with a notice saying to sign in. `/login` lists every sign-in the profile offers, each with its status and where it lives: a DeepSeek API key, CLIProxyAPI (address and API key), and the OpenAI (ChatGPT), Anthropic (Claude Pro/Max), GitHub Copilot, OpenRouter, Kimi, and xAI sign-ins, each of which also takes an API key. `/login <name>` goes straight to one, by its name, label, or key reference in any case, and a typo is answered with the nearest name. Each field is one panel naming the provider, its step, a default where one applies, and guidance. A refused answer asks again in the same panel with the reason: an empty or malformed key asks for the key, a key CLIProxyAPI rejects asks for the key, and an address it cannot reach returns to the address with what was typed. A signed-in provider's models reach `/model` at once, and the first sign-in of a session with no model also selects that provider's model and saves it as the default. `/logout [name]` removes a stored key, the CLIProxyAPI route and key, or a sign-in and the route it added; a key the environment or a `.env` file supplies is named instead, since it is changed where it is set.

Enter submits; while working it steers the next step. Alt+↑ sends steering now instead of at the next step: a draft typed during a turn is submitted, the turn is interrupted, and a new turn starts with it, and with an empty draft Alt+↑ does the same for queued input. A `/` command draft is left alone. Shift-Tab steps the selected model's reasoning effort to the next the route offers, wrapping to the provider default, and shows the choice as a notice and in the status line's `think` reading; a change during a turn takes effect from its next step, and a route without efforts says so. Escape closes an open completion menu, then cancels the displayed question, active command, or running Agent. Press Ctrl-C twice to quit: the first shows `Press Ctrl-C again to quit` for `doubleInterruptMs` (2 seconds by default), and the prompt goes when that window ends or when any other key is pressed. Paste inserts text without submitting. `/login` opens a selectable sign-in target picker, with each target's `Configured` or `Not set` state in its own column; `/login <target>` starts that target directly. Choose CLIProxyAPI, or run `/login cliproxyapi`, to enter its URL and API key in two steps. The saved URL is offered when reconfiguring. Bake validates `GET /v1/models?client_version=pi`, stores the key in its credential store, and adds the returned models under `cliproxyapi/` to `/model`. The URL may be a server root, `/v1`, or `/backend-api` address; each model is served over the protocol its upstream relays cleanly. Claude models — by id, or by the listing's `owned_by: anthropic` — use Anthropic Messages at `/v1/messages` on the server root, so their prompts carry cache breakpoints; over the proxy's Responses translator Claude caches nothing. Claude models that list `xhigh` or `max` efforts take adaptive thinking with an effort level; older ones keep budget thinking. Kimi, Moonshot, GLM, Qwen, DeepSeek, and MiniMax models use `/v1/chat/completions` so that the proxy never translates their tool-call history to chat itself. OpenAI, Gemini, Grok, and the rest use `/v1/responses`. Models that produce only images or video are left out of `/model`. The route also carries two defaults for a proxy that balances several upstream accounts: a retry delay of up to 60 seconds, so a `429` whose `reset_seconds` says every account is cooling down is waited out instead of ending the turn, and session affinity, so each session stays on the one account whose prompt cache holds it. Each launch reads the proxy's list again in the background, after the terminal opens, so a model the proxy started serving after the login reaches `/model`; a model the proxy stops listing is dropped unless the session, the new-session default, or the subagent allow-list uses it. A proxy that cannot be read keeps the saved list. Repeat the login to change the connection. A route an earlier release's login wrote is upgraded at launch to what the current login writes, from the saved route alone: each model's protocol, Claude's endpoint and adaptive thinking, the retry delay, and session affinity are filled in where the route lacks them, and a notice names what changed. A value set by hand, including `false`, is kept. When the settings file is read-only or refuses the upgrade, the route stays as it was and the notice asks for `/login cliproxyapi` instead. An empty model catalog leaves the existing route unchanged. `/help` lists only the composed commands. `/changelog` writes the running root package version’s section of the root `CHANGELOG.md` to the transcript. `/model` opens the model sheet while idle; `/model <provider/model> [effort]` selects a route directly.

The runner supplies the root package version through optional `AppProps.version`. An empty session outside child inspection opens with a `BAKE v<root version>` welcome block carrying the session line. Inline mode prints it once into terminal scrollback. Fullscreen shows it until conversation content arrives, then keeps the session heading at the beginning of the scrollable transcript. Resumed history has no welcome banner.

New sessions default to `workspace-write` with approval policy `ask`; explicit `DSH_PERMISSION_MODE` or permission-default settings take precedence. The session's `permissions` projection names `Access <mode>` where the session opens: under the session line in a new session's welcome block, or after the heading of a resumed session. It is not on the status line; a later `/permission` change is reported by the command's result. `/permission` lists the modes, and `/permission read-only`, `/permission workspace-write`, or `/permission danger-full-access` changes the current session immediately. Resume preserves its recorded mode; `/new` uses the configured default. Child inspection shows the child’s own permission mode. Profiles without that projection omit the indicator. The status line's `think` reading reports the selected model’s explicit reasoning effort, or its advertised default. Models with no reasoning controls show no level; switching `/model` updates it, and resume restores the selected level.

Left/Right moves the cursor by one visible character. Home/End or Ctrl-A/E moves to the current line’s start/end. Backspace deletes before the cursor; Delete deletes after it. Ctrl-J or Alt-Enter (Option-Enter where Option sends Meta) inserts a newline in any terminal, as do the question and sign-in inputs; Shift-Enter does too where the terminal reports it as CSI-u, as terminals configured for it do, while most send it as a plain Enter. `/terminal-setup` makes the terminal send Escape and a carriage return, the Alt-Enter sequence, for Shift-Enter. It identifies the terminal from the environment. For VS Code, Cursor, Windsurf, Windows Terminal, Ghostty, kitty, and Alacritty, it shows the configuration file and the lines it would add, and only after the user accepts does it copy the file to `<file>.bak-<milliseconds>` and add the binding, keeping the file's comments and layout. The report names the backup and the command that undoes the change, and says whether the terminal must reload its configuration. Run again, it reports the binding already set and changes nothing; a Shift-Enter binding to anything else is reported and left in place. For WezTerm, iTerm2, Apple Terminal, a terminal it cannot identify, and a session over SSH or in a remote editor window, it prints the steps instead, with Option as Meta for Option-Enter on macOS. Inside tmux it sets up the terminal around tmux. Enter submits the entire draft from any cursor position. Paste inserts at the cursor and preserves line breaks. A paste over 800 characters or of three lines or more shows as one placeholder, such as `[Pasted text #1 +42 lines]`; the cursor steps over it as one character, one Backspace or Delete removes it, and Enter submits the pasted text in its place. A paste that is exactly one PNG, JPEG, WebP, or GIF path, as terminals send a dropped file (quoted, backslash-escaped, or a `file://` URL), stages that image and shows `[Image #N]`; a path that cannot be staged stays text. Ctrl-V, or a paste that arrives empty, stages the clipboard's image through `wl-paste`, `xclip`, AppleScript, or PowerShell. Erasing an `[Image #N]` placeholder unstages its image, and a submitted prompt keeps the placeholder text beside the image. The welcome card names Ctrl+J once, with `/terminal-setup` for Shift+Enter, and `/help` ends with every composer key.

In a draft of several rows, Up/Down moves the caret to the row above or below, keeping its column. From the first row, Up recalls older human input, and from the last row, Down recalls newer input, when completion is closed; Ctrl-P/N recalls it even with completion open. An older entry of several rows opens with the caret on its first row, so the next Up keeps going back. Recall includes committed user messages and pending human input from the current session. Browsing past the newest entry restores the unsent draft and its cursor. Editing a recalled entry leaves the Session log unchanged, and recall never submits automatically. While a goal is set, Up past the oldest entry selects it on the header and restores the unsent draft, and Enter opens its full view; Ctrl+O opens that view from anywhere, including over a draft. The task list's row sits above the goal: Up from the selected goal, or past the oldest entry when no goal is set, selects it, and Enter or Ctrl+T opens every task. Questions and login prompts have cursor editing but no history recall; their answers stay out of composer history.

For a question, use Up/Down to focus an option or Other answer. Enter chooses the focused option; for a question allowing several answers, Space toggles options and Enter submits them. Typing or pasting starts an Other answer, which stays visible while you browse options. For several answers, Other text can be submitted together with selected options. Escape dismisses the question.

In the model picker, type any words of a route to filter (`v4 flash`) and use Up/Down and Enter to choose; a catalog name that only restates the route is not repeated beside it. Models with reasoning controls open a second picker containing the provider’s advertised efforts and a provider-default option. The selection changes only after the final choice; Escape cancels either stage. A turn starting during selection cancels the change. Partial catalog failures remain visible, and exact routes remain valid even when absent from advisory catalogs.

Type `/` to discover the current session’s commands and user-invocable skills. The menu shows `/model`, `/resume`, `/new`, and `/clear` first when available, after `/login` while nothing is signed in. Type a prefix to filter and use Up/Down to choose. Each row shows the command’s argument placeholder, where `<…>` is required and `[…]` optional. Enter runs the selected command; a command whose input is required is filled in with a trailing space instead, and its usage stays under the composer while the arguments are typed. Tab inserts the name for editing. After a command and a space, the same menu offers matching registered argument choices: permission presets, `plan off`, goal subcommands, sign-in and sign-out targets with their status, and model routes. Tab or Enter inserts a partial choice; Enter on an exact complete choice submits the line. If no choices match, the usage row stays visible. Model routes are read once per menu session after a successful lookup. Enter inserts a selected skill name, or submits it when its full name is already typed. Registered commands take precedence over skills with the same name, and a capitalized command name such as `/Model` runs that command. A slash name that is neither a command nor a skill is not sent: the draft stays, and a notice names the nearest command when one is close. Start the line with a space to send it to the model as text. While skill discovery is loading or incomplete, unrecognized names pass through. Skill slash input is sent unchanged to the Harness, which loads recognized skill instructions at its pre-step boundary and records them in the Session. `/help` lists every command with its placeholder, followed by the available skills; `/help <command>` shows one command’s usage. Command outcomes, including those of `/model` and `/login`, commit to the transcript under the command row; progress such as model loading or a sign-in URL uses the notice line.

`/compact` summarizes older completed history when a useful range exists. While it runs, the header shows `Compacting history…` in blue beside a sheet of dough being folded, then preparation, summarization, and saving with elapsed time when space allows; Escape cancels the attempt. Enter queues a prompt meanwhile: it waits on the pending panel and runs as its own turn once compaction finishes, fails, or is cancelled, and Alt+↑ says it already runs next. Other commands wait until compaction ends. The command result reports the number of history items and estimated tokens folded, or says when no history is compactable. The transcript marks the summary in the same blue without displaying its model-facing text. When a running turn compacts its context automatically, the header shows the same blue compaction until it ends, and Enter still steers the turn.

Use `/usage` to read remaining DeepSeek API credit. The result lists total, granted, and topped-up balances by currency and whether API calls are available. It reads the configured DeepSeek endpoint and credential; a custom gateway needs a compatible `/user/balance` endpoint. This is account balance, not token usage for the current conversation.

Type `@` at the start of a word to discover workspace paths. Up/Down selects; Tab replaces the token at the cursor with a file reference or descends into a directory, preserving subsequent text. Paths with spaces use `@"path with spaces"`; directory completion leaves the cursor inside the closing quote. Enter submits the exact draft. Discovery is bounded by the session workspace and the Harness provider’s configured exclusions and limits. Missing providers and search failures appear in the menu without preventing manual input.

Use `/attach notes with spaces.bin` to stage a file for the next ordinary prompt. The entire trimmed remainder is one literal path, relative to the session workspace; do not add shell quotes. `/remove-attachment <number>` removes the displayed item, and `/clear-attachments` discards all staged items. Each command reports the file or count changed in the transcript. Enter sends text and attachments together, including an attachment-only prompt. PNG, JPEG, WebP, and GIF extensions select image admission; the Harness validates their bytes and normalizes images. Other files retain their exact bytes.

Attachment submission holds the composer until admission finishes. Escape cancels it; failures and cancellation preserve the text, cursor, and staged sources for retry. Submission during `/attach` reads is refused until the read settles. Sources clear after the Agent accepts the message into its inbox. Pending input and resumed transcripts show attachment metadata; recalling text does not restage attachments. While files are staged, the TUI allows registered commands unless their metadata declares `input.attachments: true`; those commands could consume attachment input, which this composer reserves for the next ordinary prompt. Session navigation separately requires an empty draft. Local command recall restores the submitted line, including arguments omitted from `command/run`; after resume, redacted commands without a local line are skipped. `/login` with arguments is never recalled. Unsaved sources disappear on exit.

Agent interruption retains queued input. Alt+↑ sends queued human messages from both the next-step and next-turn inboxes now: a running turn is interrupted and a new turn starts with them, in the order they were queued; plugin context remains queued. The pending panel displays this action. Context usage shows the Harness’s projected occupancy as an estimate prefixed with `~`, including output growth and compaction. With it, the TUI reads where automatic compaction starts for that route: the lowest threshold that the composition's compaction engine and the session preset's own engine report, after any per-model policy. This bundle makes the composition's engine manual-only, so only the preset's own engine reports one. Nothing is shown under a preset without its own engine, such as `minimal`, or with automatic compaction disabled. When `/model` changes routes, the status line withholds occupancy until that route reports usage; session-wide billed totals remain visible. A narrow terminal shows `ctx ~N%` when the full reading cannot fit beside the access boundary. Child inspection reads its own context and billed totals, whether the child is live or saved, without borrowing the parent’s. A dim row between the input and the status line shows this session’s delegated agent count and names each child with its activity glyph in its own colour, including saved children and active remote runs; it stays one line and cuts names that do not fit. From an empty prompt, press Down to select it, then Enter to open the child picker; Up, Left, or Escape returns to the prompt. “Live” means the child session is resident; “Working” follows the child Agent or an active subagent run. Settled children also show their latest recorded outcome: “Completed”, “Failed”, or “Stopped”, alongside residency such as “Saved”. Only the child’s own turn boundaries count; a new turn clears the previous outcome, and missing or unreadable outcomes do not imply success. You can also press Ctrl+G or run `/agents`; filter by label or id, then use Up/Down and Enter to open a child’s read-only session. Its transcript updates while the parent continues working; Escape returns to the parent and preserves the unsent draft. Parent approvals return focus to the parent. Opening saved history does not resume the child. Remote runs without local transcripts and unreadable records explain why they cannot open. The status line names the model first, then shows the session's billed `in` and `out` tokens from the token meter's `tokenUsage` projection once a request has reported usage. Input counts uncached, cache-read, and cache-write tokens together. `cache hit N%` is the cache-read share of that input; it appears only when the provider reports cache traffic, as DeepSeek does through `prompt_cache_hit_tokens`. Inside a git repository the status line also names the displayed session's branch and its uncommitted changes, after the context reading. `WorkspaceGit` reads them with `git --no-optional-locks status --porcelain=v2 --branch` two seconds after each read finishes, and at once when the displayed session's workspace changes; the reads never take the index lock, so they cannot fail a commit the agent runs, and the runner stops and awaits them on exit. Outside a repository, or without git, the field is left out.

In an install the installers made, the status line names a newer release as `update v<version> · /update`, after every reading of the session; a narrow line gives it up before any other reading. The answer comes from a check cached under the Bake home for an hour, or ten minutes after a failure, read before the first frame and refreshed in the background every ten minutes while the terminal runs; the runner stops and awaits that schedule on exit. The notice never installs anything. `/update` checks and installs the newer release beside the running one, showing its progress on one row above the composer: the step, a meter the download fills with its percentage and bytes, and a comet for the steps without a known length; the session keeps running its own release, and the status line then reads `update v<version> · restart to use`. A source checkout shows no notice, and `BAKE_NO_UPDATE_CHECK=1` turns the check off. See [Updating an install](../../../../distribution/README.md#updating-an-install).

Use `--resume <id>`, or its alias `--session-id <id>` as the headless profile spells it, from the session’s recorded workspace. The stored preset remains authoritative; a conflicting `--preset` is rejected. A legacy session with no recorded preset requires an explicit `--preset`. Unknown ids never create replacement sessions. A session another Bake process has open is refused before the terminal is touched: the launch prints `dsh: <id>: open in another Bake process; …` with what to do to stderr and exits with status 75 (`EX_TEMPFAIL`), so closing the session there and running the same command again succeeds. Fresh empty sessions follow the harness persistence policy and need not survive exit. Resume restores the model and explicit effort from the last recorded request; provider-default effort remains implicit.

While a workflow runs, the row below the input names it. Ctrl+G shows recorded workflow progress, each member’s workflow and phase, and direct delegations marked `Direct`. The sheet opens even before the first child starts. A saved run without a final record is shown as `Unfinished`; reopening a session does not make it appear active.

Use `/resume` or its alias `/sessions` to choose a saved session from the current workspace or create a new session. `/new` and `/clear` start a fresh session directly. A green filled dot and a `Current` status mark the current session, dim open dots mark saved history by last use, most recent first, and each row shows how long ago the session was last used beside its short id. A session without a title is named `Untitled session` rather than by its id. The pointer starts on the most recently used saved session, so `/resume` then Enter returns to it; with no saved session it starts on the current one. An ocean blue plus marks the new-session action, pinned under the list so a long history never scrolls it away. The labels remain visible without color. Type to filter by title or id, use Up/Down and Enter to choose, and press Escape to cancel. The list excludes subagents and sessions with another live Agent owner. Navigation requires an idle Agent and an empty inbox, including plugin context; finish queued work, or press Alt+↑ to send queued human input now. Activity or new queued input cancels an open picker. Failed or canceled preparation keeps the current session displayed. Choosing a session another Bake process has open keeps the current one and says so on the notice line, with what to do: close it in that process, or start a new session with `/new`.

A successful switch resets the composer and history recall, opens the selected transcript, and drains the previous Agent handle. Inline mode leaves earlier output in terminal scrollback. Fullscreen replaces the viewport with the selected session and follows its newest output; `/resume` reopens saved sessions. Resume restores the recorded preset and last requested model configuration; new sessions use profile defaults. The picker does not change workspaces or supply a preset for legacy sessions; use `--resume <id> --preset <name>` for those sessions. Session listing and title reads use Harness services; unavailable titles remain selectable by id.

The runner’s [configuration table](../../DESIGN.md#8-configuration) includes locale, quit timing, and credential references. [The keyless PTY check](../../scripts/pty-smoke.ts) creates its own temporary profile and workspace; it does not require changes to a user profile.

## Understand the implementation

<details>

<summary>Session and terminal ownership</summary>

`session.ts` owns registry setup and recorded composition. `controller.ts` joins query history with live events and dispatches commands. `catalog.ts` observes session-scoped command and skill metadata, cancels superseded reads, and stops discovery during teardown. `references.ts` delegates path search to `agent.ctx.fileReferences.list`, aborts superseded queries, and drains outstanding reads at shutdown. `model.ts` reads provider catalogs and validates exact routes and efforts before the controller updates the Harness selection reference. `attachments.ts` stages bounded reads through the scoped filesystem, delegates image batches and file storage to Harness, and drains uncancellable provider calls before teardown. `interactions.ts` queues scoped requests and settles them on abort or disposal. `terminal-setup.ts` runs `/terminal-setup`: it reads the terminal's configuration files, asks through the interaction queue, backs a file up, and writes it with `dsh-atomic-write`, writing through a symlink instead of replacing it. `terminal-bindings.ts` is its pure part: detection from the environment, each terminal's documented file locations, and the edits. It edits JSON with comments through `jsonc.ts`, which parses to nodes that keep their offsets and splices new entries in without reformatting the file. `navigation.ts` finishes the `/sessions` or `/resume` command before preparing a replacement, rechecks the old Agent’s status and inbox, and retires its handle only after replacement replay succeeds. `runner.ts` loads the UI and Shiki graphs as separate artifacts while the profile and session open, releases Ink synchronously before draining navigation and disposing handles. `external-editor.ts` runs the user's editor on a private temporary file while Ink's `suspendTerminal` holds the terminal for it, stops this process's own read of stdin for that time so no typed line is lost to it, and the runner holds its rerenders until Ink redraws. `output.ts` strips SGR styling when `NO_COLOR` is non-empty, preserving terminal controls, and writes each of Ink's renders to the terminal as one write. In inline mode it draws transcript rows over the previous frame instead of erasing it first, and starts the first frame and each resize replay on the terminal's bottom row; the runner flushes it synchronously when it releases the terminal. `syntax.ts` wraps Shiki as the synchronous `highlight` the presentation layer calls for response code, tool source, structured output, and diffs: common languages start loading while the session opens, any other loads its grammar the first time a file in it is drawn, and until then its lines stay plain. It keeps the most recently drawn runs, bounded by count and by a megabyte of text, and draws a larger run without keeping it; the runner closes it after draining navigation. The launcher’s fatal-release hook disposes the same Cordis effect.

The runner resolves `screen` before mounting and asks Ink to own the alternate screen in fullscreen mode. In that mode, `output.ts` batches positioned updates without inline anchoring or newline conversion, homes the alternate buffer after entering it, turns SGR mouse reporting on with the alternate buffer and off before leaving it, and removes scrollback-erasure controls. The same release path restores the primary screen on quit, disposal, and fatal failure.

No new persistence types or runtime invariants are declared: session storage, inbox state, and Agent lifetime remain owned by their harness services. See [wiring](../../DESIGN.md) and [dependency documentation](../../DEPENDENCIES.md).

<a id="model-experience"></a>

## Model Experience

The terminal profile sets `spill-policy.maxInlineBytes` to 16 KiB for newly produced tool previews; oversized output is stored through the existing spill service. The shipped coding presets also cap selected file-read text at 16 KiB. These limits leave recorded results and tool schemas intact.

The bundle omits the harness's fixed identity opener, so the system prompt starts with the preset persona; the shipped `standard` and `ptc` presets introduce the agent as Bake. Ordinary human input becomes a logged user message. `@` file selections remain literal path references; choosing one does not read or inject its contents. The composed Harness provider supplies path-reference guidance when the Agent has a `read` tool. Explicit attachments become durable image/file blocks. Harness projects generic files into readable file handles and prepares image inputs for the selected model. Commands own any model-visible effects through the harness registry. Only the session preset's own engine compacts history automatically, before a step under context pressure and after a context-overflow failure. The bundle keeps the base engine for `/compact` alone, because its listeners would otherwise reach every preset's agents. A `minimal` session's history is summarized only when the user runs `/compact`, and a request that overflows the context window fails instead of being compacted and retried. A `minimal` request carries the preset's fixed persona, its one shell tool, and the conversation: no workspace instructions, skill catalog, or runtime context. Model selection uses the Harness request-routing reference; the next request records its configuration and any model-switch notice. Approval and question answers return to their requesting services; login secrets never enter model input or Session history.

The TUI does not assemble model requests or alter cache settings.

<a id="known-limitations"></a>

## Known Limitations and Deferred Work

- One displayed root session at a time; session navigation is confined to the current workspace. The picker reads all matching session records and titles, with a bounded number of visible rows.

- The picker lists sessions another Bake process has open; the refusal comes when one is chosen. Neither refusal can name that process: the session's kernel write lock records no owner.

- Attachment arguments to registered commands, and inline image previews are not supported. Image submission checks the current selected model; Harness owns final request admission.

- A model choice not yet used by a request is not persisted; selection does not change profile defaults.

- Tool execution qualification uses the built profile; source-launch module duplication is documented in [the runbook](../../PLAN.md#132-build-from-a-clean-checkout).

- Terminal scrollback keeps original output after compaction.

- Long-history resume has substantial transient memory cost; the [whole-process diagnostic](performance/README.md) records reproducible workloads, measurements, and the unresolved large-history failure.
