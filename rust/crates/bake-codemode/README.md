# bake-codemode

The native engine of Pi's codemode for Bake's Rust agent, slices 1 and 2 of the [code mode design](../../../docs/roadmap/rust-0.4/code-mode.md). A script is model-written JavaScript, the body of an async function, whose only capability is calling the tools and globals its host declares. The crate runs it in the QuickJS-NG WebAssembly binary Pi v1.3.0 runs, with Wasmtime, inside the calling process. Like Pi's `packages/codemode`, it has no agent types: the host answers every call. Nothing in the agent uses it yet; the `codemode` tool is slice 4.

## API

- `CodemodeEngine::get()` compiles the engine once per process (a `OnceLock`) and returns it; `compile_time()` reports how long Cranelift took. The first call blocks its thread for the compile (about half a second in a release build), so an async host makes it from `spawn_blocking`.
- `CodemodeEngine::start(ExecuteRequest)` starts a script on its own thread and returns the `Run`, which owns it. The request holds the parsed `Source` (whose `timeout_ms` is the run's deadline; none without it), the `ToolDeclaration`s on `tools`, the `GlobalDeclaration`s (`discovery_globals()` gives Pi's `searchTools`, `describeTool`, and `describeNamespace`), the `store` snapshot `load()` reads, `Limits`, optional `Deterministic` mode, and an optional `ExitHook` called when the thread exits. An invalid request (Pi's global name rules, duplicate tool names, and in deterministic mode duplicate script names or a bad start time) is a `StartError` and starts no thread.
- `Run::next().await` returns `Event`s in order: `Call(HostCall::Tool | HostCall::Global)`, `Output(OutputItem::Text | Image)`, in deterministic mode `Started` and `Idle`, then one `Done(Arc<Outcome>)`, which later calls return again as the same `Arc`. It needs no Tokio timer: the run's own threads keep its deadline.
- `Run::answer(id, Ok(value) | Err(CallError))` resolves or rejects a call; `Run::answer_in_order(seq, now_ms, id, result)` does so in deterministic mode. Both return `AnswerError` for a call that is not waiting and, in order, for a reused result number or a clock value that is not finite; answers after the outcome are ignored. `Run::finished()` says whether the outcome is decided.
- `Run::abort()` ends the script with an error it cannot catch, reported as `Failure::Aborted` with `Execution aborted`; `Run::abort_with(message)` reports `message` instead, as Pi reports an abort signal's reason. The first stop's message counts. Dropping a `Run` aborts it and joins its thread: in place outside a Tokio runtime, on a blocking task inside one.
- `Run::handle()` returns a `RunHandle`, cloneable and `Send`, with `answer`, `answer_in_order`, `abort`, and `abort_with`, so tasks that execute calls answer them while another task owns the `Run` and awaits its events. A handle does not keep the script alive: after the `Run` is dropped its answers are ignored.
- `Outcome` carries `Ok(Completion { value, store_writes })` or a `Failure`: `Exception(ScriptError)` (Pi's `script` kind), `NeverSettles`, `Timeout`, `Aborted`, `OutOfMemory` (the linear-memory limit), `OutputLimit` (the host's recheck), or `Protocol` (Pi's `sandbox` kind: a broken bridge, a bad guest pointer, a trap, or a call past `MAX_PENDING_CALLS` or `MAX_PENDING_ARGUMENT_BYTES`); in deterministic mode also `During`. Output is not repeated in the outcome: the host keeps the `Output` events.
- `Source::parse` is Pi's `// @options:` parser; `render_declarations`, `render_tool_signature`, `render_tool_sample`, and `schema_to_type` render TypeScript from JSON Schema; `to_codemode_identifier` maps tool names; `Bm25Ranker`, `create_tool_search_document`, and `tokenize` rank tools for the host's `searchTools()` answers.

## Engine

- `engine/quickjs.wasm` is `quickjs-wasi` 3.6.2's binary (QuickJS-NG 0.17.0, 637,405 bytes, SHA-256 `d4c9375f…4bbd9`), embedded with `include_bytes!`; `engine/PROVENANCE` records the npm integrity hash. A unit test checks the embedded bytes' SHA-256.
- The engine has its own Wasmtime `Config`: epoch interruption on, a 32 MiB Wasm stack, and no Wasm backtraces. Compiling checks that the module imports exactly the twelve functions below and that every export the driver calls has the signature it expects.
- The twelve imports are Bake's (`src/host.rs`): `clock_time_get` (the host's clocks, or virtual time), `random_get` (`getrandom`, or a seeded mulberry32), `fd_write` (discarded, reported as written), `fd_close`, `fd_seek`, and `fd_fdstat_get` (`EBADF`); `host_call` (the prelude's bridge), `host_interrupt` (the stop flag and deadline), `host_promise_rejection` (never enabled; frees its values), `host_module_normalize` and `host_module_load` (refused with NULL), and `host_get_timezone_offset` (0: scripts run in UTC). Every guest pointer and length is checked against linear memory before the host reads or writes; a bad one ends the run as `Protocol`.
- The driver (`src/vm.rs`, `src/guest.rs`) ports the part of `quickjs-wasi`'s `index.js` that Pi's `vm.ts` uses and follows `vm.ts`'s contract: the VM runs only when the host delivers something, drains promise jobs in batches of 50 with a stop check between batches, asks the prelude after each drain whether the script waits on nothing (`NeverSettles`), and never decides by itself that the script ended: the prelude's `done` unwinds the guest, so nothing queued after it runs. A stop recorded before `done` wins.

## Script environment

The prelude is `assets/prelude.js`, the text of Pi v1.3.0's `prelude-source.ts` with its MIT notice; a unit test pins its FNV-1a hash (`8c6c9242`) to Pi's. It freezes the built-ins and defines `tools` (with Pi's close-match errors), `ALL_TOOLS`, `text`, `image`, `exit`, `console.*`, `store` and `load` (256 Ki characters per value, 1 Mi in total), and the declared globals; `a.b` globals form frozen namespaces. Calls and results cross the bridge as JSON text. Nothing else is in the VM: no timers, I/O, modules, `WebAssembly`, or `models`.

## Containment and limits

- Each run is its own Wasm instance on its own thread with a 40 MiB stack (reserved, committed as used). QuickJS's stack guard (`qjs_set_max_stack_size`, 512 KiB) measures the C stack in linear memory, and built-ins that recurse natively use far more Wasm stack per byte of it: nested arrays 100,000 deep still trapped `JSON.stringify` on an 8 MiB Wasm stack, not on 12 MiB. With 32 MiB, deep recursion in script functions, `JSON.parse`, `JSON.stringify`, `String()` of nested arrays, and `eval` of deeply nested source is a catchable `RangeError`. A native recursion the guard does not see would still exhaust the Wasm stack, which traps and ends the run as `Protocol`; the process keeps working.
- QuickJS's heap is limited to 256 MiB by default (`qjs_set_memory_limit`): an allocation beyond it is a catchable `InternalError: out of memory`. A `StoreLimits` limiter caps linear memory at 320 MiB with one memory, table, and instance; growth past it traps and the run ends as `OutOfMemory` while the process keeps working.
- A deadline or `abort()` sets the run's stop flag and increments the engine's epoch; every running store's epoch callback then checks its own flag and deadline, so a long built-in such as one `JSON.stringify` of ten million elements stops at the next loop back-edge or call in compiled code. `host_interrupt` answers QuickJS's own interrupt poll (QuickJS-NG's regex engine polls it too), and the driver checks between job batches and while it waits for answers. A run with a deadline has a watchdog thread (64 KiB stack) that stops it at the deadline, so a built-in that runs past it stops whether or not the host awaits `Run::next`; the script thread joins it before exiting. An abort stops a script even while it allocates at the heap limit, catching each out-of-memory error.
- At most `MAX_PENDING_CALLS` (1024) calls may wait for results the VM has not yet applied, and their JSON arguments may take at most `MAX_PENDING_ARGUMENT_BYTES` (64 MiB) together. A call past either ends the run as `Protocol`, telling the script to await calls before making more or to batch them, so a loop that calls without awaiting ends at once instead of filling the heap, and the host's queues, with calls the VM can never settle; the byte budget is checked before the host copies a call's arguments. A `Promise.all` over a thousand items fits. The call is not refused with an error the script could catch: the prelude calls the bridge inside a `Promise` executor, so a host error thrown into the script would only reject that call's promise, a loop that does not await would go on making calls, and the refused call would stay in the prelude's pending set, hiding a never-settling script.
- The prelude limits output to 16 Mi characters and 100,000 items; the host rechecks the same limits before copying output out of the guest.

## Deterministic mode

`ExecuteRequest::deterministic` runs Pi's `start()` mode: the realtime clock reads the seed while the context is created (QuickJS seeds `Math.random()` from it) and then virtual time from `started_at_ms`, advanced only by answered results and never backwards; randomness comes from the seed; `WeakRef` and `FinalizationRegistry` are absent; answers are applied in `seq` order, early ones buffered. The run reports `Started` with Pi's fingerprint (`quickjs-wasi 3.6.2, quickjs 0.17.0, prelude 8c6c9242, deterministic 1, stack 524288, heap …, budget none`) and `Idle` after each drain, and the outcome's `During`. Pi's pinned `Math.random()` values for seeds 0 and 1 reproduce exactly.

## Tests

`cargo test -p bake-codemode --locked` runs 42 unit tests and 94 integration tests (`tests/codemode/`, one binary so all share one compiled engine; a debug build compiles it in about 0.7 s on Linux x86_64, since the workspace builds Cranelift optimized). They port Pi v1.3.0's cases, naming each:

- `test/source.test.ts` (5) and `test/declarations.test.ts` (17) as unit tests of `src/source.rs` and `src/declarations.rs`; the `tokenize` and `Bm25Ranker` cases of `coding-agent/test/tool-search.test.ts` (4) in `src/tool_search.rs`.
- `test/sandbox.test.ts` in `tests/codemode/sandbox.rs`, against a `Run`-based host (`tests/codemode/harness.rs`) that executes calls the way Pi's `execution.ts` does, each call's task answering through a `RunHandle`. The abort case checks Pi's messages: `abort_with` reports "user cancelled" and, for Pi's `close()`, "Sandbox closed", and `abort()` reports `Execution aborted`. Pi runs each case on its worker, inline, and remote backends; Bake has one. "supports register and unregister between executions" becomes per-request tool declarations; the seven broken-bridge cases run against the bridge decoder (`src/host.rs`); "embedded sources parse as JavaScript" is the prelude hash test and a run using every prelude global. Not applicable: "rejects execute after close" (a `Run` is one script; there is no sandbox object), the worker path, missing worker file, failing wasm module (the module is embedded and its ABI checked at compile time), and Node `--watch` cases.
- `test/deterministic.test.ts` in `tests/codemode/deterministic.rs`, including the pinned random values and the "diverged" abort message. "leaves a call waiting when its answer cannot be serialized" and the non-object rejection properties are ruled out by `serde_json::Value` and `CallError`'s types; the remote transport's reordering case is the in-order delivery case.
- `test/worker-lifetime.test.ts` in `tests/codemode/lifetime.rs`: a refused request starts no thread and calls its exit hook once; abort (with Pi's "cancelled"), timeout, and drop settle with the partial output and the thread exits; ordinary and deterministic runs report their thread's exit; a spinning script and its thread end within a second of an abort, timeout, or drop. Not applicable: worker construction and wasm loading failures and a throwing `onWorkerStarted` hook.

Bake's own cases: the embedded binary's SHA-256 and ABI; forged pointers and lengths on `host_call`, `host_promise_rejection`, and every WASI import, refused without a panic, and forged value pointers that make the guest trap; malformed bridge messages; escaped lone surrogates rewritten only inside strings, and reaching the host as U+FFFD from a return value, a call's arguments, and store keys and values; a lone surrogate counted once by the output recount; ten million loop iterations; an infinite loop, regex backtracking, and a long `JSON.stringify` stopped at the deadline (the last is stopped only by the epoch: with the epoch increment removed it completes), and long built-ins stopped at the deadline while nothing awaits `Run::next` (with the watchdog's stop removed they run on for seconds); a spinning loop, a job flood, a regex, and allocation at the heap limit stopped by `abort()`; `abort_with`'s message from a handle, the first stop's winning, and the outcome reported again as the same `Arc`; the heap limit as a catchable error, an oversized `'x'.repeat(2 ** 30)` as a catchable `RangeError`, and linear-memory exhaustion ending the run with the engine still usable; deep recursion, and deep nesting in `JSON.parse`, `JSON.stringify`, `String()`, and `eval` as a catchable `RangeError`; a loop calling without awaiting ending at the pending-call limit, with and without a deadline, three rounds of 1024 waiting calls and a `Promise.all` of 1000 succeeding, and one call over the 64 MiB argument budget or several passing it together ending the run while sequential calls of the same size succeed; and a dropped `Run` joining its thread, outside and inside a runtime.

## Differences from Pi and the design

- Every script runs in UTC; Pi keeps the host's time zone outside deterministic mode.
- `HostCall::Global` covers the discovery functions and any other global, since Pi's globals are generic; `Event` adds `Started` and `Idle`, and `Run` adds `answer_in_order` and `finished` for deterministic mode. `answer` returns an `AnswerError` instead of throwing.
- The prelude's own output-limit error is a script `RangeError`, as in Pi; `Failure::OutputLimit` is the host's recheck.
- Unhandled promise rejections are not recorded: Pi installs no handler, so `host_promise_rejection` is never enabled.
- Lone surrogates in strings leaving the VM become U+FFFD, one per surrogate so UTF-16 lengths are kept: raw ones in text, and escaped ones (`\ud83d`, as `JSON.stringify` writes them) in return values, call arguments, and stored values before `serde_json` parses them. A JSON payload nested more than 128 levels deep fails `serde_json` and ends the run as a broken bridge, where Pi would accept it.
- No deadline by default: a request without `timeout_ms` runs until it ends or is aborted. Pi's `execute()` defaults to 300,000 ms (`DEFAULT_TIMEOUT_MS`); Pi's coding-agent tool passes `Infinity`, which the caller of this crate expresses as no `timeout_ms`.
- QuickJS's heap is limited to 256 MiB by default (`Limits::heap_bytes`), where Pi sets no heap limit; the deterministic fingerprint therefore reads `heap 268435456` where Pi's reads `heap none`. `heap_bytes: None` restores Pi's.
- A script may have at most 1024 calls waiting (`MAX_PENDING_CALLS`), whose arguments take at most 64 MiB (`MAX_PENDING_ARGUMENT_BYTES`); Pi has no limit.
- `Run::abort_with` takes the message Pi reads from an abort signal's reason; `abort()` is Pi's default, `Execution aborted`.
- An unknown host function name, which `quickjs-wasi` throws into the script, ends the run as `Protocol`: the module's only host function is the bridge.
