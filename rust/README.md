# Bake Rust terminal preview

## Summary

Run Bake's native fullscreen composer, edit multiline Unicode drafts, send prompts to a scripted fixture runtime, and inspect sample agents while preserving your draft. This is an opt-in preview for the [Bake 0.4 Rust roadmap](../docs/roadmap/rust-0.4/README.md).

The preview shows sample content and scripted fixture turns only. It does not connect to a model, run tools, read credentials or the Bake home, write sessions, or start agents. Separate diagnostics read explicitly selected Sessions: [`session inspect`](#inspect-a-session-log) restores a current-format log, and [`session stat`](#inspect-session-metadata) reports metadata from a current or historical header. [`session list`](#list-stored-sessions) discovers that metadata across a named root. The shipped TypeScript terminal is unchanged and remains the default. This preview does not complete any roadmap scope.

## Run it

Prerequisites: [rustup](https://rustup.rs) and the platform linker it needs: a C compiler toolchain on Linux and macOS (`build-essential` or equivalent, or the Xcode Command Line Tools), and the Visual Studio C++ Build Tools (MSVC) on Windows. `rust-toolchain.toml` pins Rust 1.99.0 with rustfmt and Clippy; run Cargo from this directory so rustup selects it.

From the repository root, `bun run dev:rust` builds and opens the preview. Directly with Cargo:

```sh
cd rust
cargo run --locked -p bake-cli -- preview    # fullscreen preview; needs an interactive terminal
cargo run --locked -p bake-cli -- --help     # also printed when no arguments are given
cargo run --locked -p bake-cli -- --version
```

The binary is `bake-rs`. `preview` refuses to start, before changing any terminal mode, when standard input or output is not a terminal (exit status 1). Unknown commands and extra arguments fail with a diagnostic (exit status 2).

## Supported subset

- **Editing:** grapheme-safe insertion and deletion, including emoji ZWJ sequences, combining marks, regional-indicator flags, CJK, and Thai. When a deletion joins its neighbors into one grapheme, such as removing the newline between a letter and a combining mark, the caret moves to the joined grapheme's edge in the direction of the deletion and no text is dropped. Typing runs undo together; each paste, newline, or run of deletions is its own step. Undo keeps 64 steps; the draft holds at most 256 KiB, and longer input is cut at a grapheme boundary with a notice.
- **Input cleanup:** CRLF and CR become LF. Control characters other than LF and tab are dropped so they cannot become escape sequences. A tab is kept and drawn to the next four-cell stop.
- **Paste:** bracketed paste inserts text without submitting.
- **Wrapping:** the draft wraps as the TypeScript composer's `wrapDraft` does: rows break after spaces and tabs, blanks at a break hang past the row, a wide character is a word of its own, and a word longer than a row splits between graphemes. Rows never depend on the caret, so moving it never moves a word or changes the composer's height; a caret after a full row sits in the cell after the text. Wrapping, tab stops, and the caret share the cell widths the renderer draws with, and the terminal cursor sits at the caret.
- **Composer box:** from 12 columns, a rounded box frames the draft, `│ ❯ text │`, in the two rows the rules above and below it would take. The header, notice, agents row, and status line are inset two cells to align with the box's contents. A terminal without a UTF-8 locale, with no `TERM` or `TERM=dumb`, or with a Chinese, Japanese, or Korean character locale gets `+`, `-`, `|`, and a `>` prompt; Windows Terminal's `WT_SESSION` counts as UTF-8. Narrower than 12 columns, the box keeps only its top and bottom edges as plain rules.
- **Window:** the composer shows up to five rows, or a fifth of the terminal's height up to 12 rows on a terminal of 30 rows or more. The window keeps its position and moves only when the caret would leave it; after a width change the caret keeps its row in the window where the new layout allows. Dim `^` and `v` mark hidden rows, and the box's edges count them, `+N above` and `+N below`. - **Modes:** the composer reads differently while idle, while the sample turn runs, while the sample compaction runs, and while an agent is inspected. Only the empty draft's placeholder, the bottom edge's hint, and the prompt's tone change, so a mode change never rewraps the draft or moves the caret. The empty draft reads `Type a draft · Alt+Enter newline · Ctrl+Z undo` while idle, `Enter steers the next step · Alt+↑ sends now` during a turn, `Compacting… Enter queues · Esc cancels` during compaction, and `Read-only · Esc returns to parent` when inspection finds it empty. The bottom edge reads `Enter sends` over a draft while idle, `Esc interrupts` during a turn, nothing during compaction, and `draft kept · Esc returns` during inspection, where the prompt and draft are dim. Narrower than 60 columns, the placeholder keeps only its first part and only the inspection label remains. A hidden-row count takes the bottom edge before any hint. Enter in every mode shows the no-model notice, and Alt+↑ does nothing.
- **Activity line:** Ctrl+T starts a sample turn. It appends a running code-mode script, `{} Codemode: Read every manifest, then build`, to the transcript, whose calls arrive on a fixed timeline as the harness would dispatch them: a `tools.glob`, then twelve `tools.read` calls under `Promise.all`, at most ten in flight as the dispatch pool allows, one of them failing, then `tools.bash  bun run build`, which runs until the turn ends. While the script runs, its head counts the calls in flight, `13 calls · 9 running`, each site's meter fills as its calls settle, and an accent `▸` in the gutter marks the line whose calls are in flight. The script settles with the turn: when Ctrl+T moves on to the compaction it runs to its end, every call settled, the build ` exit 0 `, and what it logged and returned below; when Esc stops it, the calls in flight end interrupted, in yellow, those not yet started never run, the head carries an ` interrupted ` tag, and an interruption is not counted as a failure. The bar shows the turn as text alone: a word picked from 32 baking verbs, then its phase and elapsed time, `Kneading…  thinking · 3s`. The phase steps through sample phases every four seconds. A band of light sweeps across the word every 70 ms, blending from orange to a pale glint when `COLORTERM` is `truecolor` or `24bit`, and stepping through yellow, light yellow, and bright white otherwise. A second Ctrl+T replaces it with a sample compaction, `Compacting history…  preparing · 0s`, with its own clock and phases, in blue blending toward light blue, or blue, light blue, and bright white. Under `NO_COLOR` the word is bold and still, and only the seconds change. Nothing runs during either sample.
- **Fixture runtime:** Enter sends the draft through the runtime port to a scripted stand-in for the agent runtime, on its own thread. It answers every prompt with the same turn on a fixed timeline: it commits the prompt as a user row, starts the turn, streams a line of reasoning a word every 40 ms, runs one call, `Bash: true`, for 800 ms, then streams its answer, which says that no model or tool ran. The bar shows the phase the fixture reports, `thinking`, `running bash`, then `writing`, and the turn's outcome once it ends. Rows still being written are live: each update replaces them, and a commit settles them, so a streamed row is drawn once. A steer sent while the turn runs waits for the current step to end and then runs as a further step of the same turn; until then the runtime lists it above the bar under `Pending input`, as `Next step: later`, with `Alt+↑ sends it now` below. A prompt of several lines reads there as one, cut to the row with `…`, where the oracle wraps it. Alt+↑ interrupts the turn, keeping what waits, and starts a turn with every waiting prompt in the order they were sent. Esc commits what was live as it stood, a running call failed with an ` interrupted ` tag, and ends the turn; a waiting steer then starts the next one. Frames that only runtime updates prompted are drawn at most every 16 ms; a batch with input is drawn at once. The port's thread is joined before the terminal is restored, so no update outlives the preview. The fixture is development tooling and proves no runtime parity.
- **Layout:** fullscreen alternate screen at any size. From the bottom up: the agents row, the composer box, the bar on the box's top edge, the notice, and the transcript body. Rows go to the first composer row, the bar, the box's top edge, its bottom edge, the agents row, the gap, further draft rows while the body keeps three rows, and the notice, in that order, so a short terminal gives up the notice, the gap, the agents row, the bottom edge, the top edge, and the bar first; the box closes only when both edges fit. Events already waiting are applied together and drawn once, so a burst of keys or resizes repaints once. Every resize clears the screen and repaints the whole frame inside one synchronized update, even when a burst of resizes ends at the previous size.
- **Transcript:** the body above the controls is a viewport over a fixed sample session; nothing in it ran. It opens with the preview's title and introduction, then three turns: a search, a code-mode script, and a failing test run that an edit fixes. The title carries the palette beside it as a strip of swatches, hues then greys, when it fits whole, colour is on, and the frame is not classic. Every turn after the first row opens with a blank row, then a faint dashed rule of ASCII hyphens across the transcript's width, directly above the user's words, which follow a cyan prompt mark, `> Run the parser tests`, the rows a long prompt wraps to hanging under the text; reasoning is dim and italic and answers are plain, both at column 2. Each call is one row, `✓ Bash: bun test tests/parser.test.ts`, with its state mark (green `✓` done, red `✗` failed, and while it runs a white `●` that blinks: shown for 600 ms, then a blank of the same width for 600 ms, so the row never moves), the tool name bold in the foreground with a colon after it, `Bash:`, so the arguments of the common tools align, and its status two cells after the argument: its own, such as `412 lines`, or else its output's line count. An exit code or an interruption is a tag, a short code with a cell of padding on each side on a dark tint of its tone: ` exit 0 ` green, ` exit 1 ` red, ` interrupted ` yellow. Sixteen colours draw a tag's text in its tone without the tint, and `NO_COLOR` plain; the padding keeps its width either way. A status that does not fit there takes its own row under the argument and wraps rather than being cut. A read's or edit's path reads by its file name, the directory dim. An edit's output is a numbered diff, styled after [Diffs](https://diffs.com/), and its status counts it, `+1 -1`. Hunk headers set the line numbers, which are dim on context and red or green on a changed line; the lines before a hunk read `⋯ 40 unmodified lines`, and past 16 rows the rest fold. A changed line has a red or green bar, `▎` (`-` and `+` under `NO_COLOR` or with the classic frame), a tint across the line, and a stronger tint on the part that changed from the line it pairs with; without a box the changed line takes its colour whole and the changed part is bold. Code keeps its syntax colour. When the call's text area is 100 cells or wider the diff is side by side, each side numbered from its own file, a dim `│` between them, a removed run beside the added run after it, and the shorter side keeping its tint down a wrapped row; narrower, it is unified. Output starts at column 4, under the tool name. A result longer than five lines shows its first two and last two lines around `⋯ 4 more lines`. A code-mode script, the sample's second turn, is one block headed `Codemode` and marked with braces, `{}`, in its state's colour (green done, red failed, white and blinking while it runs; under `NO_COLOR` or with the classic frame it takes a call's mark, since colour cannot tell the states apart), drawn as the program it is rather than as a batch of calls: `{} Codemode: Find TODOs` followed by `13 calls · 1 failed`, then its source, numbered and whole up to thirteen lines (longer, its first two and last two lines and every line a call came from, around counts), with each call site hung under the first line that names its binding, `╰` at the code column. A site of one call reads `╰ ✓ tools.glob  src/**/*.ts  12 files`; a site of several reads `╰ ✓ tools.read ×12`, a meter with a cell per call (`━` done green, `╌` running, `✗` failed red, `╳` interrupted yellow), and a tally, `11 done · 1 failed`, with up to three failures listed under it. A binding no line names hangs after the source. After a blank row comes all the model reads back, labelled as the program wrote it: `console` before what it logged and `return` before what it returned, or `error` before how it failed, in red. On a truecolor terminal each call, and each script with everything under it, sits in its own box: a soft grey background `#25282f` across the full width, a faint red `#2e2225` for a call that failed. Inside a box of more than one line, a padding row opens and closes it; a call of one line, such as a read, is one tinted row. Text keeps two cells clear of its right edge, and everything the call holds, its output, diff, source, and `⋯` counts, starts at column 4 under the tool name, with no gutter; the state mark, a script's gutter mark, and its `console` and `return` labels stay at column 2. Sixteen-colour terminals and `NO_COLOR` draw no box. Without a box, output hangs from a dim `│` gutter at column 2. Code is coloured where the transcript shows code, and nowhere else: a code-mode script's source and the value it returned (as TypeScript), a shell call's command (the program sky, flags dim, strings lime, variables orange, pipes and redirects violet), and an edit's diff in the language of its file's extension (TypeScript and JavaScript, Rust, or shell; any other file plain). Keywords are violet, strings lime, numbers and constants such as `true` orange, called names sky, and comments dim and italic. Program output, answers, and reasoning are never coloured as code. A shell call's output takes the colours its command would print in a terminal: Bake runs commands with `NO_COLOR=1` and `TERM=dumb`, so the preview recognises familiar shapes instead, a search's `path:line:` (path magenta, numbers green), a test runner's markers and counts (`(pass)`, `✓`, `PASS`, `3 pass` green; `(fail)`, `FAILED`, `1 fail` red and bold; skips yellow; zero counts and `[1.20ms]` timings dim), `git status --short` codes, and an `error:` or `warning:` label from any command. Output that carries its own SGR colour keeps it, brought to the nearest of sixteen colours on an ANSI terminal and dropped under `NO_COLOR`. Every escape sequence and control character is removed from any tool's output, and a tab is four spaces. The lexers are line-based and change no text, so colour never moves a wrap. A blank row opens every row of the transcript but the first, so each box stands apart. The classic frame draws `|`, `+`, `x`, `*`, `...`, `` ` ``, and `>` instead. Lines wrap at the viewport's width, never truncate. The viewport follows the newest line until PgUp, Ctrl+↑, or Ctrl+Home moves it; while reading, its position holds, and paging down to the bottom or Ctrl+End follows again. A page is the viewport less four lines, and at least half of it. The transcript's last column is its scrollbar, kept clear even while the history fits, so text never reflows when the bar appears: a heavy `┃` thumb on a thin `│` track, grey on dark grey, accented cyan while dragged (bold on dim under `NO_COLOR`, `#` on `|` with the classic frame). The thumb is as long as the visible share of the history and rests at the foot while following. The row just above the controls, which is otherwise the blank gap over the bar, is the scroll indicator. While following, it holds `Wheel/PgUp scroll · Ctrl+↑ prompts` right-aligned, ending in the status line's column, once the history is taller than the viewport. While reading, it holds a pill centred on that row, `↓ 12 lines below · Ctrl+End`, sky on the box's grey; once output arrives below, it turns yellow, `↓ New output · 16 lines below · Ctrl+End`. A narrow pill drops its key, then its count, rather than be cut. Pressing the pill follows output again. A notice sits between the indicator and the bar. Drawing lays out only the rows the viewport visits; the scrollbar measures every row's height once per width and look, and again only for rows appended or changed since.
- **Agents:** the standing row under the box reads `Agents  2 samples · none running`, with `Ctrl+G` at the right. Ctrl+G opens the agent list in the body: `Fixed examples · nothing is running`, then a card for each agent, its name, its id as a blue tag after it, and the first line of what it does; the selected card is marked `▸` (`>` with the classic frame) and drawn in cyan. Enter inspects the selected agent as a ledger: its name, a dashed rule, then `Id` (a tag), `Role`, `State`, `Input` (`Read only · typing never reaches an agent or your draft`, in yellow), and `Draft`, the labels dim and the values in one column. The bar reads `Agents  ↑↓ select · Enter inspect · Esc back` on the list and is a breadcrumb while inspecting, `Agents / Sample explorer  Tab agents · Esc draft`, with `Agents` underlined.
- **Commands:** The slash menu ports the slash half of the TypeScript `completion.ts` over a fixed sample of the runtime's commands, with their names, hints, and descriptions: `/` and a partial name before the caret list the commands with that prefix, `model`, `resume`, `new`, and `clear` first, eight at a time above the bar with `+5 more, keep typing to narrow` after them; the selected row carries `▸` and the box's edge says `Tab completes`. Up and Down cycle the selection, Tab fills in `/name `, Enter submits the selected command or fills in one whose hint is required (`<path>`), and Esc closes the menu until the draft or caret changes. Once a command with a hint is typed with a space, its usage line, `/goal [objective|clear]  Set or view…`, takes the menu's place. No command runs: a submitted one says `Commands are not available in this preview`. Skills and argument choices are not ported.
- **Mentions:** `@` at the start of the draft or after whitespace, and the path typed after it, or `@"` for a path with spaces, open the file menu, which ports the file half of `completion.ts` and the `@` grammar of `bake-file-reference`. The view asks for the token's paths and lists only the answer to the query now at the caret, `Finding paths…` until it comes; `No matching paths` or `File discovery failed: …` say when none come. A worker thread lists them as the TypeScript `WorkspaceFileSearch` does, under the working directory and never past it or through a symbolic link: a query with a `/`, or none, lists that directory as it is now, hiding dotfiles until the name starts with `.`; a bare name is ranked against one traversal of up to 50,000 paths, the name equal to, starting with, or holding it ahead of a path holding it or its letters in order, directories first; `.git`, `node_modules`, `target`, and the other build and dependency directories the oracle names are never listed. Twenty at most come back, of which the menu shows eight and counts the rest. Rows read as they go in, `@src/main.rs`, or `@"my docs/a.md"`, a long path cut from its start; when files and directories mix, each names its kind. Tab puts in the selected path: a file with a space after it, a directory with the caret on its `/` to list what is inside. A turn's end marks the traversal stale, and it is rebuilt after the next answer, which the old one gives. Only paths are read, never a file's contents, and the preview sends nothing, so a mention goes nowhere.
- **Images:** Images stage as the TypeScript TUI's do. Ctrl+V, or an empty paste, which is what a terminal sends for a clipboard holding only an image, reads the clipboard's image: `wl-paste` on Wayland then `xclip`, AppleScript on macOS, and PowerShell on Windows, preferring PNG, then JPEG, WebP, and GIF; without one the notice says `No image on the clipboard`. A paste that is exactly one image path, quoted, backslash-escaped, `~/`-relative, or a `file://` URL, as a terminal drops a file, reads that file, and goes in as text when it is not an image. Reads run on a worker thread the loop joins on exit. A staged image puts `[Image #2]` at the caret and is listed above the bar under `Staged attachments: 1` as `shot.png · image/png · 40 B · 3×2`, its pixel size read from a PNG or GIF header. Erasing the placeholder, by Backspace, Delete, or a kill, unstages the image; neither undo nor Ctrl+Y brings the placeholder back. The preview sends nothing, so staged images go nowhere.
- **Mouse:** the preview turns on the terminal's mouse reports for presses, releases, the wheel, and motion while a button is held (modes 1000, 1002, and 1006, as the TypeScript TUI does) and turns them off on exit; the terminal's own selection stays on Shift-drag, or Option-drag on macOS. The wheel follows the TypeScript acceleration: a lone notch moves one row and a fast spin up to six rows a notch, fractions carrying so a steady spin moves evenly; a local macOS terminal, which accelerates the wheel itself, moves one row a report. Each report is timestamped by the input thread, so a burst applied in one batch still accelerates by its real gaps. A press on the scrollbar's track moves the thumb's middle there, and dragging follows the pointer, even off the bar, until release. A press in the transcript starts a selection, which the preview draws and copies itself, as the TypeScript fullscreen does: a drag selects cells, a double click within 500 ms on the same word selects the word, joined across `/` and `-` so a path is one word, and a triple click the line. Selected cells are drawn reversed in their own colours. The selection names the transcript row and line that draw each end, not screen rows, so it stays on its text while the view scrolls; a drag held on the top or bottom line scrolls it on a line every 50 ms. On release a drag, a word, or a line is copied, each line as drawn, cut to its cells and trimmed at its end; a plain click selects nothing and drops what was selected. The scroll indicator's row says `Copied` in green, or `Copy failed` in red, for 1.5 s. Esc drops a selection before it stops anything, and a change of width drops it, since its lines wrap anew. Copying follows the TypeScript `writeClipboardText`: over SSH the terminal's own clipboard through OSC 52, otherwise `pbcopy` on macOS, `clip` on Windows, `clip.exe` in WSL (OSC 52 under Windows Terminal), and `wl-copy` on Wayland then `xclip` and `xsel`, on a worker thread with a five-second limit per tool that the loop joins on exit; when no tool takes the text, OSC 52 is the last resort.
- **Bar:** one row directly above the box holds what the session is doing on the left and the status line right-aligned beside it, `Kneading…  thinking · 3s        deepseek-v4-flash high  ctx ~11%  ~/bake ⎇ main`. The left side is the sample's activity, the last sample turn's outcome, held until the next turn starts (`✓ Completed  8s` when Ctrl+T moves it on to a compaction, `■ Interrupted  3s` when Esc stops it), the agent list's title and keys, or the inspected agent; idle, it is empty. As the row narrows, the left side's phase and time give way first, then status fields by rank, then the status line whole; the activity word is never cut. Right-aligned, the status does not move when the activity starts or ends. The agents row's `Tab` key draws only on a terminal 60 columns or wider and only whole.
- **Status line:** minimal and consolidated into three fields: the model with its thinking level, `deepseek-v4-flash high`; the context window's occupancy, `ctx ~11% (15.2k/128k)`; and the location, the working directory under home with the git branch after it, `~/bake ⎇ main`. A reading the session lacks is left out; the preview has no model, so it reads `no model  ~/bake ⎇ main`. The branch comes from the repository's `HEAD` file at startup, a detached commit shows as `(1a2b3c4)`, and the classic frame writes `on main` instead of `⎇ main`. Fields give way by the TypeScript status line's ranks: the context's absolute count; then the directory, which takes only what the other fields leave, cut from its start so the branch stays, until fewer than six of its cells fit and the branch stands alone; then the branch; then the thinking level. The model is cut last, to eight cells, and the context percentage never yields. The level and the context reading take the TypeScript palette's warming tones.

Not implemented: model connection, sessions, real agents, queueing during compaction, the 32-entry presentation cache, inline (scrollback) mode, dictionary word breaks for Thai, Lao, Khmer, and Myanmar, a setting that overrides the frame style, skills and argument choices in the slash menu, sending attachments, redo, and keyboard-enhancement protocols.

## Terminal ownership

`TerminalSession` in `bake-tui` is the only code that changes terminal modes: raw mode, the alternate screen, bracketed paste, autowrap, cursor visibility, and synchronized output. Autowrap is off while the preview runs, so a row the terminal draws wider than measured is clipped instead of scrolling the screen. Each frame is written between synchronized-update markers (DEC mode 2026), and an update left open by a failure is ended on restore. It records each mode before requesting it and restores exactly those modes, in reverse order, attempting every step even when one fails:

- On quit or a handled signal, the preview closes the session explicitly. A restoration failure is reported (`bake-rs: preview failed: ...`, exit status 1) rather than discarded.
- On a loop error, the session is still closed; the loop error is reported, and a restoration error behind it is not.
- On a setup failure, only the modes already requested are restored.
- On a panic, a panic hook restores the terminal before the panic message prints. Dropping the session also restores it; restoration runs at most once, so these fallbacks never repeat it.

On Unix, SIGINT, SIGTERM, and SIGHUP are handled while the preview runs. Raw mode turns the Ctrl+C key into input, so SIGINT comes only from another process. A signal thread forwards each one to the loop as it arrives; the loop restores the terminal and exits with status 128 plus the signal number: 130, 143, and 129. After the terminal is restored the handlers are unregistered, but signal-hook does not reinstate the previous disposition, so those signals are ignored in the moment before the process exits. A second signal during restoration does not interrupt it, and SIGKILL or SIGSTOP cannot be handled at all.

An input thread reads terminal input as it arrives, decodes it into the view's messages, and sends them to the loop. It checks every 50 ms whether to stop, and the preview joins it before leaving raw mode, so it reads nothing meant for the shell. If the thread fails or ends unexpectedly, the loop reports `terminal input stopped` and restores the terminal. Between messages the loop sleeps until the next one, or until the sample activity's next shimmer beat or second.

## Inspect a Session log

```sh
cargo run --locked -p bake-cli -- session inspect --max-bytes <N> --max-source-seqs <N> [--] <file>
```

`session inspect` opens one explicitly named Session log read-only, restores it as the production read path does with the [`bake-session`](#layout-of-this-workspace) reader, and prints one JSON record on standard output. It is a development diagnostic in this preview binary, which stays out of the release archives.

- **Budgets.** Both options are required positive decimal integers no greater than 9007199254740991, each given once, in either order. `--max-bytes` bounds the file's size and, for Zstd, the cumulative decoded plaintext; a plain log's plaintext is its file. `--max-source-seqs` bounds each event's expanded `sourceEventSeqs`.
- **Names.** Only `session.v3.jsonl` (plain) and `session.v3.jsonl.zstd` (Zstd) are opened, and the name alone selects the decoder. A recognized older generation (`session.jsonl`, `session.vN.jsonl`, with or without `.zstd`) or newer one is refused before the file is opened, as is any name TypeScript does not treat as canonical. Nothing is migrated. The path may hold non-UTF-8 components; `--` must precede a path that starts with `-`.
- **Reading.** On Unix the file is opened without blocking, so a FIFO is refused rather than waited on. The open file must be a regular file within `--max-bytes`; at most one byte more is read, and the read is refused when the file's size, modification time, or, on Unix, device, inode, or change time differ afterwards. This detects ordinary modification; it is not an atomic snapshot or a lease, and it never retries.
- **Restored record** (exit 0): `status`, `encoding` (`none` or `zstd`), `formatVersion`, `fileBytes`, the logical `header` (`id`, `createdAt`, `cwd`, `parentSession`, `isSeeded`, `origin`, `delegationDepth`, `agentPreset`, each absent optional value `null`), `storedEventCount`, `committedPlaintextBytes`, `inheritedEventCount`, `torn` (`null`, or the physical `truncateTo` offset, `recoveredFrom`, and `recoveredEventCount` of rows recovered from a torn Zstd frame), `repair` (`closerTypes` of the interrupted-turn closers and `endSeedAppended`), and `projection` (`messageCount`, `hasRequestHeader`, `hasRequestContext`). No message, tool, or request content, and not the path, is printed. JSON control characters, including the terminal escape character, are escaped; other Unicode is printed as UTF-8.
- **Refused record** (exit 3): the same leading fields and a `refusal` with `kind` (`invalid`, `unsupported`, or `native-limit`, where this preview cannot reproduce the production outcome and claims none), a `message`, and the event record `line` (counted from 1 after the header), event `seq`, and physical byte `offset` where the reader reports them, otherwise `null`.
- **Other exits.** An unsupported name, an unreadable, oversized, irregular, or changing file prints one diagnostic on standard error with exit status 1. Usage errors exit with status 2. When standard output is closed, the command exits with status 1 and prints nothing.

Given a file, the command does not check the log's stored identity or select a generation in a Session directory. It never truncates, repairs, migrates, or resumes the Session. It reads no Bake home, configuration, or credentials, and changes no terminal mode. Restoration supports `image/offload` decisions and known event types marked `ignorable`, such as a routed subagent's `subagent/routing-decision`, within its validated subset. The remaining [native limits](../conformance/README.md#plain-log-restoration-cases), including unsupported projected numbers and JavaScript coercions, stay `native-limit` refusals.

### Look up a Session by id

```sh
cargo run --locked -p bake-cli -- session inspect --root <dir> --id <id> --max-bytes <N> --max-source-seqs <N> --max-entries <N> [--compression none|zstd]
```

With `--root` and `--id` instead of a file, the command finds the Session as the TypeScript JSONL backend's `open(id, 'read')` does, and only in the root you name; it never falls back to the Bake home. `--compression` names the root's encoding and defaults to `zstd`, as the backend does. `--max-entries`, required in this form, bounds the directory entries the lookup reads across all listings; the other two budgets apply to the selected file as above. `--root` must be UTF-8, as the backend's root is a JavaScript string. A relative root is resolved against the working directory, and `.` and `..` are applied without following symlinks, as Node's `path.resolve` does. On Windows the system's full-path resolution is used, and only relative roots and drive-absolute roots such as `C:\sessions` are accepted: verbatim (`\\?\`) and device (`\\.\`) paths, network shares, drive-relative paths such as `C:x`, paths rooted without a drive, and names ending in a dot or a space or naming a reserved Windows device are `native-limit` refusals at stage `root`, as is a resolved root that is not UTF-8.

- **Order.** The whole root is checked first: a regular `*.jsonl` or `*.jsonl.zstd` file in a project directory is the flat legacy layout, and a generation of the other compression in any Session directory is an encoding mismatch. Then each project is searched for the id: a readable file, link, or directory named `<id>.jsonl` or `<id>.jsonl.zstd` is the legacy layout, the id's directory may be a symlink, and the numerically highest canonical generation is selected. Project directories that are symlinks are skipped; on Windows every reparse-point entry is treated as a link during layout enumeration, as Node treats it. An id in two projects is a duplicate; an id in none, or a missing root, is not found. A newer generation is refused from its first line or Zstd frame alone, but the whole file is read within `--max-bytes`, where TypeScript reads only that header, so a large newer file can exit 1 where TypeScript refuses it as unsupported. An absent newer generation, such as a dangling link, is a malformed header, as in TypeScript; an absent current one is an I/O failure. An older generation (v0, v1, or v2), plain or Zstd, is read within `--max-bytes` and migrated in memory, as TypeScript's read path migrates it. Its stored identity is checked, every refusal is reported at stage `generation`, and nothing is published. A selected generation that is not a regular file fails; no lower generation is tried. The current generation is scanned, its header id and the path its id and `cwd` name are compared with the selected file, by spelling or else by resolved real path, and then it is restored. Ids and `cwd` values are encoded into directory names as the backend encodes them.
- **Records.** Every record also has `path`, the selected generation relative to the root with `/` separators, or `null`; `fileBytes` is `null` when no file was read. A refusal adds `stage` (`root`, `layout`, `lookup`, `generation`, `scan`, `identity`, or `restore`), a `reason` code, `null` for scan and restore refusals, for a newer generation's corrupt header frame or native limit, and for an older generation's corrupt or unsupported migration (codes such as `legacy-layout`, `encoding-mismatch`, `duplicate-id`, `not-found`, `newer-format`, `migration-limit`, `id-mismatch`, `path-mismatch`, `entry-budget`, `non-utf8-name`, `unsupported-root`, or `unsupported-name`), and the root-relative `path` it names; `kind` may also be `not-found`. An unreadable root or directory, a Session id that names a file, and the file failures above, including a selected file over `--max-bytes`, exit with status 1 with the same diagnostics as the file form.
- **Limits.** Entries are visited in byte order of their names, while TypeScript uses the operating system's order. When faults coexist in different directories, the first one found wins in each, so the stage, reason, and even whether the command refuses or fails can differ from TypeScript's. On Windows, encoded ids and traversed directory names ending in a dot or space or naming a reserved device are `native-limit` refusals with reason `unsupported-name`: requested ids are checked before listing, at stage `lookup`, and listed names at stage `layout`. A project or Session directory whose name is not UTF-8 is a `native-limit` refusal, because Node reads such a name with replacement characters and then opens a different path. Nothing is written or locked, a migration stays in memory, and the directory and file checks are not an atomic snapshot, so a concurrent change can go undetected. The [shared lookup cases](../conformance/README.md#session-lookup-cases) record what is compared with TypeScript.

## Inspect Session metadata

Use `session stat` to read a Session's header and physical file size without replaying its events. From the repository root:

```sh
rust/target/debug/bake-rs session stat --root <dir> --id <id> --max-header-bytes <N> --max-entries <N> [--compression none|zstd]
```

Build the binary with `bun run check:rust` first. On Windows its name ends in `.exe`. Both budgets are required positive integers no greater than 9007199254740991. Compression defaults to `zstd`. The command uses the [lookup rules](#inspect-a-session-log) to select the highest canonical generation in the named root, then checks its header and stored identity. It never falls back to an older generation or reads configuration, credentials, or the Bake home.

Format v0 and v1 headers derive `isSeeded` from the presence of `seedLength`, including zero. Headers below v3 translate the `code` preset to `ptc`; a current-format header keeps its preset. Event rows are not decoded or validated, so a corrupt body does not prevent a valid header from being reported. No file is written, locked, or migrated. The command does not migrate historical events or resume an Agent.

The command prints one `bake/session-stat` version-1 JSON record. `status` is `found`, `absent`, or `refused`. `path` is relative to the root, `storedVersion` identifies the selected filename's version, and both are `null` when lookup finds no generation. A found record supplies the current logical `header`, with absent optional fields represented as `null`, and `sizeBytes`. A refused record adds a `refusal` with its stage, reason, kind, and message. Size is observed after reading the header; the result is not an atomic snapshot and exposes no file revision.

A missing Session or file, an incomplete plain line or Zstd frame, and a malformed header produce `absent`. Retired policy fields, a filename/header version mismatch, a newer format, an identity mismatch, or a corrupt first Zstd frame produce a refusal. The header budget includes the terminating LF and bounds both the physical prefix and decoded header. The bounded prefix may include body bytes, and one extra byte distinguishes EOF at the budget from more input. A large body is accepted when its header fits. Unsupported JSON representations and path spellings retain explicit native-limit refusals. Exit status is 0 for found or absent, 3 for a structured refusal, 1 for I/O failure, and 2 for invalid arguments.

The [shared header and stat cases](../conformance/README.md#session-metadata-cases) compare the native reader and command with the TypeScript backend. They leave input bytes and modification times unchanged and check the command's private home remains empty. Symlink and directory-generation cases have explicit platform restrictions; Linux runs do not establish Windows behavior.

## List stored Sessions

Use `session list` to discover materialized Sessions in a root you supply. Build the binary as described above, then run it from the repository root:

```sh
rust/target/debug/bake-rs session list --root <dir> --max-header-bytes <N> --max-entries <N> [--compression none|zstd]
```

Compression defaults to `zstd`. Both budgets are required positive integers no greater than 9007199254740991. The command checks the whole root's layout and encoding before discovering Sessions, selects each real Session directory's highest canonical generation, and reads its header with the [metadata rules](#inspect-session-metadata). It ignores directory links during discovery and follows selected file links, subject to the stored identity check. The header budget applies separately to each artifact; the entry budget counts every listing across the layout and discovery passes.

An absent root produces an empty list. Missing, incomplete, malformed, unsupported, and corrupt Zstd headers are skipped, as the TypeScript backend's discovery skips them. There is no fallback to an older generation. Retired policy fields, filename/header version mismatches, invalid stored identities, duplicate admitted header IDs, and native limits abort the listing. I/O errors also abort it. Native limits must remain visible because the command cannot decide whether the affected artifact belongs in the list.

The command prints one `bake/session-list` version-1 JSON record. A `listed` record contains `sessions`, each with a root-relative `path`, `storedVersion`, current logical `header`, and physical `sizeBytes`. A `refused` record contains the structured `refusal` and an empty `sessions` array. Exit status is 0 for listed, 3 for refused, 1 for I/O failure, and 2 for invalid arguments. Native results follow byte-order directory traversal; TypeScript promises no order. When several artifacts are faulty, native and TypeScript discovery can report different first errors. Sizes are observed after all headers have been admitted, so the result is not an atomic snapshot.

This diagnostic lists materialized files only and reports no revision token or process-local pending Session. It reads no configuration or default home and writes, locks, or migrates no files. The [shared listing cases](../conformance/README.md#session-listing-cases) compare it with the TypeScript backend's public `list()` and verify that the storage tree stays unchanged.
