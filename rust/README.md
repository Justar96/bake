# Bake Rust agent

## Summary

Run Bake's native agent, `bake`, fullscreen or inline with terminal scrollback: edit multiline Unicode drafts, send them to a real agent session that streams answers, thinking, and tool calls, steer or stop a turn, and resume the session later. `bake preview` runs the same components against a scripted fixture runtime with sample agents. Both modes share the same components and styling. This is an opt-in development build for the [Bake 0.4 Rust roadmap](../docs/roadmap/rust-0.4/README.md).

`bake` in a terminal opens an interactive session over the same setup as print mode (see [Interactive sessions](#interactive-sessions)). `bake preview` shows sample content and scripted fixture turns and connects to nothing. `bake -p` runs a headless Pi print-mode turn: it reads the Bake home's models, credentials, and settings, imports the 0.3 CLIProxyAPI route, key, and default model read-only (D25), connects to a model, and writes Pi-format sessions; it runs Pi's built-in file tools. The shipped TypeScript terminal is unchanged and remains the default. This build does not complete any roadmap scope.

## Run it

Prerequisites: [rustup](https://rustup.rs) and the platform linker it needs: a C compiler toolchain on Linux and macOS (`build-essential` or equivalent, or the Xcode Command Line Tools), and the Visual Studio C++ Build Tools (MSVC) on Windows. `rust-toolchain.toml` pins Rust 1.99.0 with rustfmt and Clippy; run Cargo from this directory so rustup selects it.

From the repository root, `bun run dev:rust` builds and opens an interactive session with the models in your Bake home, and `bun run dev:rust:preview` opens the preview. Directly with Cargo:

```sh
cd rust
cargo run --locked -p bake-cli --             # interactive session; needs an interactive terminal
cargo run --locked -p bake-cli -- --inline -c # continue the latest session with terminal scrollback
cargo run --locked -p bake-cli -- preview     # fullscreen preview with no model connection
cargo run --locked -p bake-cli -- preview --inline  # same preview with terminal scrollback
cargo run --locked -p bake-cli -- --help      # also printed when no arguments are given and a stream is not a terminal
cargo run --locked -p bake-cli -- --version
cargo run --locked -p bake-cli -- docs       # the documentation topics; `docs <topic>` prints one
cargo run --locked -p bake-cli -- --self-check  # one JSON line: version, platform, documentation hashes
cargo run --locked -p bake-cli -- update --check  # report a published native release; exits 10 when one is available
```

Print-mode stdout and stderr pass through an owned writer with a bounded queue of 8 KiB chunks. Normal exit drains output; a handled signal cancels pending delivery before awaiting session shutdown, so a full unread pipe cannot prevent cancellation even with one agent runtime worker. Both the writer and the independent signal thread are joined. A delivery failure exits 1 unless a handled signal determines the exit status. On Unix the writer restores inherited descriptor flags when it ends.

Print mode accepts optional `--max-model-calls <n>` and `--run-timeout-ms <n>` limits shared across its prompts, retries, and summaries. The deadline starts before the first prompt, after startup, and cancellation awaits cleanup. JSON `agent_settled` events carry a typed outcome; model failures and exhausted budgets exit 1 in both output modes. Native loopback tests cover shared and zero budgets, session reopening after exhaustion, and failed JSON requests.

The binary is `bake`. Both preview modes refuse to start, before changing any terminal mode, when standard input or output is not a terminal (exit status 1). Unsupported preview arguments fail with exit status 2. `bake docs` prints Bake's 0.4 user documentation, compiled into the binary from `crates/bake-cli/docs/*.md`: the topic list, or one topic's Markdown with `bake docs <topic>` (`cli`, `home`, `models`, `settings`, `permissions`, `sessions`, `context`). It needs no terminal or Bake home, and an unknown topic fails with exit status 2 and the list. `bake --self-check`, given alone, prints one line of JSON, `{"kind":"bake-self-check","schema":1,"version":…,"runtime":"rust","target":…,"docs":{…}}`: the Cargo version, the release platform (`darwin-arm64`, `darwin-x64`, `linux-arm64`, `linux-x64`, or `win32-x64`), and the SHA-256 of each embedded documentation topic. It exits 1 on any other platform, when the embedded documentation is missing, repeated, or untitled, or when standard output is closed, and 2 when given another argument. It reads no Bake home, credentials, settings, environment, or network, needs no terminal, and starts no async runtime; it does not test a model, provider route, or sandbox backend. `bun run release:pack:rust` relies on it (see [the distribution guide](../distribution/README.md#native-preview-archive)). Unknown agent options fail as Pi's do (`Error: Unknown option…`, exit status 1), and other words are prompts.

Inline mode writes settled transcript rows once into the terminal's normal screen and keeps the composer, panels, and live output in a bounded region below them. It preserves pre-launch shell output and removes the live controls when it exits. The inline writer owns the terminal's saved-cursor slot to track its live region through resize; other output must not use that slot while the preview runs. Fullscreen remains the default.

## Interactive sessions

`bake` without `-p` or `--mode`, with standard input and output on a terminal, runs `cli::start_interactive`, the setup print mode uses, before any terminal mode changes: a failure prints as print mode's do and exits with status 1. Unlike print mode, no model or no API key is not a failure: the session opens with a note naming `/login` and `/model`, and refuses prompts until a model is ready. The session, model, tool, permission, skill, and prompt-template flags mean what they mean for `-p`. Message arguments and `@file` attachments run first, in order. The transcript opens with the session file (or `--no-session`), any model fallback, and the messages a resumed session already holds.

- **Prompts:** Enter sends the draft as Pi's `prompt` while idle. While a turn runs it steers, as Pi's `onSubmit` does: the prompt joins the turn at its next step and shows in the pending-input panel until then. A steer takes text only, so a draft with staged images is kept with a notice until the turn ends. A prompt sent after Esc, while the stopped turn ends, waits for its own turn. Alt+↑ steers the waiting prompts.
- **Admission:** each prompt is answered once, admitted when the session takes it or refused with its reason; a refused prompt's text, images, and caret come back into the draft, ahead of anything typed since.
- **Stopping:** Esc clears the session's steering queue into the draft and aborts the turn, as Pi's `restoreQueuedMessagesToEditor({ abort: true })` does. The turn's partial answer stays in the transcript once, and a running `bash` call's process tree is killed.
- **Commands:** `/skill:name` and prompt templates are expanded by the session. `bake-tui::live::commands` runs `/model`, `/thinking`, `/settings`, `/session`, `/name`, `/new`, `/resume`, `/tree`, `/fork`, `/clone`, `/compact`, `/login`, `/logout`, `/refresh-models`, `/changelog`, `/share`, and `/bug`, one at a time, each as a task the driver owns (see below). Pi's other built-in commands (`/copy`, `/reload`, …) and other `/word` prompts that name no template are refused with the draft kept.
- **Model, thinking, and settings:** Pi v1.2.0's `handleModelCommand`, selectors, and `showSettingsSelector`. An exact `/model` match is set at once (Pi regression 7443); otherwise a list opens over the composer. Enter changes the session and Ctrl+S also saves the default. `/settings` offers the steering mode, follow-up mode, and auto-compaction, saved as it changes them. A change goes through `AgentSession`'s setters, which run one at a time and, for a model or thinking level, write the session entry first and apply only what was written; the change takes effect at the next model request, while a response in flight keeps its model.
- **Sheets:** dialogs are drawn as the TypeScript terminal's picker sheet (`apps/tui/packages/ui/src/sheet.tsx`, `picker.tsx`): a framed panel up to 80 columns with a title, a `> ` filter row, a `▸` pointer, a `Current` mark, group headings with counts, `n more` edges, the selected row's description, and a footer whose keys shorten so Esc stays visible. `/model` lists readable names grouped by provider with the route as detail; its filter still matches exact ids. `/session` is a read-only sheet whose long values wrap with a hanging indent. Inline, a closed sheet's rows are refilled with the transcript's tail, so the sheet leaves no gap above the controls beyond the inline transcript viewport's existing blank rows.
- **Sessions:** Pi v1.2.0's `handleSessionCommand`, `handleNameCommand`, `handleClearCommand`, `showSessionSelector`, and `AgentSessionRuntime`'s `newSession` and `switchSession`, with the TypeScript navigation's rules (`apps/tui/packages/app/src/navigation.ts`). `/name` writes a normalized `session_info` entry and emits `session_info_changed`. `/new` and `/resume` build the next session with `cli::SessionFactory` beside the running one, and the driver swaps them only when no turn runs and the command was not cancelled; otherwise the running session and the draft stay. A running turn refuses the switch rather than aborting it, as the TypeScript navigation did, where Pi aborts. `/resume` lists the working directory's sessions only, answers with a session id that a fresh listing resolves (a missing, empty, duplicate, or other-directory choice is refused), and restores the chosen session's model, thinking level, and permission; the view starts its transcript over with `RuntimeUpdate::Replaced`. Building the chosen session may append to its file before the switch commits. `/tree` (Pi v1.3.0's `showTreeSelector` and `navigateTree`) lists `live::tree::tree_rows` in the shared sheet, then asks Pi's "Summarize branch?" (`BranchSummaryChoice`: no summary, summarize, or summarize with a one-line custom prompt; `branchSummary.skipPrompt` skips it), and moves the running session's leaf with `AgentSession::navigate_tree` (`TreeNavigationOptions`: `summarize`, `custom_instructions`, `replace_instructions`, `label`). It claims the idle session; with a summary it collects the entries of the branch left back to the common ancestor and summarizes them with `branchSummary.reserveTokens` and Pi's summarization retries (events with `source: "branchSummary"`), while the bar shows `summarizing branch` and Esc (`AgentSession::abort_branch_summary`) cancels it, writing nothing and reopening the tree; a summary already made is written even if a cancel arrives later, as in Pi. The `branch_summary` entry, and the label, are written at the new position through the session write boundary; without a summary nothing is written and the command's cancel is rechecked under the session lock before the move. It rebuilds the transcript from the new path, where the summary replays as `Row::branch_summary`, and keeps the live model, thinking level, and permission, as Pi does; a chosen user message returns as `RuntimeUpdate::Restored`, never sent. `/fork` (Pi's `showUserMessageSelector` and runtime `fork`) stages a session from `SessionFactory::fork` over `SessionManager::branched_copy`, which never touches the running session's file or writer lock, and commits it as `/resume` does; `/clone` (Pi v1.3.0's `handleCloneCommand`, runtime `fork` with `position: "at"`, `ForkPosition::At`) does the same with the whole path up to the current leaf and an empty draft. `/resume` searches as Pi v1.2.0's session selector does (`session-selector-search.ts`, through `bake-coding-agent::session::search`): fuzzy words, whitespace-collapsed `"quoted phrases"`, and case-insensitive `re:` patterns over each session's id, name, every user and assistant message text in its file (every branch, as Pi's listing reads the log), and working directory; Ctrl+S switches between recent and relevance order and Ctrl+N shows only named sessions, as Pi binds them, and the sheet's state row shows both or why a pattern cannot match, in which case nothing is listed and Enter chooses nothing. Searching, toggling, and cancelling neither write a session nor send a request. `/compact [instructions]` (Pi's `handleCompactCommand` and `compaction_end` rendering) runs `AgentSession::compact_when_idle` as the session's work: the driver brackets it with `TurnStarted` and `TurnEnded`, so the bar shows `compacting` and Esc (`Request::Cancel`) aborts the command's signal; it opens no dialog, so no keyboard handoff drops keys typed meanwhile. It shares the transition barrier of `/new`, `/tree`, and `/fork`: it starts only while idle (Pi aborts a running response instead), and prompts and commands sent while it runs are refused with their drafts kept. On success the transcript starts over with `projection::replay_compacted` (the kept history without the latest summary) and `Compacted from N tokens` below it; a cancel or failed summary writes nothing and returns the draft, and only the command's own cancellation ends the bar as interrupted. Not ported: label editing, tree filter modes and folding, expandable branch-summary rows, the compaction cost notice, Pi's threaded session order, path toggle, rename and delete keys, and switching to another directory's session.
- **CLIProxyAPI account:** `/login` asks for the proxy address, then the key in a field that draws only `•`, checks the key against the proxy's model list, and commits the account through `cliproxyapi::account` (see `bake docs models`). `/refresh-models` re-reads the list and `/logout` signs out; each launch also refreshes once in the background, quietly unless a write it committed may not be durable. Esc or a quit aborts the command and its request up to the commit. After that, the commit runs to its end and is reported. No update, transcript row, or `Debug` output carries the key.
- **Dialog input:** a dialog takes keys only once it is drawn whole and armed, by the same barrier as approvals; keys typed before that, during a field's check, or while a closing dialog hands back to the composer (shown as `Preparing…`) reach neither the next field nor the draft. Only a fresh Enter answers. Dialog ids only grow, a stale answer is dropped, and Esc aborts only the command whose dialog is showing. Ctrl+T and Ctrl+G, the preview's sample controls, say they are preview only, and the sample-agent row is hidden.
- **Status:** the status line shows the session's model, thinking level, and context use after each turn.
- **Quitting:** Ctrl+C twice, SIGINT, SIGTERM, SIGHUP, or a closed terminal stops the turn and awaits the session's shutdown, its writes, model requests, and tools, before the terminal is restored; the exit statuses are those of [Terminal ownership](#terminal-ownership).
- **Approvals:** under `ask`, requests wait in order. The panel shows the tool, call id, reason, and arguments, escaping control, bidirectional, and zero-width characters; Up, Down, PgUp, and PgDn scroll the detail. After `Preparing approval…` gives way to the controls, `y` then Enter allows that call once, `n` rejects, and Esc cancels. Ctrl+C twice quits. A grant never changes the preset or covers another call. The draft, caret, and staged images stay intact. Queued input, pasted text, repeats, and Enter alone cannot approve; resizing clears a selected allow. Cancellation takes precedence over a ready answer, and stopping or losing the terminal refuses pending requests. `never` rejects before showing a panel; print mode has no answerer.

`bake-tui::live` holds the port: `LivePort` owns the `AgentSession` from the moment it is given one, starts its driver task only once the terminal is set up, and shuts the session down when stopped or dropped, including after a driver panic, which it reports. On shutdown the driver aborts a running command and the startup refresh, shuts the session down, then awaits both, so a commit already started has finished before the terminal is given back; a driver that panics hands them to the port, which does the same. A `projection::Projector` subscribed to the session turns its events into the view's `RuntimeUpdate`s. The steering queue, `AgentSession::steer`, `follow_up`, `clear_queue`, and its `queue_update` event, is adapted from Pi v1.2.0's `agent-session.ts`, and the frontend's submit, escape, and event handling from its `modes/interactive/interactive-mode.ts`; see `crates/bake-tui/NOTICE`.

## Supported subset

- **Editing:** grapheme-safe insertion and deletion, including emoji ZWJ sequences, combining marks, regional-indicator flags, CJK, and Thai. When a deletion joins its neighbors into one grapheme, such as removing the newline between a letter and a combining mark, the caret moves to the joined grapheme's edge in the direction of the deletion and no text is dropped. Typing runs undo together; each paste, newline, or run of deletions is its own step. Undo keeps 64 steps; the draft holds at most 256 KiB, and longer input is cut at a grapheme boundary with a notice.
- **Input cleanup:** CRLF and CR become LF. Control characters other than LF and tab are dropped so they cannot become escape sequences. A tab is kept and drawn to the next four-cell stop.
- **Paste:** bracketed paste inserts text without submitting.
- **Wrapping:** the draft wraps as the TypeScript composer's `wrapDraft` does: rows break after spaces and tabs, blanks at a break hang past the row, a wide character is a word of its own, and a word longer than a row splits between graphemes. Rows never depend on the caret, so moving it never moves a word or changes the composer's height; a caret after a full row sits in the cell after the text. Wrapping, tab stops, and the caret share the cell widths the renderer draws with, and the terminal cursor sits at the caret.
- **Composer box:** from 12 columns, a rounded box frames the draft, `│ ❯ text │`, in the two rows the rules above and below it would take. The header, notice, agents row, and status line are inset two cells to align with the box's contents. A terminal without a UTF-8 locale, with no `TERM` or `TERM=dumb`, or with a Chinese, Japanese, or Korean character locale gets `+`, `-`, `|`, and a `>` prompt; Windows Terminal's `WT_SESSION` counts as UTF-8. Narrower than 12 columns, the box keeps only its top and bottom edges as plain rules.
- **Window:** the composer shows up to five rows, or a fifth of the terminal's height up to 12 rows on a terminal of 30 rows or more. The window keeps its position and moves only when the caret would leave it; after a width change the caret keeps its row in the window where the new layout allows. Dim `^` and `v` mark hidden rows, and the box's edges count them, `+N above` and `+N below`. - **Modes:** the composer reads differently while idle, while the sample turn runs, while the sample compaction runs, and while an agent is inspected. Only the empty draft's placeholder, the bottom edge's hint, and the prompt's tone change, so a mode change never rewraps the draft or moves the caret. The empty draft reads `Type a draft · Alt+Enter newline · Ctrl+Z undo` while idle, `Enter steers the next step · Alt+↑ sends now` during a turn, `Compacting… Enter queues · Esc cancels` during compaction, and `Read-only · Esc returns to parent` when inspection finds it empty. The bottom edge reads `Enter sends` over a draft while idle, `Esc interrupts` during a turn, nothing during compaction, and `draft kept · Esc returns` during inspection, where the prompt and draft are dim. Narrower than 60 columns, the placeholder keeps only its first part and only the inspection label remains. A hidden-row count takes the bottom edge before any hint. Enter in every mode shows the no-model notice, and Alt+↑ does nothing.
- **Activity line:** Ctrl+T starts a sample turn. It appends a running `codemode` call, a `{} Codemode` block, to the transcript, whose nested calls arrive on a fixed timeline as the tool would dispatch them: a `find`, then a `read` of every manifest under `Promise.all`, at most sixteen running at once as the tool allows, one of them failing, then a `bash` build, which runs until the turn ends. While the script runs, its head counts the calls and how many are running, `21 calls · 15 running`, and each call's row turns from `●` to `✓` or `✗` as it settles. The script settles with the turn: when Ctrl+T moves on to the compaction it runs to its end, every call settled, with what it handed back below and `took` in the head; when Esc stops it, the head carries an ` interrupted ` tag and its running calls are cancelled, `⊘`. The bar shows the turn as text alone: a word picked from 32 baking verbs, then its phase and elapsed time, `Kneading…  thinking · 3s`. The phase steps through sample phases every four seconds. A band of light sweeps across the word every 70 ms, blending from orange to a pale glint when `COLORTERM` is `truecolor` or `24bit`, and stepping through yellow, light yellow, and bright white otherwise. A second Ctrl+T replaces it with a sample compaction, `Compacting history…  preparing · 0s`, with its own clock and phases, in blue blending toward light blue, or blue, light blue, and bright white. Under `NO_COLOR` the word is bold and still, and only the seconds change. Nothing runs during either sample.
- **Fixture runtime:** Enter sends the draft through the runtime port to a scripted stand-in for the agent runtime, on its own thread. It answers every prompt with the same turn on a fixed timeline: it commits the prompt as a user row, starts the turn, streams a line of reasoning a word every 40 ms, runs one call, `Bash: true`, for 800 ms, then streams its answer, which says that no model or tool ran. The bar shows the phase the fixture reports, `thinking`, `running bash`, then `writing`, and the turn's outcome once it ends. Rows still being written are live: each update replaces them, and a commit settles them, so a streamed row is drawn once. A steer sent while the turn runs waits for the current step to end and then runs as a further step of the same turn; until then the runtime lists it above the bar under `Pending input`, as `Next step: later`, with `Alt+↑ sends it now` below. A prompt of several lines reads there as one, cut to the row with `…`, where the oracle wraps it. Alt+↑ interrupts the turn, keeping what waits, and starts a turn with every waiting prompt in the order they were sent. Esc commits what was live as it stood, a running call failed with an ` interrupted ` tag, and ends the turn; a waiting steer then starts the next one. Frames that only runtime updates prompted are drawn at most every 16 ms; a batch with input is drawn at once. The port's thread is joined before the terminal is restored, so no update outlives the preview. The fixture is development tooling and proves no runtime parity.
- **Layout:** the default fullscreen mode uses the alternate screen at any size. From the bottom up: the agents row, the composer box, the bar on the box's top edge, the notice, and the transcript body. Rows go to the first composer row, the bar, the box's top edge, its bottom edge, the agents row, the gap, further draft rows while the body keeps three rows, and the notice, in that order, so a short terminal gives up the notice, the gap, the agents row, the bottom edge, the top edge, and the bar first; the box closes only when both edges fit. Events already waiting are applied together and drawn once, so a burst of keys or resizes repaints once. Every fullscreen resize clears the screen and repaints the whole frame inside one synchronized update, even when a burst of resizes ends at the previous size.
- **Inline output:** `preview --inline` uses the normal screen. Settled rows are written once using the same transcript presentation as fullscreen. Live output and the same composer, bar, panels, and inspector occupy a held region below them, initially reserving up to eight transcript rows while following. The region grows for larger drafts and panels and keeps that allocation until a terminal shrink requires less. PgUp and the existing history keys display history inside that region; returning to live output clears those temporary rows. The Ctrl+T sample stays live until it settles. Resizes repaint the held region without clearing the screen or replaying committed rows; the terminal owns reflow of its scrollback.
- **Transcript:** the body above the controls is a viewport over a fixed sample session; nothing in it ran. It opens with the preview's title and introduction, then three turns: a search, a `codemode` call, and a failing test run that an edit fixes. The title carries the palette beside it as a strip of swatches, hues then greys, when it fits whole, colour is on, and the frame is not classic. Every turn after the first row opens with a blank row, then a faint dashed rule of ASCII hyphens across the transcript's width, directly above the user's words, which follow a cyan prompt mark, `> Run the parser tests`, the rows a long prompt wraps to hanging under the text; reasoning is dim and italic and answers are plain, both at column 2. Each call is one row, `✓ Bash: bun test tests/parser.test.ts`, with its state mark (green `✓` done, red `✗` failed, and while it runs a white `●` that blinks: shown for 600 ms, then a blank of the same width for 600 ms, so the row never moves), the tool name bold in the foreground with a colon after it, `Bash:`, so the arguments of the common tools align, and its status two cells after the argument: its own, such as `412 lines`, or else its output's line count. An exit code or an interruption is a tag, a short code with a cell of padding on each side on a dark tint of its tone: ` exit 0 ` green, ` exit 1 ` red, ` interrupted ` yellow. Sixteen colours draw a tag's text in its tone without the tint, and `NO_COLOR` plain; the padding keeps its width either way. A status that does not fit there takes its own row under the argument and wraps rather than being cut. A read's or edit's path reads by its file name, the directory dim. ## Terminal ownership

`TerminalSession` in `bake-tui` selects fullscreen or inline through `ScreenMode` and is the only code that changes terminal modes: raw mode, the alternate screen, bracketed paste, autowrap, cursor visibility, and synchronized output. Autowrap is off while the preview runs, so a row the terminal draws wider than measured is clipped instead of scrolling the screen. Each frame is written between synchronized-update markers (DEC mode 2026), and an update left open by a failure is ended on restore. It records each mode before requesting it and restores exactly those modes, in reverse order, attempting every step even when one fails:

- On quit or a handled signal, the preview closes the session explicitly. A restoration failure is reported (`bake: preview failed: ...`, exit status 1) rather than discarded.
- On a hangup, the terminal is gone: SIGHUP arrived, standard input or output reported a hangup, or a write failed with EIO or a broken pipe. The preview still attempts restoration, drops its failures as the TypeScript launcher's `tolerateLostTerminal` does, prints nothing, and exits with status 129.
- On a loop error, the session is still closed; the loop error is reported, and a restoration error behind it is not.
- On a setup failure, only the modes already requested are restored.
- On a panic, a panic hook restores the terminal before the panic message prints. Dropping the session also restores it; restoration runs at most once, so these fallbacks never repeat it.

On Unix, SIGINT, SIGTERM, and SIGHUP are handled while the preview runs. Raw mode turns the Ctrl+C key into input, so SIGINT comes only from another process. A signal thread forwards each one to the loop as it arrives; the loop restores the terminal and exits with status 128 plus the signal number: 130, 143, and 129, the last as a hangup. A terminal that closes sends SIGHUP only to the process it controls, so a watcher thread also polls standard input and output for a hangup every 50 ms. After the terminal is restored the handlers are unregistered, but signal-hook does not reinstate the previous disposition, so those signals are ignored in the moment before the process exits. A second signal during restoration does not interrupt it, and SIGKILL or SIGSTOP cannot be handled at all.

An input thread reads terminal input as it arrives, decodes it into the view's messages, and sends them to the loop. Crossterm's `use-dev-tty` reader polls the terminal and the resize signal level-triggered, so keys that arrive with a resize are read at once rather than left waiting for the next keystroke. The thread checks every 50 ms whether to stop, and the preview joins it before leaving raw mode, so it reads nothing meant for the shell. After a hangup Crossterm's reader may keep polling the closed terminal without returning, so the preview waits for the thread only 100 ms and then leaves it to end with the process. If the thread fails or ends unexpectedly, the loop reports `terminal input stopped` and restores the terminal. Between messages the loop sleeps until the next one, or until the sample activity's next shimmer beat or second.

Job-journal tests kill child writers after start durability, terminal durability, and notice durability; reopen confirms no duplicate effect or notice. Fault injection refuses start, terminal, and observation writes.
