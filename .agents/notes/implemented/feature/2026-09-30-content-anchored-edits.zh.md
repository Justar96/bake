# Agent Note：内容锚定编辑

Status: implemented

[English](2026-09-30-content-anchored-edits.md) | 中文

## 问题

编辑前读取防护会拒绝对会话未读取过、或自文件上次变化后未重新读取过的文件执行 `edit`。在 75 个已记录的 Bake 会话（9,444 次工具调用）中，213 个工具错误里有 103 个是这类拒绝：70 个未读取，33 个陈旧。每次拒绝都消耗一次模型请求，通常还要为重新读取再消耗一次，而两次都会重新发送整个上下文。模型也会绕开这道防护：它们通过 `bash` 运行 Python 脚本完成了 384 次文件编辑，而通过 `edit` 完成的是 1,700 次。这些脚本每个的替换次数中位数为 2，其中 298 个断言了恰好一次匹配，而这正是 `edit` 本来就强制执行的规则。脚本放弃了原子性、diff 卡片和观察跟踪；33 次陈旧拒绝中有 16 次发生在同一会话的此类 shell 编辑之后。

## 决策

`dsh-fs-observation-policy` 默认返回 `anchored` 编辑意图（`editGuard: anchored`）；会话有观察记录时，该意图携带观察到的版本。提供方在每目标锁内用共享的 `checkEditGuard` 规则应用它：

- 不带 `replaceAll` 的替换作用于当前内容，无论文件是否被观察过，因为其精确且唯一的匹配本身就是前置条件。
- `replaceAll` 替换没有唯一性锚点，仍需要观察到的版本（`FS_NOT_OBSERVED`），且该版本必须是当前的（`FS_STALE_VERSION`）。
- 结果报告 `basis: observed | changed | unobserved`。基础不是 `observed` 时，`edit` 会在结果末尾附上带行号的编辑后行（最多 40 行），使模型无需重新读取即可获得当前视图。

`write` 保留其版本防护；`editGuard: version` 可恢复原先的编辑拒绝行为。`edit` 还接受 `edits: [{ old_string, new_string, replace_all? }]`：每一项都与原始内容匹配，匹配范围不得重叠，并在一次原子写入中全部发布。`ctx.fs.editText` 接受单个 `FsEditRequest` 或其数组。`str_replace_editor` 对锚定的 `str_replace` 与 `edit` 同样处理：它与刚读取的内容匹配，并由基于该次 stat 的比较并交换保护这一窗口；按行定位的 `insert` 仍需要观察记录。

## 为什么唯一匹配是充分的前置条件

提供方在同一个每目标锁内读取、匹配并写入。文件其他位置的并发变化属于替换所作用的内容，因此会被保留；与匹配范围重叠的并发变化会使文本不再匹配，编辑以 `FS_EDIT_NOT_FOUND` 失败，而不会悄悄覆盖该变化。模型除非碰巧，无法复现一个从未见过的文件中唯一的多字符片段，因此未读取的编辑实际上基于模型通过其他方式获得的内容，例如 `grep` 或 `sed -n`。整文件覆盖和全部替换没有这样的锚点，因此保留防护。

## 曾考虑的替代方案

**保留严格防护并改进拒绝文本。** 这是之前的选择：重复的相同拒绝会被抑制，不再分派。一项覆盖 90 次真实运行的配对评估显示没有节省 token，因为拒绝和恢复读取仍会进入模型历史；描述中更长的指引还让某个模型的每次请求多出约 600 个输入 token。

**允许陈旧编辑但拒绝未读取编辑。** 这只能消除 33 次陈旧拒绝；70 次未读取拒绝以及转向 shell 脚本的倾向依然存在。

**在内部重新读取后自动重试编辑。** 这等价于锚定，但会隐藏文件已变化的事实。锚定基础会报告这一变化，工具也会显示编辑后的行。

**单独的多处编辑工具。** 它的 schema 会随每次请求重新发送，模型还要在两个编辑工具之间选择。`edit` 上可选的 `edits` 数组成本更低，并保留了模型已熟悉的单次编辑形式。

## 后果

除 `replace_all` 外，未读取和陈旧的编辑拒绝都不再出现，同一文件的多处修改可以放进一次调用。回显编辑后的行只在模型未见过其所修改内容时增加 token。编辑现在可能落在模型从未打开过的文件中，因此其结果就是模型对该区域的第一次查看。需要旧约定的部署可设置 `editGuard: version`，同一构建也可以比较两种防护。[事件门禁 Agent Note](../architecture/2026-06-26-file-context-as-event-gate.zh.md) 仍拥有事件词汇和由提供方强制执行的防护；本 Note 只改变默认的编辑决策。

## 验证

`packages/fs/tool-fs/tests/integration.spec.ts` 在真实本地后端上覆盖锚定默认行为：检查未读取和已变化的文件、被其他写入者移除的匹配、严格的 `replace_all` 与 `write`、原子多处编辑、重叠和缺失条目的诊断，以及对不同片段的并发编辑。严格约定仍在 `editGuard: version` 下得到覆盖。`packages/fs/fs-observation-policy/tests/policy.spec.ts` 覆盖两种防护决策。
